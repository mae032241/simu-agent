# 当前科学 Agent 比较评估

日期：2026-08-31

文档角色：当前实现快照评估，不是规范架构、实施计划或科学资格声明

比较基线：`baseline/8765-codex@404aeb14c6ebc4b08bac599db91eaee54c103f48`

当前对象：上述提交叠加当前未提交工作树；工作树变化后本文必须重新核验

发布边界：仅作本地当前评估，不进入 H6-B 最小源发布文档清单

## 1. 范围与结论

本文回答三个问题：

1. 当前科学 Agent 相比 8765 基线究竟改进了什么；
2. 当前设计与 AI Scientist-v2、直接使用 Codex 相比分别适合什么；
3. 使用较弱模型或需要人工补齐科学内容时，三种方案会怎样失败。

规范架构仍由[当前架构](../ARCHITECTURE.zh-CN.md)和
[最小设计宪章](SCIENTIFIC_AGENT_DESIGN_CHARTER.zh-CN.md)拥有；8765 的冻结事实由
[R0 基线记录](../plans/R0_8765_BASELINE_CHARACTERIZATION.zh-CN.md)拥有。本文只比较这些事实，不建立
第二套架构权威。

总体结论是：

> 当前实现已经从“由分散角色表、领域分支和多套注册入口拼成的科研流程控制器”，转向“以
> `OperationSpec` 为行为原子、以单一编译目录为能力权威、由轻控制面约束多角色科学 Agent”的
> 方向。它在可追溯、外部副作用、精确审批、领域工具和失败关闭方面强于 AI Scientist-v2 与直接
> 使用 Codex，但在开放式探索、模型配置、人工内容接管和已证明的科学产出方面仍明显不足。

这次重构首先改善的是架构边界和可信度，不是已经证明科研效果优于其他方案。当前真实科学回归在
证据阶段之后被假设审查阻断，说明失败关闭有效，但不能证明新架构已经提升结论准确率或科研吞吐。

## 2. 8765 基线中原本正确的部分

8765 不是一个应被全部推翻的失败版本。以下能力构成了当前重构应继续保留的基座：

- 证据提取者、证据审查者、构想者、批判者、实验设计者、诊断者、TCAD 作者和 TCAD 审查者之间
  的多角色职责划分；
- Agent 任务、确定性变换、人工审批和外部执行各自具有基本生命周期；
- 作者与审查者使用不同任务目录，父会话历史不直接继承给 Worker；
- 审批网页、历史记录、不可变 Artifact 和内容摘要已经能够承担基本审计；
- TCAD 作者能够在私有任务目录编写与调试工程，TCAD 审查者不获得作者调试权限；
- 外部执行在授权前不会提交，重复授权和提交具有基本幂等性。

这些已由 R0 从清洁 wheel 安装入口复现。当前重构的目标不是重新发明这些生命周期，而是消除它们
周围分散的角色表、上下文策略、领域分支和注册入口。

## 3. 当前实现相对 8765 的关键改进

### 3.1 从“角色和流程配置”转为单一行为原子

8765 的一个科学角色需要同时散落在角色资源、调度拓扑、上下文策略、运行时资源表、输出 Schema、
工具分配和插件适配器中。当前把一次可执行行为收敛为不可变的 `OperationSpec`，统一声明：

- 行为目的和适用条件；
- 输入、输出和语义用途；
- Agent、Transform、Approval 或 Effect 执行种类；
- 专业提示、工作区、领域工具和原生工具；
- 网络、时限、文件数和字节上限；
- 独立审查边和人工审批要求；
- 外部副作用适配器。

`OperationSpec` 只引用窄组件，不实现所有功能，因此不是巨型行为类。Schema、validator、projector、
workspace hook、Worker tool 和 Effect adapter 仍由各插件的小组件实现。

### 3.2 从多注册表转为一个插件入口和一次启动编译

8765 的完整安装同时存在角色包、变换适配器和 Operation 声明三类入口，其中旧 Operation 入口在
清洁安装中甚至无法加载。当前只有 `scidiscovery.plugins` 一个入口，每个插件返回一个
`PluginDefinition`，启动时一次编译出唯一 `CompiledCatalog`。

`public`、`support`、`internal` 和诊断用 `all` 只是同一目录的投影视图，不是新的注册表。插件安装
后不应要求核心、调度器、UI 或部署脚本增加插件名分支。

### 3.3 科学判断重新归还 Agent

当前控制面不再用固定阶段、领域流程或确定性评分公式决定“下一项科研行为”。交互式调度 Agent 根据
当前矛盾和不可变记录选择一个最短、可辩护的公开 Operation；控制面只验证精确输入、资格、预算、
审查和副作用条件。

这避免了把“科学优先级判断”伪装成控制规则，也避免为每个新领域重写固定 DAG。代价是调度模型
仍然必须作出真实科学判断，较弱模型可能在目录中选择错误操作。

### 3.4 输入、工具和输出由同一个编译合同约束

8765 默认上下文允许额外输入，最多可见 32 个输入和 64 MiB 内容；同类角色通常获得固定工具集合，
同一进程还可能读取兄弟任务目录。当前 Agent Operation 把输入端口、文件暴露方式、输出合同、
Worker MCP 工具、静态资源和上限编译到同一 Run 授权中。

Agent 之间不直接传递聊天、隐藏上下文或内部标识，只能消费显式绑定的输入文件并产生封存输出文件。
子 Agent 的完成消息只是传输信号，只有控制面报告任务完成后的封存输出才是科学结果。

需要诚实保留的限制是：当前 `spawn_agent` 原型尚未做到 Codex 原生工具的平台级不可见；服务端能够
拒绝未声明的领域工具，但对可见原生工具仍有提示约束成分，因此不能把它宣称为完整强沙箱。

### 3.5 通用核心与领域插件开始真正分离

8765 核心源码有 6 处直接导入 TCAD/曲线领域包，关键通用模块中还有 114 行角色、Schema、profile
或 TCAD 分支命中。当前同口径扫描的通用核心领域标记为零：

- 通用核心拥有 Operation ABI、Artifact、Run、可选 Approval/Execution 和通用 MCP；
- 通用科研插件拥有证据、假设、批判、实验设计和诊断类 Operation；
- TCAD 插件拥有器件参数、Deck、调试工具、求解器和执行适配器；
- 曲线插件拥有图证据、曲线 Schema、数字化、评分和诊断；
- InGaAs Fig.4 插件只拥有项目冻结能力。

这比“核心暴露插件接口，但仍按插件名理解领域对象”更接近真正的插件化。

### 3.6 修订、审查和副作用的权威边界更清楚

当前修订是生产者 Operation 产生的完整新对象：旧 Artifact 不变，新对象不继承旧审查、资格或人工
决定。原来的跨对象补丁、补丁应用和递归恢复链已经删除。

Approval Operation 只把精确对象投影成固定安全文档；人工决定绑定精确 subjects、Operation 身份
和合同摘要。Effect Operation 必须先形成精确副作用请求和独立授权，再由插件 adapter 执行；
adapter 不能批准自己或解释科学结论。

### 3.7 控制职责减少，但系统还不能称为轻量

同口径指标显示，8765 六个核心职责文件合计 13,657 行，当前职责后继聚合为 9,518 行，减少
4,139 行，约 30.3%。旧 `scheduler_topology.py` 和 `platforms/roles.py` 已退出生产路径；新的
`operations/` 包为 7 个文件、2,064 行。

S1 候选将测试证明、表格示例和未启用 Worker 进程移出生产面后，当前生产 Python 为144个文件、
57,207行；默认产品目录仍有45个 Operation，其中26个公开、19个辅助。这个净减证明发布边界开始
收敛，但控制主干尚未简化，不能据此宣称框架已经轻量化完成。当前正确表述仍是“关键控制职责
明显收敛，生产证明面已减重”。

## 4. 当前仍未解决的问题

### 4.1 模型仍被写死为 `gpt-5.4`

`scientific_agent_operation()` 和 TCAD 的生产 Agent 声明直接写入 `model="gpt-5.4"`。编译器把
它纳入权限模板和目录摘要，生成 Codex Agent 配置时原样写入；Worker 启动时也使用同一模型。
手工修改生成配置会被目录一致性检查拒绝。

冻结后的模型不可被 Agent 偷换是正确约束，但具体模型不应硬编码在插件源码。合理边界是：

```text
Operation 声明模型需求或逻辑配置名
                ↓
部署配置绑定具体模型与推理强度
                ↓
启动时解析并写入编译目录摘要
                ↓
运行期间不可静默修改
```

在修复前，当前框架不能正式支持“强模型规划和审查、弱模型执行”或异构模型独立审查。

### 4.2 人工决策很强，人工内容接管很弱

人工可以通过 UI 批准、拒绝和授权执行，也可以摄入原始来源；但当前没有一等入口让专家下载某个
科学输出模板、修改完整内容、上传为同 Schema 的类型化修订，再进入相同 validator、来源和独立
审查链。普通人工上传当前主要被登记为 `source_file/opaque`，不能直接替代假设、实验设计或
TCAD 工程生产者。

这会使系统出现“能够可靠地拒绝错误，但专家不容易正式接手并继续”的问题。

### 4.3 单行动调度缺少有界探索宽度

当前调度器每次只选择一个公开 Operation。它避免了在核心引入树搜索、隐含排序和固定流程，但也
意味着错误假设更容易让整条研究停住。当前不应直接引入 AI Scientist-v2 的大规模树搜索；更小的
方案是由插件声明一次生成 2 至 4 个候选的组合 Operation，每个候选仍保留独立来源与审查。

### 4.4 工程门通过不等于科学效果通过

R5-G 的证据阶段完成；初始假设和有界修订假设均被独立批判者判定为 `blocked`，因此没有进入实验
设计和新的真实外部执行。这个结果证明了系统没有为了闭环而伪造通过，但没有证明新架构相对 8765、
单 Agent 或其他框架提升了科研质量。

### 4.5 当前收口状态仍有未完成项

- H6-A 的一次性评估归档和 H6-B 的发布投影收窄已通过独立审查；
- H6-C 候选完成全部千行文件消费者审计，共删除六个零消费者表面且没有机械拆分巨型文件；
  首轮总审查打回项返工后，第二轮独立复审已通过；
- 当前新增 R5-S 生产减重提案，拟先压缩 Worker 协议、准入规则、实例管理和重复数据合同；该方案
  S1 三项生产降级已经独立实现审查通过；当前只放行 S2，后续阶段仍未放行；
- 最终端到端 H7 在 R5-S 完成前暂停；
- 审批 UI 满足安全合同，但现场反馈仍认为信息密度和排版较差；
- 新架构尚未完成三个差异领域“不改核心、不改通用调度器”的实证。

## 5. 与 AI Scientist-v2 的比较

AI Scientist-v2 的目标是从高层主题和研究想法出发，在机器学习领域自动生成假设、实验代码、结果、
图表和论文。它使用实验进度管理器协调预研究、超参数调优、研究议程和消融实验四个阶段，并在每个
阶段内进行并行树搜索、执行和调试。官方实现说明见
[AI Scientist-v2 代码库](https://github.com/SakanaAI/AI-Scientist-v2)，方法和评价见
[AI Scientist-v2 论文](https://arxiv.org/html/2504.08066)。

| 维度 | 当前 SciDiscovery | AI Scientist-v2 |
| --- | --- | --- |
| 基本原子 | 已编译、类型化、可审计的 Operation | 研究阶段中的代码/实验树节点 |
| 调度方式 | 从当前矛盾选择一个有界公开行为 | 阶段管理器加并行树搜索，选优节点进入下一阶段 |
| 科学探索 | 当前偏串行和失败关闭 | 多节点、多随机种子、多次调试，探索宽度较强 |
| 领域范围 | 目标是插件化通用基座；已有 TCAD、曲线和项目插件 | 官方实证主要是机器学习、Python、CUDA 和 Hugging Face 数据 |
| 新方法生成 | 只能在已注册工具和 Agent 文件工作区内实现 | Agent 可以现场生成并执行新的 Python 实验代码 |
| 来源和谱系 | 不可变 Artifact、精确父链、实例语义绑定 | 以实验目录、代码节点、检查点和最终文稿为主 |
| 独立审查 | 编译审查边、不同 Operation 和精确输入 | LLM/VLM 评价节点、图表和文稿 |
| 外部副作用 | 审批后通过 Effect adapter 幂等执行和恢复 | 直接运行 LLM 生成代码，官方要求置于受控沙箱 |
| 人工介入 | 精确决策和执行授权强；科学内容接管弱 | 正式实验主要允许高层选题和完整运行挑选；文件层手改容易但会破坏自主运行边界 |
| 模型分工 | 结构支持逐 Operation 模型字段，但当前实际统一硬编码 5.4 | 代码生成、反馈、摘要、写作和审查可使用不同模型 |
| 已有科研实证 | 当前新回归停在假设阶段 | 三篇自主论文提交研讨会，一篇达到接收线；尚不能稳定达到研讨会水平 |
| 主要成本 | 控制协议和插件合同较重，执行较审慎 | 树搜索调用和实验算力较重，官方单论文最长运行上限为 15 小时 |

AI Scientist-v2 的“通用”需要按其证据范围理解：它去掉了每个机器学习题目必须准备人工代码模板的
限制，能够跨多个机器学习主题工作，但尚未证明可以低成本接入 TCAD、湿实验或任意外部科学设备。

它的科研效果也不应只引用“首篇 AI 论文通过同行评审”：官方实验从约 40 个 AI 想法中由人选择
3 个，再对每个想法运行多个随机种子并挑选最佳完整稿件；三篇中一篇达到研讨会接收线。作者明确
指出当前系统不能稳定达到研讨会标准，并报告了论证不足、图注错误、数据重叠和声称的实验未实际
执行等风险。

### 5.1 当前设计优于 AI Scientist-v2 的地方

- 更适合 TCAD、求解器、昂贵仿真和其他具有真实副作用的科研；
- 输入、输出、审查、授权和执行结果具有更强的不可变谱系；
- 科学不合格结果更可能被阻断，而不是继续进入论文叙述；
- 人工审批绑定精确对象，聊天不能被误当成授权；
- 新领域工具可以作为插件组件进入同一 Operation 编译闭包。

### 5.2 AI Scientist-v2 优于当前设计的地方

- 能用树搜索、并行节点和调试深度探索多个实验方向；
- 可以现场创造新实验代码，不要求所有分析方法预先注册；
- 模型和阶段配置比当前硬编码 5.4 更灵活；
- 已有完整论文生成和真实同行评审实证；
- 对普通机器学习题目接入成本更低，控制协议更少。

## 6. 与直接使用 Codex 的比较

“直接使用 Codex”指：研究者在项目目录中通过对话、`AGENTS.md`、skills、MCP、原生文件/终端/网络
工具和 Codex 子 Agent 完成研究，不增加 SciDiscovery 的 Operation、Artifact、Approval 和
Execution 控制层。

Codex 当前原生支持子 Agent、项目级自定义 Agent、逐 Agent 模型和推理强度、MCP、skills、沙箱和
审批模式。子 Agent 可以隔离嘈杂上下文并并行工作；其沙箱通常继承父会话，也可以为自定义 Agent
配置只读等覆盖。具体能力见
[OpenAI Codex 子 Agent 官方文档](https://developers.openai.com/codex/multi-agent)。因此，不能把
SciDiscovery 当前的 `gpt-5.4` 硬编码或原生工具隔离缺口归因于 Codex 本身。

| 维度 | 当前 SciDiscovery | 直接使用 Codex |
| --- | --- | --- |
| 启动成本 | 需要插件、Operation 编译、实例和受控生命周期 | 打开项目并给出目标即可开始 |
| 行为约束 | 输入、输出、工具、审查和效果在启动时冻结 | 主要由会话指令、Agent 配置、skills、MCP 和沙箱约束 |
| 动态适应 | 只能选择已注册 Operation，但 Worker 可在其工作区内开放判断 | 可以即时拆任务、写新代码、改变计划和调用新工具 |
| 多 Agent | 角色由 Operation 编译，文件封存交接 | 原生子 Agent 可并行、跟进和返回摘要 |
| 模型配置 | 当前实现实际硬编码 5.4 | 可按父 Agent、默认子 Agent 或自定义 Agent 配置模型与推理强度 |
| 科学记录 | Artifact、父链、current、qualification 和审查状态一等化 | 文件和 Git 很灵活，但不会自动成为类型化科学谱系 |
| 人工协作 | 正式审批强，内容修改入口弱 | 对话纠偏和直接编辑最方便，但人工改动含义需要自行记录 |
| 外部执行 | 精确请求、审批、adapter、幂等和恢复 | 依赖 Codex 沙箱、审批和用户监督；没有领域执行状态机 |
| 失败方式 | 更可能停在 preflight、validator 或独立审查 | 更可能继续尝试并产出文件，但错误可能直到人工检查才暴露 |
| 最适场景 | 可复现、受监管、昂贵或有真实副作用的重复科研 | 快速原型、一次性分析、专家持续在环和开放式代码探索 |

直接使用 Codex 并不天然缺少多 Agent、模型分工或工具能力。SciDiscovery 的必要价值不能是“它能够
启动子 Agent”，而必须是 Codex 本身不会自动提供的领域科研合同：不可变科学来源、精确资格、独立
审查、类型化插件能力、外部效果幂等恢复和可追踪人工决定。

如果一个任务只是专家和 Codex 共同编写一次性分析脚本，SciDiscovery 很可能是不必要的负担；如果
相同 TCAD 研究需要反复运行、交给不同人员审查、批准昂贵求解器执行并追踪结论来源，控制层才有
明确净价值。

## 7. 较弱模型下的差异

### 7.1 当前 SciDiscovery：精度优先、容易诚实停住

有利因素：

- 专业角色和最小上下文减少无关干扰；
- JSON Schema、validator、精确端口和工具收据可接管机械正确性；
- 作者、批判者和审查者分离，错误结果不会自动成为下游事实；
- 外部副作用不依赖模型自行记住审批规则。

不利因素：

- 调度 Agent 仍需从完整安装的 26 个公开 Operation 中作科学选择；
- 当前所有生产 Agent 统一绑定同一个 5.4 模型，审查错误可能高度相关；
- 单行动策略缺少搜索冗余，弱模型产生差假设后容易连续阻断；
- 过强或不可发现的 validator 语义会让弱模型陷入重复修复；
- 结果可能是安全但低吞吐，即大量 `blocked` 而非错误接受。

### 7.2 AI Scientist-v2：搜索补偿偶发失败，但会扩散系统性错误

树搜索、并行节点、随机种子和最大调试深度可以弥补一部分编码错误或局部坏选择。但较弱模型同时
负责提出方案、生成代码和评价节点时，同一种数据泄漏、指标误解或科学误判可能复制到整棵树。
官方 FAQ 也明确说明成功率取决于基础模型和想法复杂度，强模型在实验阶段成功率更高。

因此它更可能“产出某个结果”，却不一定更可能“产出可信结果”，并且搜索会放大 token、运行时间
和实验算力成本。

### 7.3 直接 Codex：人工在场时灵活，脱离人工时缺少科学护栏

直接 Codex 可以把强模型配置给父 Agent 或审查者，把较弱模型用于检索、格式化和批量任务；人也能
随时观察子线程、补充背景、改代码和改变方向。这对弱模型非常重要，而且当前 SciDiscovery 因模型
硬编码还做不到同等灵活。

但直接使用时，Schema、来源、资格、独立审查和外部效果合同需要研究者自行建立。如果人工没有持续
检查，弱模型可能生成一个形式完整但科学上错误的目录，系统本身不会像 SciDiscovery 那样在正式
下游准入处失败关闭。

### 7.4 弱模型下的选择结论

| 条件 | 更合适的方案 | 原因 |
| --- | --- | --- |
| 弱模型、无人监督、昂贵外部执行 | 当前 SciDiscovery 的方向 | 更可能阻断错误和未授权副作用，但科研任务可能无法完成 |
| 弱模型、专家持续在环、一次性分析 | 直接 Codex | 专家可快速纠偏和直接修改，协议成本最低 |
| 弱模型、低成本机器学习、允许大量试错 | AI Scientist-v2 | 搜索和调试能提高找到可运行节点的概率，但需额外科学核验 |
| 强模型、开放式机器学习探索 | AI Scientist-v2 或直接 Codex | 探索宽度和现场代码创造更强 |
| 强模型、TCAD/设备/可审计重复研究 | 修复后的 SciDiscovery | 插件工具、来源、审批和执行恢复更重要 |

## 8. 人工介入时的差异

人工介入至少分为四类，不能统一称为“人在环”：

| 人工行为 | 当前 SciDiscovery | AI Scientist-v2 | 直接 Codex |
| --- | --- | --- | --- |
| 选择研究目标或候选 | 可通过实例目标和调度决定表达 | 官方评价中由人从约40个想法选择3个 | 对话中随时决定，最方便 |
| 批准、拒绝或授权执行 | 一等化、精确绑定并可审计 | 不是主要运行抽象 | 使用通用审批/沙箱，非科学对象级合同 |
| 修正假设、实验设计或结果解释 | 缺少正式类型化人工生产者 | 官方选定运行内部不进行人工内容编辑；普通文件可手改但改变实验性质 | 可直接对话或编辑文件，最方便 |
| 保留修正来源与重新审查 | 当前结构具备基础，但缺少人工内容入口 | 需要另行记录 | 需要研究者自行用 Git、文件和记录实现 |

当前最需要补齐的不是新的人工审批状态，而是一个最小的“人工辅助科学内容 Operation”：

1. 人工下载当前输出的 Schema 模板和精确输入说明；
2. 上传一个完整替代对象，而不是跨对象补丁；
3. 新对象记录人工生产者、原对象和精确输入来源；
4. 复用相同 codec、validator、端口和大小限制；
5. 不继承旧审查、资格或批准，仍进入独立审查。

这能让专家接管内容而不绕过科学合同，也不会把 Approval 变成内容编辑器或增加第二任务生命周期。

## 9. 最小后续改进

按收益和复杂度排序，建议只做以下四项：

1. **启动期模型绑定。** Operation 声明逻辑模型需求，由部署配置绑定具体模型和推理强度；解析结果
   纳入目录摘要，运行期不可更改。支持强规划/审查模型、弱执行模型和异构独立审查。
2. **人工类型化内容接管。** 增加一个复用既有完整对象修订合同的人工执行入口，不增加审批状态机、
   补丁协议或万能修订管理器。
3. **机械适用性过滤。** 根据端口可绑定性、资格、预算和副作用准备度缩小调度 Agent 可见的公开
   Operation 集合，但不得加入科学排序或固定阶段。
4. **插件级小候选组合。** 对高不确定性环节允许一次产生 2 至 4 个候选；不在核心复制 AI
   Scientist-v2 的大规模树搜索和研究阶段状态机。

明确不建议：

- 新建科学图、OperationRun 或第二 current；
- 把 AI Scientist-v2 的四阶段和 57 节点预算写入核心；
- 让 Agent 在运行时自行选择或更改模型；
- 为人工修正重新引入跨对象 patch/apply/receipt 链；
- 给控制层增加科学优先级公式；
- 仅为减少单文件行数继续拆分内聚模块。

## 10. 建议的实证矩阵

后续评价不应只比较“是否跑到终点”，而应在同一任务上至少测试：

| 自变量 | 水平 |
| --- | --- |
| 模型能力 | 强模型、较弱模型 |
| 协作形态 | 单 Agent、当前多角色、直接 Codex |
| 人工介入 | 无人工、仅决策、允许类型化内容接管 |
| 探索宽度 | 单候选、2至4个有界候选 |

核心指标应包含错误接受率、阻断率、专家修复时间、最终结论质量、证据错误率、真实运行成本、重复运行
稳定性和插件接入劳动。AI Scientist-v2 只应在其能够公平运行的机器学习任务上作为直接对照，不能
把 TCAD 任务不能运行简单计为其失败。

在人工类型化接管和模型绑定完成前，当前最准确的产品定位是：

> 一个正在形成的高可信、可监督、可插拔科学 Agent 基座；它已经比 8765 更清楚地分离通用控制与
> 领域能力，但还不是比 AI Scientist-v2 更强的开放式自主科学家，也没有证明在所有任务上优于
> 直接使用 Codex。
