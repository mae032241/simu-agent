# 科学研究 Agent 最小设计宪章

更新日期：2026-09-02  
状态：R5-L Run v1 规范性基线

## 1. 使命

SciDiscovery 是一个证据约束、多角色协作、可审计且可恢复的科学研究 Agent 基座。它不以固定流程
替代科学判断，也不以控制状态数量衡量可信度。成功标准是：专业 Agent 能在最小上下文和最小权限
下提出、审查和修订科学内容；每项结果具有可追踪来源；人工风险决定与外部副作用精确绑定；新增
领域只需注册插件能力。

## 2. 基本原子

`OperationSpec` 是唯一行为原子。它声明输入、输出、执行种类、组件引用、上下文、工具、资源、
独立审查、人工审批和副作用要求。它不保存状态，也不是包含实现的巨型类。窄 codec、validator、
projector、workspace hook、Worker tool、Transform 和 adapter 由插件实现，启动时一次编译为唯一
`CompiledCatalog`。

Agent 输出的 JSON Schema、结构化语义规则和提交校验必须由同一编译 Operation 产生。Schema 负责
形状、必填、枚举和范围，并由提交路径直接执行；语义规则必须具有稳定编号并显式列出依赖输入；
每个 Python 内容或上下文校验器必须绑定一条已声明规则。控制面不得在提交时追加 Worker 执行前
不可见的科学规则，也不得把缺失的可选端口变成 Worker 输出拒绝；此类访问是插件契约故障。
只有显式的 `SemanticRuleViolation` 才表示已绑定规则发现了 Worker 可修订错误；其余内容或上下文
校验异常必须终止 Run，不得驱动 Worker 重试。

## 3. 权力分配

- 调度 Agent：依据当前矛盾和不可变记录选择一个最短可辩护的 public Operation；不制造科学输出。
- 科学 Worker：提出、批评、审查、修订和解释科学内容；只看到显式绑定的 Run 文件。
- 控制面：拥有 Artifact、Run、current，以及按 Operation 明确启用的 Approval、Promotion 和
  Execution 事实；普通探索不支付资格或副作用状态成本。
- 确定性程序：拥有可重放的格式转换、单位换算、集合展开和显式 Metric；不选择科学目标或结论。
- 领域 adapter：只执行声明的外部副作用和机械结果收集；不能批准自己或解释科学结论。
- 人工审批：只在 loopback UI 对精确可见对象决定；聊天文字不构成批准。

## 4. 注册与插件边界

系统只有 `scidiscovery.plugins` 一个注册入口。`public`、`support`、`internal` 和 `all` 是同一目录
的投影。通用科研插件拥有领域无关的角色 Operation；曲线插件拥有曲线 Schema 与算法；TCAD 插件
拥有参数、Deck、求解器和运行适配。依赖只能从专业领域指向可复用能力，通用能力不得反向依赖
TCAD。领域产物种类使用格式受限的插件标识，不进入核心闭集枚举；Worker 建议不是调度权威。新插件不能要求
核心、调度器、UI 或部署代码增加插件名分支。

## 5. 通信与最小授权

Agent 之间不直接交换聊天或隐藏上下文，只通过显式输入文件和封存输出文件通信。Worker 不接收
内部 Artifact、Run、Approval、session、token 或外部执行标识。默认可信本地路径采用软隔离：每个
Worker 获得一个包含显式输入、输出 Schema、可选恢复草稿和任务工作文件的 Run 目录，并可使用 Codex
原生文件与代码能力；普通任务内读写不要求逐项注册或生成读取收据。服务端仍按编译 Operation 精确
验证领域工具，并且只有通过提交校验的封存输出才能登记为 Artifact。该模式不是平台级沙箱，不得
携带生产凭证或直接执行不可逆副作用；真正的强隔离只在出现多租户、不可信插件或敏感数据等真实
消费者后作为可选后端另行验证，不能增加默认路径成本。

## 6. 不可退化事实

- Artifact、receipt 和旧 revision 不可原地修改；
- current 只有一个运行权威；启用 PromotionPolicy 时资格也只有一个权威；
- readiness 与 invoke 使用同一 preflight；
- revision 是完整新对象，不继承旧审查或资格；
- evidence qualification 与 execution authorization 分离；
- query 不推进状态，显式 command/reconcile 才能写入；
- submission unknown 只能权威查回，不能盲目重发；
- UI 展示可以重排，但不得改变精确审批对象和科学字节；
- 控制层不得用固定公式覆盖 Agent 的科研优先级判断。
- 假设审查只判断机制合理性、可证伪性和原则上的有限可区分性；定量判据、提取算法与误差传播由
  实验设计拥有。结构化处置是封存科学结论而非路由命令；调度 Agent 结合它与唯一编译目录选择
  Operation，控制面不维护第二套行动类型映射。
- 同一审查边的修订次数必须有界；问题维度没有进展时保留“不确定”并停止，不能用反复改写文本
  替代新证据或新计算。

## 7. 复杂度纪律

不得为历史兼容、新领域或单次验收增加第二注册表、第二 current、第二任务生命周期、固定科研 DAG、
新数据库状态机或按插件名分支。删除旧责任后才允许拆分巨型文件；拆分不能增加权威数量。一次性
科研评估脚本不进入产品工作流。任何新增实体必须证明它保护了既有实体无法保护的承重不变量。

## 8. 符合性

33 项稳定行为约束记录在 `SCIENTIFIC_AGENT_CONSTRAINTS.yaml`。约束是验收矩阵，不是33个运行实体。
每个阶段必须通过真实安装入口、正例、目标入口负例和独立审查；测试数量或旧审计结论不能自动证明
当前工作树符合。
