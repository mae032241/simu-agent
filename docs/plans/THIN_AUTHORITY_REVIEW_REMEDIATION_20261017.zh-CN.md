# 薄控制层：授权边界、正式审查与工程检查修复计划

状态：计划已通过[独立设计审查](evidence/THIN_AUTHORITY_REVIEW_REMEDIATION_REVIEW_20261017.zh-CN.md)，未实施；A1具体部署设计仍需单独独审。本文件不表示任何节点已实施。基线 `dev@10b4f2f`。用户要求制定修复计划，本轮只改文档，不运行测试/模型或修改系统权限。

## 1. 范围与事实

本计划接管[能力迁移计划](THIN_CAPABILITY_MIGRATION_20261016.zh-CN.md)中 P3 授权/正式审查和 R0 时间窗的四项新增问题，其他迁移工作仍归原计划。164 项定向通过的[报告](evidence/P_MIGRATION_TARGETED_TEST_REPORT_20261017.zh-CN.md)保留其历史范围，不证明抵抗恶意 Worker 或科学判断独立性。

- `experiments._adapter → execution_authority.host_services/_gate → host_secret` 在 Worker 调用的本地执行进程中取签名密钥。当前信任本地主机进程；签名、0600、哈希和不向模型展示路径，不能替代读权限隔离。
- `formal_review.request_route` 对重复不可用请求返回空路由，`controller.run` 直接进入 wait，跳过配置的交付收口。余额未清零，但自动推进停止。
- 正式审查已有专用提示词和角色模型配置。身份不重叠只证明程序层作者分离，不证明观点独立；`validate_job` 强制传入请求方结论会产生锚定风险。
- R0 的工程回放限于原调用期限，当前最多10秒并留2秒反馈，原训练耗尽时间时可能不运行。未运行不是通过，但目前缺少提前规划检查机会的机制。

不改 H/W/A/E 科学职责，不恢复 Root，不建立第二份实例/预算数据库，不让模型填写签名、引用链、包装或权限材料。

## 3. A0/A1：真正的授权归属

### A0 最小设计冻结

1. 列出实际 launcher、进程用户/沙箱、密钥位置、控制目录写权、远端连接凭据和所有 prepare/submit/cancel/collect/recover入口，不只检查UI路径。
2. 明确支持两种能力边界：现有可信本地模式只防误操作/合同错误；隔离执行部署才可主张恶意Worker不能伪造人工批准。模式不是对同一代码贴一个标签，须有不同的实际访问能力。
3. 文档收窄当前保证；旧批准原件保留，不自动升级为隔离模式资格。如不能提供OS或远端端点级隔离，A1标未具备，不用mock PASS代替。

### A1 实现约束

- 首选复用CLI管理的宿主控制服务生命周期，不恢复MCP Agent调度。UI是批准入口，实际授权服务不能只存在于浏览器连接期间；UI重启不丢已接受工作。
- Worker侧仅代理受管请求。签名私钥、批准写入、原资源账本的敏感写入和执行凭据由实际隔离的宿主拥有。Worker本地最多读取公开验证材料/有界状态；`host_secret`不再由不可信调用进程执行。
- **不同进程/socket/同UID文件0600均不自动构成隔离。** 设计必须选定可验证的独立OS主体或受限挂载/沙箱边界，使Worker无法读宿主密钥、改控制原件、控制宿主进程；也不能访问有同等权限的远端凭据/未受保护的提交入口。
- 通用注册接口承接命令，TCAD只实现领域能力。RPC按实例、原call、确切输入/目标和当前授权绑定，不接受客户端自报“已审批/已审查/预算充足”。服务端在副作用前从唯一权威记录核验，错误/撤销/过期保持拒绝。
- 复用原控制账本、精确资格、资源reserve/settle、永久未提交凭据；不要在socket侧另建可漂移的预算或授权数据库。谁实际写入哪些原件由A0矩阵确定。
- 响应丢失保持unknown、只查询原call；不得因服务重启重新submit。撤销对尚未执行的新副作用生效，已接受job的查询/取消/收集按原维护规则处理，不因修复授权而失去维护能力。
- 旧软模式实例不静默迁移签名/身份/预算；需要部署变更时明确迁移边界和原执行维护路径。不自动使用sudo、改用户权限或启动真实远端作业。

必要负例：从真实Worker权限子进程读密钥/写批准/直接调用record_decision/绕过RPC提交均不可获得执行权；伪造/错实例/错call/过期/撤销请求拒绝；批准后的唯一原call可执行；响应丢失与重启不重放。攻击测试只针对临时测试资源，禁止真实机时和生产凭据。

## 4. A2：重复不可用请求不能吞掉推进

- 将不可用原因和精确failure_key作为控制事实，反馈给普通A；下一份任务由控制层投影当前可选动作。未改变对象/身份前不再次派正式审查。
- 科学对象选择与去向仍由A决定。控制层不把不合格对象改成合格，也不自动替A挑候选。资格依赖只阻止对应副作用，不全局封锁其他合法研究/分析。
- 已消耗预算/步数不重置；重复非法输出走现有有限补正机制。不能不断重开A来掩盖同一失败。
- 补正耗尽时：若配置交付策略，进入现有受限收口，只能交付已具资格的候选或明确的未完成报告；如果必须的资格仍缺失，不能“为了完成”提交。无可行路径则记录明确的等待/阻断及恢复条件，不用通用wait冒充完成。
- 新证据/新subject改变failure_key时可重新申请；仅改route_reason措辞不能重置机会。续接/重启保持原failure事实。

验收：缺对象、缺作者身份、不支持launcher三类；重复两次仍可转其他合法路径；具delivery_policy可收口；无合法交付时保留缺口；预算/补正不重置；已通过正式审查路径不退化。

## 5. A3：独立审查先看证据，后看请求方解释

- 保留控制层requester身份/原seal用于审计；**机械来源引用不等于默认将该结论正文喂给审查者。** 修改validate_job的必要条件，改核确切请求/对象/判据/原始目标，而非强制请求方conclusion为模型输入。
- 默认正式审查包包含原始问题/限制、确切被审对象、需要判断的主张和适用判据、必要直接证据与已知未知项。原件通过现有按需入口取得，不重新递归展开历史。当前request_route直接以请求方route_reason作为question、再绑定job.instruction；本轮必须一并拆开：默认使用中立的审查任务模板和确切对象/原判据，不原样注入请求方推荐性route_reason。原理由留在控制原件；被审科学主张仍以有来源的待检主张呈现，程序不语义改写为结论。
- 请求方的推荐、通过倾向和完整论证不默认投递；如审查者需复核其主张，可明确读取并记录暴露状态。这是分阶段提供材料，不宣称仅隐藏默认视图就形成访问隔离或盲评。
- 保留专用正式审查提示词。在现有profile选择上支持可选正式审查覆盖配置，默认沿用现有A配置；模型不同只是可选减相关措施，不作为独立合格的充分条件。
- 输出资格继续准确标注身份独立/证据适用性，不把同模型自动判不合格，也不把不同thread等同于科学观点独立。

验收：构造带明显倾向的请求方结论，检查默认prompt/文件包不泄露该倾向；对象/判据/限制未遗漏；按需读能追溯；作者/辅助参与者重叠及未知身份仍不能获得正式独立资格；ordinary A输入不受不必要限制。

## 6. A4：把检查机会前移，不暗中续额

- 可选isolated_replay继续是功能能力，不成为所有插件必备接口。能力与原调用配置提前声明工程检查/反馈所需时间，提示Worker该检查的有限覆盖。
- 由操作员冻结的执行预算策略决定是否预留以及预留多少；从本次已授权总窗口中分配，不能给原call额外续10秒，也不在训练结束后自动新开无预算检查。
- 支持预留的适配器执行前就分开实验截止与检查截止；不支持切分的适配器如实报告无预留/尽力执行，不伪称保证会查。不得在训练已接受后悄悄改截止或取消昂贵远端作业。
- 本轮A4只实施原调用内的预留与反馈。调用截止后，即使全场尚有余额，也不能据此续原call或重开检查；已有检查intent但无outcome保持unknown，仅维护/查询。重要候选的后置检查若确有需要，另行设计独立显式有限检查操作，从原总余额扣除并绑定原候选/输入及已知未执行证明；不在本轮顺带新增，也不重复主实验。
- 成功、未运行、能力不支持、检查不确定、明确工程失败分别展示。未运行不算通过，也不一票否决所有候选；既有必需交付审计继续独立执行。

验收：短训练能检查；长训练在预先接受的窗口分配下留出检查；无余量为not_run；缺能力为unsupported；中途崩溃unknown不重跑；检查失败不篡改原实验成功事实；总deadline/原资源消费不增加。模拟时钟和小型fixture即可，不重跑完整cov科学场。
