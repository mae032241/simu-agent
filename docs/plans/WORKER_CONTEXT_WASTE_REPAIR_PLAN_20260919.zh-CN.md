### 不变边界

- 总体目标、当前目标、精确输入与相关进展必须可访问；Worker 判断科学相关性，控制层不生成科学摘要来替代原文。
- 完整审查可以需要完整原件；优化重复展示，不强制独立审查只读摘要。
- 保留原始证据、来源、失败日志、源代码与恢复材料；不把磁盘大小当上下文消耗。
- 不新增科学必填字段、机械登记或“已读证明”准入；不改变校验职责、Run/Artifact 身份、审批、资格及执行权限。
- 不新建 MCP 服务、科学角色、知识库、跨轮读取状态机；不把 Root/Worker 隐藏聊天当科学证据。
- 不为省往返而预取尚不需要的材料，不强制复用旧 Agent；新独立审查仍保持独立性。
- 本轮不修改 Fig4 科学目标、模型或评分方法，不启动 TCAD；沿用已冻结材料进行工程验收。

## 2. 度量与完成判据

主指标依次为：实际单请求输入峰值、首请求到节点结束的净新增、重复显示的原文字节/片段及其原因。同时记录必要信息覆盖、提交成功与错误、未缓存输入、输出 token、耗时。累计输入/缓存/请求次数仅为辅助，不把缓存累计携带当多份窗口增长，也不将字符量换算为假定精确 token。

Root sol A/B 已证明峰值 24,000 → 21,009、净增 9,852 → 6,569；该改善不因累计输入 +1.18% 而作废。真实 review 的 22,521 → 67,196 是本轮定位样本，不是宣称其中 44,675 全部可删。首次必要阅读、输出撰写和平台固定成本分别保留。

每项只有在目标无效行为减少且完整性检查通过后才能标为完成。不能以内容遗漏换取低峰值，也不承诺未经实测的百分比。真实模型结果若受随机阅读影响，报告不确定性；最多增加一对预先限定的对照，不通过反复试跑挑出最好结果。配置差异或模型回执不匹配的样本不用于比较。

## 4. S1 / F1：原文读取不再因截断而重叠补读

### 修改位置与设计

- 新增一个普通本地辅助模块 `src/scidiscovery/artifact_agent/service/input_reader.py`，由 `local_workspace.py` 按现有 schema/tool reader 的方式安装为 `tools/read_input.py`。它不是 MCP/Operation，不拥有新权限、科学判断或提交门禁。
- 支持已有 Workspace 内明确路径的 JSON 和文本原文；路径按现有允许的本地读取边界解析，不放大权限或跟随路径穿越到外部。二进制 solver 产品继续使用领域解析能力，不塞进该读取器。
- JSON 支持原始 JSON Pointer 精确选值，以及仅列直接字段的目录。大对象/文本支持稳定的、不重叠的连续片段，返回当前范围、下一范围、是否完整与原件定位。不截断后伪装成完整对象；字符串片段明确标记为片段，不伪装成可独立解析的完整 JSON。
- 给输出设置固定、可解释的**完整序列化回复预算**（首版默认 4 KiB，最大 8 KiB，包含路径、转义、目录和翻页信息）。分页基于固定原件/选定值的一致序列化；UTF-8 多字节边界安全，完整拼接必须恢复精确选定值，数字精度不得改写，测试包含长小数、大整数、极端指数，保留原数字词形而非经浮点往返。若定位元数据本身超预算，返回明确的本地读取错误，不静默省掉定位。
- 所有已读回执不持久化为控制状态：下一偏移只是读原件的定位，不是“Agent 已理解”的证明。文件变化不能把旧偏移静默解释成新内容；固定输入沿用不可变原件身份，可变文件先固定读取快照或重新开始并明确版本变化。
- `platforms/codex.py` 的通用 Worker 指引用简短示例推荐此入口：按所需字段读；需要全篇时一次连续读完；别对 compact JSON 用行数充当内容预算。已有 `read_output_schema.py`/`read_tool_contract.py` 继续各司其职，不另建通用 Schema/合同框架。
- 明确内层 shell 返回预算不等于外层 `functions.exec` 聚合预算；多个结果合并时以**总显示量**计预算，避免一次打印多份各自已接近上限的片段。观察到外层截断时只补缺失部分，不用任意 fold 区间重新铺满。
- 原生 shell 权限保留。辅助脚本只能保证自己的输出，不能宣称已强制限制全部原生命令；行为验收必须证明 Worker 实际采用了安全读取方式。

### 测试与验收

1. 新增 `tests/artifact_agent/test_input_reader.py`：大单行计划、多字节、转义路径、长字符串、数组、空/null、缺失指针；遍历分页无重复/遗漏，拼回值与原件完全一致；完整回复不超预算；未授权路径/变化原件有明确诊断。
2. 测 `local_workspace.py` 的生成入口和新安装包中 helper 可执行；旧 Workspace 无 helper 时按指引使用标准库定向读取，不能必须重建旧 Run。
3. 用记录中的全文→聚合→重叠读取序列做机械负例，再用新入口读相同必要内容；同时验证最终展示出口，不只看内层 stdout 的长度。
4. 对同一冻结计划做一对 before/after 的真实 review，保留原有独立审查合同。检查总体目标、当前范围、假设/变量、验证方法、已完成状态、结论边界均未漏审；不要求生成文本逐字相同。
5. 完成条件：两次已知截断/重复补读模式消失；该节点重复显示减少；峰值/净新增有可解释改善或明确的必要新增原因。若 helper 可用但 Worker 仍反复全文读取，不能标为行为修复完成。

回滚只撤新 helper 的推荐入口/生成代码；原件、旧 Workspace、已有科学产物和科学合同不变。

## 5. S2 / F2：计算日志留存与模型展示分离

### 修改位置与设计

- `service/local_process_observation.py`、`plugins/curve_score/curve_score/analysis_workspace.py` 及实际 launcher 调用处。
- 保持现有原始日志保存策略及其真实上限；当前 128 KiB/stream 是有界留存，不宣称保存了无上限全部输出。清楚区分 total、saved、displayed 字节数和两种截断状态。
- 给现有 launcher 增加明确展示选择：计算/准备/检查默认 `summary`；已有需要 stdout 作为数据的程序调用点使用明确 `raw`。不通过命令名猜测 `cat`/计算的目的，不改进程 argv、stdin、超时、进程组清理和退出码。
- summary 完整返回上限 8 KiB：执行状态、退出码、时间、现有日志/记录路径、保存覆盖、少量有位置的错误片段。精确错误原文、路径和行号不改写；摘要无法确定原因则明说未知。
- 错误定位读取已保存原文，不只取末尾；stderr 中段 traceback/异常必须可定位。日志留存已截掉的部分只能标为缺失，不重跑求解器补日志。
- 显式 raw 保留既有消费需要，同时明确它受原生外层展示预算约束，不能宣称始终有界。需要读原文时通过 S1 或现有定向日志读取获取，不静默吞掉正文。
- 实施前盘点 `--command` 与原生 policy 所有消费者；仅模型展示消费者改默认摘要，机器解析消费者显式保留 raw，并兼容现有调用参数。不能在未核对消费者前全局改 stdout。明确处理 analysis_workspace.py 的 `--command cat analysis-start.json` 示例及现有 stdout=LOG_LIMIT 断言，单独验证 policy="inherit" 的原转发行为；摘要沿用已有脱敏规则。

### 测试与验收

扩展 `tests/operations/test_local_process_observation.py`：大 stdout、大 stderr、中段错误、成功但有 warning、无输出、超时/取消及残余进程组、raw 数据消费。验证执行一次、退出码不变、保留字节/覆盖正确、summary≤8 KiB、详情可读；不把 wrapper 正常退出当科学成功。

日志测量采用确定性命令即可；若发现真实消费者依赖模型读完整计算 stdout，再做该消费者的一次限定回放。未触发的新实验不作为本项验收前提。
