## 3. 修复后接口及职责

下列新增接口是拟实现的 Root 工程控制工具，不是当前已可调用的 Operation 名称。实现时从 RootTool 唯一定义生成模型可见 Schema，并同步调度说明及相关脚本。

| 接口 | 明确行为 |
| --- | --- |
| execution_start | 保留：按原批准启动精确执行。 |
| execution_sync | 只轮询并保存同一执行的状态与有界日志/时间信息；终态仍可刷新。绝不启动、等待或重试产物收集。 |
| execution_status | 只读本地已知状态；附带已保存观测及收集摘要，不访问 VM，不启动工作。 |
| execution_collect（新增） | 显式启动或续接同一执行的后台收集，快速返回已接受/进行中/已完成。同一执行运行中重复调用幂等；其他执行占用唯一工作槽时返回 busy，不排队、不创建尝试。失败或重启后由调度方显式续接。 |
| execution_outputs | 保留：登记语义输出名并列出已收集输出。未 collected 时给出准确状态诊断；不偷偷下载文件。 |
| diagnostic_read（新增） | 根据控制生成的诊断引用读取有界工程详情。只允许当前实例/会话中可见任务的记录，不接受任意文件路径。 |

execution_collect 只接受当前实例的精确执行名及可选本次收集总预算，不接受服务器目录、输出改名、替换执行或科学参数。调度方选择收集预算；默认值在工具 Schema 中可见。收集只消费原执行的终态文件，不重新执行审批，也不授权新求解。

本次总预算在接受请求时冻结。重复调用返回活动尝试实际采用的预算，不能隐式延长、替换或重启该尝试；后续显式续接可选择新的预算。

收集摘要包括：状态、开始/更新时间、已完成文件数和字节数、可用时的总数、实际采用的预算、最近错误引用。字段由控制层生成；未知值标未知，不虚构百分比。Execution 的原 state 继续表示原生命周期；收集中的状态作为附属运行记录，不扩展其数据库状态枚举。

## 4. 按顺序实施

### P0：基线与最小反例

修改范围：仅测试及本计划的证据目录。

1. 保存精确改前范围、安装文件摘要、现有实际超时配置及冻结执行的语义状态。
2. 在隔离夹具中复现：终态 sync 被慢 collect 拖住；中断后的已完成文件被重新 get；空 stdout/stderr 超时被转换为泛化错误；观测文件缺失与损坏无法区分。
3. 反例不得运行真实求解器、读取生产科学存储或依赖真实长时间 sleep。延迟夹具和可控时钟只验证所对应的边界。

验收：每项失败能定位到原实现的确定分支；现有安装日志和探针不被重写。

### P1：先补具体错误及可读记录（B4）

主要位置：

- src/scidiscovery/artifact_agent/interfaces/mcp.py、mcp_proxy.py；
- mcp_local_worker.py、mcp_hardened_worker.py；
- 新增一个小型 service/engineering_diagnostics.py，作为共享记录和脱敏投影实现；
- Root 工具声明及工程诊断读取路由；
- plugins/tcad_artifact/tcad_artifact/transport_logs.py、command_adapter.py、ssh_transport.py。

具体修改：

1. 在异常原始捕获处记录：所属实例/任务、操作、发生层、异常类型、具体消息、异常链、已知退出码、触发时限、实际耗时、关联日志和已完成工作。没有的事实留空，不猜测。
2. 原始异常在服务私有诊断记录保存；模型获得有界、脱敏的具体摘要和诊断引用。保留已有合法 DiagnosticError/校验字段定位，不把所有异常映射成同一句话。
3. stdout/stderr 为空也保存超时自身的事实。空子进程输出不再是错误解释的唯一载体。
4. Root/Worker/MCP 代理复用同一工程错误格式；通过错误响应 envelope 传递，避免把工程字段塞进科学结果 Schema或科学校验规则。
5. Worker 同时使用已有 run_activity/tool-attempt 记录。错误记录写入失败时保留原故障与记录故障两个事实，不用后者覆盖前者。
6. 代理与服务无法连接时，代理在自身 stderr 留下结构化错误并返回具体类型、层级和时限；不能伪造“服务端记录已保存”的诊断引用。服务可用时由诊断读取工具提供关联记录。
7. 所有详情读取有字节/条目边界并复用现有敏感信息处理；错误类型、失败动作与时间事实不能因脱敏整体消失。

验收：真实 stdio/Unix-socket 路径下，传输超时、连接失败、输出未收集、一般运行异常可区分；空 stderr 仍可定位；敏感测试字符串不出现在公开消息中；科学输出拒绝仍保留精确字段。

### P2：拆开日志同步与收集（B1）

主要位置：

- execution_bridge.py、service/executions.py；
- interfaces/mcp_root_execution_routes.py、mcp_root.py；
- 新增小型 service/execution_collection.py；
- interfaces/mcp_daemon.py 及 build_root_router 装配处；复用 runtime_plugin_bindings 的现有配置装配。

具体修改：

1. 从 ExecutionBridge.sync 删除终态 collect/ingest。sync 只更新外部状态、保存/返回最新观测。终态重读不再次提交相同状态转换；collected 也不因此丢掉原 solver 的终态信息。
2. 轮询失败返回本地已知状态及明确 observation_error，不能把求解状态改成失败或丢掉旧日志。正常响应始终不包含全量产物。
3. 新增 execution_collect，将原 collect → ingest_result 移到控制服务拥有的后台执行段；请求应在工作接受后返回。
4. daemon 共享一个小型收集协调器；每次实际收集使用一个独立本地子进程，默认仅一个活动进程，不使用线程执行可能不返回的 collect/ingest。父进程只做短请求、监督及状态投影，不引入通用队列、额外服务或新的科研 Run。忙时行为按第3节执行。
5. 同一 execution 持有专属收集锁。代理超时、重复请求、多 Root 会话不能产生同时下载同一执行的多个工作者。失败后不自动无限重试；查询不会偷偷重新收集。
6. 进度与收集尝试记录存于现有 execution exchange 目录，原子更新。持久记录保存恢复所需事实；活动进程句柄只是运行缓存。子进程从控制服务传入的配置和已冻结执行记录重新打开服务及适配器，不 fork 活动数据库连接，不序列化活对象，不重新启动完整 Root/MCP 服务。执行入口私有，只能处理本次精确执行的 collect/ingest，不能 submit 或选择科研行动。
7. 重启后残留 running 记录需与实际锁/任务一致性核对，报告 interrupted，保留下载缓存。由新的显式 collect 续接。服务停止处理与已有维护/实例关闭约束一致，不让旧后台任务在停止后继续登记。
8. 完整收集后继续使用原 ingest_result、原 Artifact 完整性与来源登记。补足登记崩溃幂等性：在登记前保存同一输出清单及 collected_at，恢复时复用；已登记的同一 manifest 可完成原数据库状态提交。不得重新生成时间戳导致同一 idempotency key 内容不同。部分下载只进入缓存；适配器必须完整返回原描述符清单后才进入登记。
9. 后台登记完成后，Root 现有 execution_outputs 发布语义名称；execution_sync 可沿用已完成结果的名称发布。execution_status 保持纯读，不因缺名字重新下载或登记。不能出现后台已 collected、结果却永久没有可发现语义名称的情况。

停止、恢复与旧接口的实施约束：

1. 正式收集子进程统一拥有 collect → 检查点 → ingest 的本地执行范围；标准 Popen 进程句柄及进程组用于停止与回收。旧 collect 也只在这个边界内调用，不能回退为 daemon 中不可终止的线程。保留旧签名；缺少细粒度进度时标 unavailable，不新增适配器资格门禁。
2. 在总预算中预留停止回收时间 `min(2秒, 总预算的10%)`，其余为实际工作预算；实际采用值写入收集记录。工作预算耗尽后先请求停止，预留时间过半仍未结束则终止本次本地进程组并 wait/reap。仅真正退出后释放执行锁及工作槽；不能用 Future.cancel、写 timed_out 或客户端断开充当停止证明。Run 内调用也必须把这段时间计入原剩余预算。
3. 子进程及其受管传输进程不得脱离本次停止范围；服务正常停止走同一回收路径。父服务异常退出时，通过父子存活通道触发子进程停止；重启先核对控制拥有的锁和进程身份，回收残留任务后才接受同一执行的续接。不能只看旧文件里的 PID 就杀进程，也不能仅删除锁文件声称已回收。
4. 若操作系统尚未确认进程退出，明确报告 stop_pending 与具体工程原因，同一执行不得重入；不声称全部故障都能被硬超时消除。可终止的旧调用必须在受控测试中回收，不得将正常兼容路径设计成永久占槽。
5. ingest 在每项 Artifact 登记之间和最终事务之前检查停止/剩余时间，数据库等待裁剪至剩余预算。已经进入的短原子写入允许在停止余量内结束；不得在 Python 线程内部强抛异常破坏事务。最终仍需终止子进程时，依赖原有原子写入及数据库事务恢复，再从稳定检查点幂等续接；验证进程被终止的实际故障点。
6. 子进程退出后先核对持久化事实：最终事务确已提交则报告 collected，记录迟到/停止事实；否则记录 interrupted 或 timed_out，保留完整缓存及已登记 Artifact。不能把半成品登记为完整结果，也不回滚已封存结果。若现有写入不能承受该边界的进程终止，只补其必要的原子恢复点，不重构 Artifact 存储系统。
7. 子进程覆盖既有维护锁的共享区间；服务停止先停止接收新收集，再回收活动进程。实例关闭继续复用现有执行生命周期判断，不新增科研完成条件。停止确认前不得由另一父服务登记同一执行。

验收：慢收集期间日志/状态查询仍快速完成；client 断开不杀求解器或重复收集；可终止但不返回的旧 collect 被实际回收后另一执行能收集；busy 不产生队列；重启与登记阶段故障可恢复；只有真实完整登记后才为 collected。

### P3：分别定义超时，复用已下载文件（B2、B3）

主要位置：

- command_adapter.py、execution_adapter.py、ssh_transport.py、runtime_plugin.py；
- local_debug_service.py、debug_contract.py、debug_adapter.py、output_recovery.py 的实际调用适配；
- execution_control.py 中现有本地 socket 收集/读取入口；不扩展 VM runner 协议；
- command/SSH 示例配置、部署配置生成与兼容处理。

采用独立的操作预算，不统一调大旧 operation_timeout_seconds：

| 预算 | 所有者及本版规则 |
| --- | --- |
| 状态/日志查询 | 短查询总预算；由适配器执行。代理响应预算需覆盖服务查询预算及小量序列化余量。 |
| 建连 | 沿用 SSH connect_timeout_seconds，裁剪至本次查询/文件剩余预算。 |
| 单文件无进展 | 以实际传输字节增长判断，独立于日志查询；触发后保留已完成文件。 |
| 单文件总时限 | 独立文件传输预算；不能以查询的30秒总限替代。 |
| 整次收集 | 调度方在 execution_collect 选择并记录；包括适配器准备、传输、登记和停止回收，所有子步骤裁剪到剩余时间，不改求解时限。 |
| 求解执行 | 维持原已批准项目的资源限制。 |

首版公开默认值：状态/日志查询5秒，代理短响应默认仍为10秒；连接沿用现有5秒；单文件总时限沿用现有SSH120秒；无字节进展30秒；整次收集默认600秒、可由调度方显式指定。它们是可调整的工程预算，不是科学门槛或完成时间预测。测试通过缩短配置/受控时钟验证语义，不能靠等待上述真实时长完成验收。

本版具体内部合同（不新增科学 Schema）：

- 在 execution_collection.py 定义一个普通 CollectionContext：`deadline_monotonic`（工作截止点）、`stop_deadline_monotonic`（总预算截止点）、`file_timeout_seconds`、`idle_timeout_seconds`、控制层进度回调，以及 `remaining_seconds()` / 停止检查。预算默认值只定义一次，由 Root 工具字段和适配器配置投影复用。上下文由调用者生成，Agent 不填写进程、案例或文件关联字段；重启续接创建新 context，不复用旧进程的时钟记录当作新预算。
- 既有执行适配器增加可选方法 `collect_with_budget(external_run_id, *, context: CollectionContext) -> tuple[LocalFileDescriptor, ...]`。成功只返回完整的原描述符类型；失败抛出保留层次/原因的工程异常，部分成果仅保存为缓存与进度，不混进成功返回。
- 作者 debug bridge 的同名方法仍返回原 CollectedTCADDebugRun；它把同一个 context 交给底层执行适配器，转换结果时继续检查剩余时间。原 `collect(external_run_id)` 保留原调用语义与原默认值；所有本版受影响的正式收集、作者调试调用点显式改用新方法，不依赖默认600秒。旧适配器走 P2 的受控兼容调用，不通过修改科学输入来补接口。
- context 的回调/活对象不跨进程或 socket 传输。command 请求的可选 collection 参数序列化上述四个预算字段，另传控制选择的进度文件位置；本地 SSH 桥消费后不透传给 VM。进度按块限频原子写入原 exchange 下的记录，完成文件及失败时立即更新；协调器读记录，Root 不为查询重发 SSH。
- 本机 socket 的 tcad_collect 增加同一可选 collection 预算参数，并同步其工具输入定义；服务端局部裁剪清单读取及摘要计算，客户端整体等待也受同一截止点约束。此路径返回本地已有文件描述符，不启动后台下载；不伪报网络字节进度。客户端超时不等于服务端已停止，服务端自己的剩余预算检查必须覆盖实际工作。
- 本轮 command 桥和 Unix-socket 服务均在控制主机上，统一沿用同一单调时钟截止点，不在序列化后重新计时。跨 VM 的 SSH 命令仍由本地传输进程按剩余时间监督，不要求远端解释本机时钟。连接解析、SSH 建连、文件循环、摘要和登记都不能各重新启动一份600秒预算；不扩展异地主机时钟协议。

接口/配置具体要求：

1. 旧 operation_timeout_seconds 保留为普通命令及旧 collect 调用的兼容设置；本版正式收集显式使用新的预算路径，不再受其30秒默认值约束。新增预算字段必须有真实执行消费方、公开默认值与部署示例，不接受“Schema新增但代码没使用”。
2. 根层短查询、后台收集及TCAD子命令均收到正确的本次预算。command 与 socket 适配器分开测试；socket 收集等待用收集预算，不沿用10秒查询默认。
3. SSH 收集前核对本执行目录中已完成文件与远端清单的路径/大小/摘要。一致则直接复用；不重新下载。检查只用于传输完整性，不重新判断科学案例映射或参数合理性。
4. 下载写入临时文件，按块写盘/计算摘要，完成后原子发布。中断文件不进入已完成清单；首版从该文件开头重传，已完成的其他文件必须复用。暂不实现跨网络协议的任意字节断点续传。
5. 复用现有 get/get_to 协议；调整本地 get_to 为可观察字节进度的有界下载，stderr同步写有界日志。避免将整个产物放入 stdout 内存再复制。
6. 每完成一个文件更新收集记录；查询直接读取该记录，不为查询再发 SSH。原 solver 日志与产物保持独立入口。
7. 超时/停止终止本次本地传输进程组，保留完成缓存，不取消原远端 solver。工作者确认停止前不释放同一执行锁，不允许重复工作者覆盖晚到结果。
8. 旧 collect 的兼容入口、细项缺失和真实停止统一采用 P2 规则；不再保留“无法停止的旧线程无限占用工作槽”的实现选项。对不受当前本地进程管理的外部副作用，只报告实际已知状态，不把本地停止说成已停止外部工作；本轮两种 TCAD 路径均不因此产生新求解。
9. local_debug_service.run 的终态分支显式计算当前 Run 剩余时间及工具已授权剩余预算，扣除停止回收余量后调用 collect_with_budget；覆盖 _finish 的读取和结果转换。不能仅依靠 _start 时的求解时限裁剪。旧 debug 适配器也必须通过受控子进程兼容执行；这个调用不创建 Root 收集尝试、不占用正式收集的全局工作槽、不成为新的科研 Run。
10. output_recovery 保留原 io_budget、字节额度及输入绑定。列目录/读取单文件继续走 inspect_outputs，不转为正式 collect；为两种适配器该现有方法添加仅关键字可选参数 `deadline_monotonic=None`，在服务入口按 `min(IO剩余时间, Run剩余时间)` 计算并传给本地 command/socket 请求，替换仅浅拷贝适配器属性的间接裁剪。所有连接/读取步骤共用这个截止点；不继承正式收集600秒。旧调用不传新参数时保持兼容。

验收：超过旧30秒的有效收集可完成；同一慢传输在剩余预算更短的作者调试/分析恢复路径按授权时间结束；日志查询不等待；中断后已完成文件的 remote.get 次数不增加；单文件无进展和整体超时原因不同；文件摘要/执行来源错误仍拒绝；错误仅影响对应传输。必须经过真实服务调用点测试预算消费，不仅断言适配器接受了新参数。

6. local_process_observation 不再把所有读取异常默默变成同一个 unobserved。记录错误类型和有界原因；没有时间证据不虚构耗时。

8. 终态Execution观测、收集进度和Agent本地计算覆盖分别展示。没有native错误记录不等于没有native错误。

## 6. 定向测试与资源预算

使用 scid-change-scope-checks 选择受影响测试。用户要求优先：**禁止全量/并发pytest、pytest-xdist与并行求解。**

沿用现有串行harness：512 MiB进程树RSS及地址空间上限、单线程数值库、每批150秒。按测试功能拆小批次；实际RSS/运行时间与失败原样记账。pytest收集也算资源占用，不先全目录收集再过滤。遇到内存限制先缩小单批范围，不能直接扩大预算。

| 分组 | 必需的有效对照 |
| --- | --- |
| 同步/收集边界 | 真实proxy→daemon下慢collect不拖住sync；终态日志可刷新；状态查询不启动收集。 |
| 收集恢复 | 重复请求只有一个下载且不延长预算；其他执行busy不排队；掉线、服务重启后复用完整文件；下载完成与登记中断分别恢复；登记时间戳稳定。 |
| 时间与停止 | 查询、建连、无进展、单文件、整次收集分别触发；不可返回但可终止的旧调用被真实回收，下一执行可工作；停止及服务退出有界；原solver调用次数不增加。 |
| 预算贯通 | 正式收集、作者调试终态与分析恢复分别经过实际服务入口；command/socket/SSH各层消费同一剩余预算；逐项调用不得重置总时钟；短Run不能借正式600秒预算延长。 |
| 登记停止 | 在逐项Artifact登记、manifest已写及最终事务前后注入进程退出；未提交事务可恢复，已提交结果不被误报未完成，不重复登记或重下载。 |
| 传输完整性 | 43项级别清单或等效夹具可跨批恢复；同执行缓存有效跳过；其他执行/坏摘要/未完成文件不能冒充完成。 |
| 诊断可读 | 空stdout/stderr超时仍可读根因；记录失败不遮蔽原错；敏感信息脱敏；跨实例及任意路径读取被拒绝。 |
| 观测边界 | 三类角色共享可选launcher；验证实际执行环境及输入输出，无额外资源限制；旧分析行为及旧Run兼容；无观测也可提交；不能利用launcher扩大角色权限。 |
| 既有流程 | 精确执行批准身份、终态失败结果收集、分析恢复、旧status-only/collect适配器、作者debug和已有目录装配仍可用。 |
| 安装贯通 | 隔离安装实际wheel与生成配置，Root新工具可见，旧配置有明确有效预算，stdio/daemon完整路径通过。 |

优先扩展所属测试：test_tcad_log_progress.py、test_log_preservation.py、test_analysis_evidence_recovery.py、test_local_process_observation.py、test_baseline_effect_lifecycle.py、test_r4_execution_approval_identity.py、test_platform_configuration.py及对应已有SSH/command夹具。收集协调器需要独立所属测试文件；不为机械字段逐项新增重复测试。
