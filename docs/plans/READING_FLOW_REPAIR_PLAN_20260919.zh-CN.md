# 读取流程回退修订计划

日期：2026-09-19。状态：用户授权的源码修订、定向测试与隔离安装完成；部署及真实 D 两轮对照已完成，整体峰值比 B 降低 15.74%；首次四次读取误用及独立复审仍未收尾。见[原生验收](READING_FLOW_NATIVE_D_ACCEPTANCE_20260919.zh-CN.md)。详见[实施记录](READING_FLOW_REPAIR_IMPLEMENTATION_20260919.zh-CN.md)。本计划接管前一轮 token 未通过项，保留 [C 组失败验收](MECHANICAL_READING_NATIVE_C_ACCEPTANCE_20260919.zh-CN.md)及全部 B/C 原始计量，不改写历史审查结论。

## 边界

控制层管理机械绑定，科学 Worker 决定材料是否充分。保留精确正文、总体目标可读、来源、独立审查与执行授权。没有新增 MCP、Operation、数据库字段或科研提交门禁。可丢弃阅读缓存不是已读/记忆证明。缓存不可用、上下文丢失时有精确重读退路。

本轮唯一范围为三项真实浪费：C1 的续读误用、C2 的角色/合同复用不明确、两轮 Schema 多次携带同一总览。正常科学原件不自动省略；禁止用不读必要证据换低窗口。

## 1. 续读只表达继续

修改 input_reader.py。首次选择材料、字段、文件/目录模式后，缓存同时保留当前选择；裸 --next/--repeat/--restart 沿当前选择，不要求重填别名、--file、pointer 或游标。已有显式完整选择仍支持，切换材料必须明确指定。隐式续读不允许混入半套选择；无当前选择或缓存损坏时明确要求重新指定材料，不猜来源。

当前选择与分页更新在同一现有锁和原子写中提交。不同显式选择仍各有导航位置；裸操作只指最后成功选择，不声称并发交付排序。发生交错时允许显式选回或从头读取。完成后 repeat 仍可重发末段，next 明确已结束。材料变更先报告变化；读取失败不推进选择。旧工作区保持原 helper，open 按实际能力给简短兼容用法，不热改冻结文件。

验收复现 C1：先读 --file assignment.json --pointer /role_instructions，然后裸 --next/--repeat；无参数遗失错误、无 restart 重印，精确拼回原正文。覆盖源变化、空文本、选择切换、损坏、并发更新和旧 helper。

## 2. 控制层输出合同复用指引

利用 worker_connections 已有同 session/thread 的历史绑定查询前一 Run，不新建历史表。gateway 继续先验证实际模型/强度，既有 attach 限制不改；仅向 Local worker 内部传入前一已绑定 Run 的定位。

Local open 按当前与前一工作区的实际角色正文、输出 Schema 和工具合同比较，给出短的“未变且仍保留时可复用／需要读取”指引。不返回旧 Run ID、路径、哈希或来源清单。材料缺失、损坏或不能比较时退回读取，不拒绝当前 Run。不能只凭 compiled digest 假定动态 Schema 相同。

首次/不能建立前序关系正常读取；受控接续必须仍读取新 instruction、目标及输入索引、语言、预算、输出和恢复要求。复用提示只证明合同相同，不证明模型记得；压缩或丢失内容仍可完整重读。工具产生新证据导致 Schema 变化时以当次原件为准。

验收从真实统一 MCP 路径覆盖初次、接续、gateway 重建、不同线程及模型不匹配；动态 Schema 或工具合同变化必须被区分。新语言、任务与目标入口不得省略。Hardened 保持现有能力。

## 3. Schema 公共部分自动去重

复用 output_schema_reader.py 的引用解析与闭包计算，不增加第二套 Schema。多 --field 合并并集；默认 CLI 保存小型可丢弃阅读缓存，包含当前原件指纹和已返回的定义位置，不复制正文、不跨 Run。

首次返回总览、公共约束及所选字段必要定义；后续同原件字段读取仅补此前未返回的定义，说明依赖仍保留的总览。已返回内容无需在每个字段请求中重复携带。--full 在首次回复丢失、上下文丢失或需要原文时总能重建；原件变化、缓存丢失/损坏、无法保存时保守返回完整所需部分。复杂引用仍保留既有全文回退。不输出内部哈希作比较任务。

缓存置于现有工具私有 .read-input 目录，生成指引的狭窄例外拓展为安装的输入/Schema 读取器；Agent 和其他 helper 的 scratch 规则不变。锁保护同时字段请求的去重，不代表交付确认。旧 Python read_schema API 及明确 --definitions-only 工程模式保留；新 CLI 默认不要求 Agent 自行管理去重状态。

验收复现 C1/C2 实际 Schema：总览后读取 evidence/findings/hypothesis_reviews，合并或连续调用均不重印总览，共享定义只返回一次。用原件闭包核对重建结果；未知字段仍明确报错，原件变化/坏缓存/--full 不丢规则。只调整提示词不算完成。

## 4. 顺序验证与完成门

保存当前 C 工作树快照；依次实现并做定向行为测试，进程树采样预算 768 MiB、串行、不得并行全量测试。检查已有角色/Schema断言，不保留要求输出机械哈希的旧测试。隔离 wheel 验证新 helper、生成指引和 MCP 响应；独立审查代码与恢复边界。

先回放 C 的真实错误及重复展开，报告正文、包装、请求次数与错误；这不是 token 证明。部署重启后沿原协议做 D 两轮 sol/medium、600 秒，组间新 Agent、组内复用，不额外告诉 D 如何省 token。先核对实际加载和精确输入/合同，分别比较首轮、接续和整体峰值/净增长，同时检查完整交付、必要证据和错误。必须同时对照 C 回退样本与更好的 B 样本，不能只相对 C 改善便宣称目标完成。

仍不通过则保留失败结论，不热改候选、不反复重跑挑结果。缺部署或 native usage 明确待验收；原生硬内存限制依然不可由离线 guard 代替。
