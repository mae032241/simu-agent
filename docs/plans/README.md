实现责任与合同见[架构](../ARCHITECTURE.zh-CN.md)，候选验证事实统一见[发布状态](../RELEASE.zh-CN.md#current-status)。本页只列待办，不维护重复验收流水。

## 优先处理

1. **清除失效工具链**：L4 作者/修订探针仍调用已删除 Operation，旧 A/B 脚本缺失输入或依赖退休入口。逐项删除失效脚本、专用测试和发布清单项，保留仍有效的通用 Worker 启动器及资源监督器。
2. **清除已确认的零消费者代码**：曲线插件的旧 diagnosis/error 包装函数、`_single_crossing`、核心 `OutputBundle` 等。删除前确认动态注册、安装入口及公开插件 API 均无消费者，不以行数或文件名决定。
3. **真实完整任务验收与 Token 对照**：固定科学任务、模型配置、输入和候选，核对跨任务续接、阶段交付、附件/UI、可选审查、执行授权及恢复；分别记录 Root、负责人、内部助手逐请求 usage、缓存和无用回包。短初始化、工程测试或单次助手调用不证明完整研究链或成本收益。
4. **隔离边界**：SEC-002 仍开放。若要支持不可信 Worker，应由可信启动器绑定身份，并以不同 OS 身份或沙箱隔离控制 socket、数据库、CAS 和审批密钥。共享 UID 的令牌或元数据不能代替隔离。

## 保留的验证缺口与设计取舍

- [约束登记](../architecture/SCIENTIFIC_AGENT_CONSTRAINTS.yaml)中的 `pending_review` / `known_issue` 保留；其中历史描述需逐项对当前候选复核，不能按旧报告推断已关闭或仍可复现。
- 实例归档需确认真实写入者停止；终态 Run 不足以证明 LocalTrusted 原生命令已退出。完整生产现场归档、恢复及回滚验收不能由旧浏览器或挂载沙箱检查替代。
- Hardened 仍是显式后端；是否退役属于产品决定，不作为垃圾代码直接删除。
- 数据库合并、服务拆分、人工内容接管和探索宽度属于后续设计议题；先证明具体收益与迁移边界，不自动启动大重构。
- 通用插件能力应有不同领域的实际交付证明；仅有声明或参考插件不代表所有插件均已通过。
