## Required amendment

### P1 — Populate `producer_inputs` in scheduling's authoritative reconstruction, not only Root's initial projection

**Plan location:** lines 79–85 and 133–138. R1 describes projecting `InvocationArtifact.producer_inputs` at Root's existing `completed_for_output` call and limits production changes to the listed files. `runs.py` is mentioned only as existing behavior to reuse; its necessary metadata-construction change is absent from P2 and the eleven-file scope.

**Actual reachable path:**

1. Root builds `InvocationArtifact` using an already loaded producer at `src/scidiscovery/artifact_agent/interfaces/mcp_root_operation_routes.py:1099` and `:1101`. R1's projection will therefore let the new `_evidence_revision_cohort` inspect the audit's exact `source_material` bindings during Root preflight.
2. `RunService.schedule` deliberately reconstructs all input artifacts from authoritative storage before any Run/workspace write: `src/scidiscovery/artifact_agent/service/runs.py:132`. It independently loads `producer` at `:136`, then creates new `InvocationArtifact` instances at `:137–147`. These are not the Root-projected instances.
3. Scheduling calls `preflight_operation` again at `runs.py:148–152`. That repeats the guards (`src/scidiscovery/operations/invoke.py:218`, `:365–379`). `science.evidence.revise-from-critic.v1` explicitly declares the affected `evidence_revision_cohort` guard (`src/scidiscovery/general_science_agent_operations.py:607`), whose existing source comparison is at `src/scidiscovery/general_science_components.py:108–114`.

With R1's default `producer_inputs=None` and only its named Root construction site updated, the second preflight loses the exact audit-source projection. Under R1's correct fail-closed rule for missing metadata, an admissible revision passes Root preflight but cannot schedule. This also regresses a previously valid **no-note** revision, since the revised guard always needs the producer bindings. Falling back to all parents or trusting the Root object would undo the intended integrity boundary.

**Smallest amendment:** explicitly add `RunService.schedule`'s `InvocationArtifact` reconstruction to P2, populating the same ordered projection from its already loaded `producer.inputs` and applying the same exact-output/completed-producer integrity rules. Update the file count/scope. Preserve the authoritative reconstruction, repeated preflight, recovery algorithms, and persisted Run format; this is a projection-completeness fix, not a new lifecycle design. No additional historical scan or producer-input persistence is needed.

**Focused acceptance:** take an otherwise admissible exact intake/audit/foundation/portfolio/critic/source cohort through the real Root `operation_preflight` **and** `operation_invoke` scheduling path, both without a note and with a note on the original audit. Both must queue successfully with the unchanged formal source set. Missing/substituted original sources must still reject, and missing producer metadata must produce the bounded diagnostic rather than a parent-set fallback. A direct call to the pure guard or Root-only preflight cannot establish this acceptance.

## Conditions already captured by R1, not additional architectural blockers

- The new `producer_inputs` is a nonpersistent projection of the original ordered Run bindings. Preserve `None` for unknown and an empty sequence for known empty. Retain full output provenance separately: primary output parents include all Run inputs and can also include a controlled evidence manifest (`service/runs.py:1227–1237`). Do not equate the new sequence with every parent for arbitrary output families or reconstruct old binding order from a new catalog.
- Parameter qualification must keep the exact optional checklist, extraction source order/aliases, expansion family, and ordered audit members. The existing checks at `parameter_operations.py:561–577` and `:628–639` explain why simply deleting parent equality is insufficient. R1's proposal to derive formal members from exact producer ports while keeping complete parent integrity is adequate; retained `evidence_sources` supplies the source aliases that a port/ref-only projection intentionally does not duplicate. Existing Transform families can keep their current path.
- `prior_signal` is not a general exemption from review admission. It works here because newly ingested text has no producer review contract: `_operation_output_contract` returns no contract for such raw records (`mcp_root_operation_routes.py:1591–1592`). Keep the existing review checks for actual scientific outputs and do not generalize the new text behavior into a blanket bypass. `SourceReference` already supports `user_statement` (`schema/cognitive.py:24–32`).
- The analysis start document is bounded: `append_view` can omit later entries (`curve_score/analysis_workspace.py:60–65`), and TCAD reserves a smaller first-pass budget (`tcad_artifact/analysis_bindings.py:173–181`). Implement A6 so its promised note path/origin remain reachable even when that index is full; a bounded navigation entry into the complete assignment is sufficient. No need to increase all display budgets or duplicate the raw text.
- Formal plan/project/case parsers inspected use their own named ports or descriptors. Generic and TCAD analysis reference checks can recognize the new source without treating it as solver output; TCAD binds solver identity by `solver_outputs`/`tool_evidence` ports (`tcad_artifact/result_analysis.py:298–312`, `analysis_bindings.py:30–38`). No extra scientific validator or registry is justified.
- The shared declaration route and the direct TCAD author/review and parameter constructors can cover the intended 25 public Agents without adding the port to Transform/Effect Operations. Runtime callable identity changes must use existing configuration identities as R1 requires; body edits alone must not be presumed to change every digest.

The user-facing behavior can be delivered by raw text registration plus explicit new-task bindings. R1 does not require a scientific preprocessing Run, invented objective/result/review, truth classifier, mechanical acknowledgment form, new database entity, or automatic workflow. Correct the one P2 projection omission, then retain the proposed focused integration, installed-entry, independent implementation review, and small live continuation acceptance. Passing this plan review would not by itself establish those runtime results.
