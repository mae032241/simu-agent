## 最后一项阻断已关闭

R2 明确 normalized_request 只包含规范化的显式根选择与配置；preflight 的展开仅供校验/预览，不能让客户端声明一个可信派生集合。首次 invoke 通过同一纯解析函数对精确不可变 manifest 求值，仍执行实际状态下的正常准入，在创建 Run 时冻结完整绑定。相同显式请求的同名重试使用服务端保存的请求身份与冻结集合。

这与当前 OperationCallInput 的普通输入选择结构、可选 preflight 及最终完整请求指纹相容；不需要令牌、快照授权或第二套请求生命周期。R1 所指出的“伪装已展开以遗漏依赖”和“归一展开项被误当新显式请求”的设计缺口已经收敛。

前文 B.3 的“消费同一解析结果”据首版合同表应理解为：相同精确来源与配置经同一解析函数得到相同绑定，而非跨请求信任客户端返回的结果。§2 的输入准入“一次完成”约束的是正式 invoke 的准入职责，不排除用户主动选择 preflight 作无副作用校验；提交阶段不重做输入资格。以具体合同表为准，整体没有执行逻辑冲突。后续文字整理可将 B.3 直接写成“共用同一解析函数”，这只是澄清，不构成阻断。

## 最终审查判断

- **功能设计**：必要依赖、历史缺口、稳定引用、错误可恢复、能力说明及模型输入裁剪均有责任方和验收路径；首版没有承诺任意文件或所有后续产物自动继承依赖。
- **源码可实施性**：manifest/工具发布记录、声明端口、Root请求冻结和现有诊断边界提供明确落点。版本、端口及请求内容需做有界改动；不能将本方案描述成零合同变化。
- **科学与控制分离**：科学作者选择无法机械获知的必要材料；控制层解析精确身份、预算及来源映射。背景附带不升级资格，独立审查和执行审批保留。
- **最小性与兼容**：不新增依赖数据库、全局图系统、多版本运行解释器或可信快照协议；历史结果可读与旧Run可续接分开，旧合同不匹配时明确停止续接。
- **计量与验收**：配对输入和环境、逐请求窗口、压缩分段、机械字节与原生token分列已明确；小样本只报告观察收益与波动，功能退化不能由平均token改善抵消。

实施时仍须完成计划已经要求的精确注册项/版本清单，并验证普通invoke、preflight→invoke、同名重试及伪造/遗漏依赖的真实入口负例。依赖超限、跨来源同名alias、旧manifest缺关系、合同漂移续接拒绝应保留在定向验收中。这些是实现必须兑现的既定检查，不是新增计划阻断。
