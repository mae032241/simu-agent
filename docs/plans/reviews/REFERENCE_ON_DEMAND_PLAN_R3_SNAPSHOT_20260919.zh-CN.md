# 准确引用、按需取证：根因整改实施计划 R3

状态：已按[R2独立审查](reviews/REFERENCE_ON_DEMAND_PLAN_R2_REVIEW_20260919.zh-CN.md)修订，待复审，未实施；[R2原文快照](reviews/REFERENCE_ON_DEMAND_PLAN_R2_SNAPSHOT_20260919.zh-CN.md)保留，三项阻断的修订不等于审查通过。Fig4保持暂停。本计划取代前版“创建任务时自动展开全部用途依赖”的方案；[R1快照](reviews/ROOT_CAUSE_REMEDIATION_PLAN_R1_SNAPSHOT_20260919.zh-CN.md)及其[审查意见](reviews/ROOT_CAUSE_DEPENDENCY_LEGACY_R1_REVIEW_20260919.zh-CN.md)保留，历史审查不继承为本计划通过。

## 1. 修订的核心决定

Root选择任务和报告，不手工搬运报告中每个引用。控制层保证这些引用可以准确定位、在授权范围内读取，但不判断哪些证据科学上必要，不递归打包全部父链。下游Agent自行选择需要核查的引用；只有明确选择复算某个计算时，才访问该项计算记录中的算法、输入和参数。

父链用于来源追溯，直接引用用于导航，计算请求记录用于复算。三者不能互相冒充。服务提供资料不证明模型已读，更不证明科学内容已验证；hash只能确认内容，不能替代准确manifest绑定或读取授权。

## 2. 子任务实际接收什么

初始assignment保留角色/工具权限、本轮指令、总体目标入口、当前目标、预算/语言/交付要求以及Root选中的精确报告和补充输入。默认不注入它们所有祖先、脚本和CSV正文。

控制层提供报告的有界直接引用索引：引用在该报告中的作用域、简短用途或原文定位、材料类型和读取入口。只选择结构化引用已有字段，不能让控制层编造新的科学摘要。完整目录很大则分页，assignment仅给入口和条目数量，不强制预读整页。

Agent发起读取后，控制层提供指定引用的原件/所选字段/文件入口。读取另一份报告时，只返回其内容和直接引用入口，不在同一次调用里自动递归加载其引用。原件图像等非文本媒介保留可用的查看入口。

## 3. 精确定位：登记一次、直接使用

复用Artifact、Run、ToolEvidenceManifest及既有源绑定，不新增依赖数据库、全局“最新关系”索引或Agent填表。

- 框架计算工具复用已接受计算请求中的输入、算法标识/版本、参数与输出记录。受控脚本只有在现有执行记录完整保存这些信息时才能提供复算导航；不要求发布后重填sources。
- 普通shell没有可靠记录时，不承诺推断依赖、不扫描文件访问或脚本import；维持现有显式输入路径，必要时报告具体缺口。
- 正式报告的manifest沿已保存的精确生产关联定位。工具产物由原生产Run正式封存记录定位manifest，并核对其中包含准确Ref；不要求后产生的manifest出现在工具产物的父链里。
- 定位后核对Ref/hash。只有定位确切关联时需要来源解析，不在每次读取反复展开父链或增加第二套资格判断；缓存仅为派生加速，不是新权威。
- 多个旧报告的同名alias各自处于原生产作用域。读取接口使用“当前根成果别名＋其内部引用”，控制层解析；Worker不填内部ID或hash。
- 旧正文和原manifest不改写。不做通用历史补登记、不全库迁移、不猜latest。历史引用有准确绑定可读取；缺失、歧义、权限不符分别明确返回，不能因为没有新索引就禁止旧资料显式使用。

## 4. 按需访问的控制边界

这是首版必须明确的合同变化，不能把“按需读取”实现为隐藏修改冻结输入。

1. **创建Run**：只冻结Root显式选择的精确输入、编译合同及读取权限；这些根成果原有的生产关联是不可变定位依据。初始准入沿现有端口/schema/资格/预算规则，不展开所有可达对象，不统一扩容端口。
2. **声明能力**：需要引用读取的Operation在编译工具声明中显式启用范围受限的只读能力，复用统一MCP路由。不向Worker开放全实例搜索或任意Artifact读取。未声明的Operation行为不变。
3. **确定范围**：仅允许声明提取规则产生的引用边：从冻结根成果开始，或从已有成功受控提供收据的对象继续单步选择。每跳保存原根和精确边路径，限定实例/权限和Operation政策；别名只是服务端作用域内的句柄，不能自证授权。内部manifest/source读取仅用于定位。首版仅出现在生产资料目录、没有授权引用边的条目只供导航，仍须Root显式绑定，不能直接读取。
4. **访问留痕**：在现有manifest/工具收据中明确区分“原对象只读访问”与“本Run新产物”，具体责任见下表。原对象读取不调用accept_tool_evidence重登记字节，不改变原Ref/producer，不作为本Run成果发布。只读记录和别名由控制层生成，不改写Run.inputs，不成为新的current/资格事实。
5. **引用输出**：输出来源解析接受已绑定来源和成功受控提供收据所授权的原Ref及locator，复用同一收据解析器，不重新做输入准入或判断模型是否读懂。目录导航、失败/中断以及交付未知记录不扩展可引用来源；局部提供不产生全文已读断言。工具提供的历史资料不能自动满足声明为必需的输入端口、受信证据cohort、审查或执行授权。
6. **新增材料**：另找论文、跨到未被根成果引用的新资料，或需要改变任务科学范围时，仍回Root显式选择并创建新Run；本工具不成为任意补材料通道。
7. **预算**：冻结输入维持已有完整输入预算；按需工具分别限制单文件可接受大小、累计唯一材料字节、请求次数/运行时间、引用索引及返回字节。不能因只返回一行索引就无限访问大原件。沿现有工具IO预算收敛，缺少预算维度时在同一工具合同补齐，不建新预算系统。
8. **超限行为**：保留未展开项和准确入口，说明何种限额阻止本次读取；不静默省略、不自动提升预算。Agent可以缩小读取/报告结论边界，改变Run预算沿既有新调用规则。
9. **重试/恢复**：同名创建保留现有不可变根输入身份。恢复仅继承从本次冻结根仍可验证、当前编译能力允许的成功只读收据；逐边验证精确链，不猜latest，不继承审查/执行资格。根或权限失效的旧记录保留为历史诊断，不开放别名或后续读取。合同身份漂移不偷偷续接旧Run；累计预算与交付未知处理见下文。

### 4.1 单一收据语义与消费者责任

在现有收据结构内增加明确的记录类型，不建立第二套输入表。历史记录保持原有“生产产物”语义，新只读记录必须显式带类型，不能以字段缺失猜测。下表是WP0必须落实的合同，不是Agent新增表单。

| 边界/代码消费者 | 必须落实的行为 |
|---|---|
| 编译工具声明、统一MCP、OperationToolContext | 单独声明引用读取权限、提取规则、请求选择器和预算；已有tool_evidence输出授权不代表读取授权。控制层解析根别名/引用句柄和字段、页或字节选择器，不要求Worker填内部Ref/hash。 |
| tool_evidence中的访问记录与ToolAttempt | 只读记录保留原精确Ref和原生产关联、冻结根、每跳引用边、能力合同身份、当前访问Run/attempt、作用域别名、提供范围和结果状态。原生产Run与当前访问Run分别存储。只读访问不走新产物登记分支。 |
| source_descriptor、evidence_sources、输出来源校验 | 通过同一解析器消费绑定输入、新产物和成功只读记录；别名不能跨作用域。局部来源保留locator；机械验证需要读取完整原件时可内部读取，不投影成Worker获全文，不新增科学充分性或全文阅读拒绝。 |
| manifest、evidence_output_refs、run_outputs及runs发布/生产者查找 | manifest可保留两类记录供追溯，只有新产物进入本Run生产输出集合；只读原件不重发布、不改变completed_for_output认定的原生产关系。 |
| run_assignment、input_reader、状态/CLI/UI投影 | 初始只投影根和有界导航；访问收据不整包塞入后续assignment/status。范围、遗漏、失败和准确入口可按需查询，页面不把访问者标成生产者。 |
| adopt_tool_evidence及恢复来源解析 | 新增只读类型分支验证根和引用链，不能套用原public_web/derived_from/execution_result恢复分支。复用通过验证的来源，不扩大冻结输入或资格。 |

精确schema、默认版本、错误码及上述消费者逐项映射在WP0完成并审查；不以“沿用现有机制”跳过。旧manifest仍可读取；无法安全表示时保留显式绑定路径，不通过workspace偷渡。

### 4.2 提供范围与失败语义

收据证明服务成功提供了什么，不证明模型记忆或科学判断。范围区分目录导航、指定字段/页/字节、完整文件可访问；文件入口不能声称其正文已进入模型。导航成功不生成原件提供收据，服务端读bytes或校验hash也不等于成功向Worker提供原件。

请求分别记录成功、失败、中断，以及已封存结果但客户端交付未知。局部结果只登记实际提供范围及原Ref/locator；失败和中断仅留下诊断，不扩展来源。结果封存与有效来源发布须有原子一致性；交付未知可按同一请求取回原封存结果，成功取回后使用原来源身份，不重登记产物。不能要求模型“确认已读”填表。服务端无法观测传输状态时如实保留未知，不伪造送达。

原件内部访问量与返回量分别计量。预算超限前不得把未返回全文登记为已提供；输出检查只验证所引用Ref/locator及授权收据，不借此判定科学结论是否被局部证据充分支持。

### 4.3 恢复链预算与并发

沿现有工具IO预算账本增加本能力必要维度，预算作用域为声明的恢复链；不是全实例永久预算，也不新增调度状态机。新预算只能通过既有显式预算变更规则授予，恢复不得自动重置。

- 累计唯一材料成本按精确原Ref去重，以完整原件大小计；不同Ref即使hash相同也不合并身份。缩小返回范围仅减少返回量，不能绕过原件限额。
- 同Ref再次读取不重复收唯一材料成本，但实际请求、服务端IO/耗时、实际返回字节仍累计。取回封存响应也计真实调用及返回成本，不重复收生产或唯一原件成本。
- 恢复承接已用额度及未决预留；并发读取在同一预算作用域原子预留，唯一Ref只预留一次，其他额度逐请求预留。完成按实结算，可证明未消耗的部分释放；无法证明的崩溃预留保留至恢复核对，不能借失败无限重试。
- 权限失效的历史来源不再可用，但已发生的成本仍留账。移除根不清空用量；新Run改变根必须重新判断收据可用范围，不能把旧来源当授权跳板。

上述字段与计量口径须在WP0固定，复用一份账本，服务端与客户端不得各自维护一套权威预算。

## 5. 引用索引如何生成

复用现有报告结构中的evidence/source_key/计算记录引用，由对应领域或通用Schema组件声明提取规则；核心不按TCAD/论文名写分支，也不调用LLM抽取引用。

- 结构化直接引用明确：生成精确引用索引，保留原定位信息。
- 只有manifest目录、没有结论对应引用：只能显示“生产资料目录”，不能说它们全部支持当前结论。目录按需分页；仅目录出现不授予读取权限，首版没有声明引用边的条目继续显式绑定。
- 原报告只有自由文本旧路径：不猜绑定；若原生产记录能确切映射则给准确入口，否则标为未解析，允许继续审查现有证据并报告限制。
- 计算记录包含算法版本/输入/参数：选中该记录后才提供该项复算导航；源代码未保存或工具版本不可复现如实报告，不声称已有完整复算包。

不新增Agent必填的“依赖表/引用重复表”。科学结论应引用证据属于原科研职责；同一引用不应在多个字段机械重复。

## 6. 保留并收敛其余根因修复

### A：开发预检、封存和记录生命周期

开发预检只检查源码/声明/能力，不要求最终科学handoff。输出封存检查真实成果/缺口，执行检查精确工程/审查/授权。共享定义，不混用所有阶段的完成条件。

不可变输入与正式成果不允许改写；开发草稿可改；尝试诊断追加；当前派生报告可以更新。修复TCAD材料化连续失败被旧报告挡住的问题；错误首次登记一次，包装层引用而不补空重复事件。模板、帮助和校验表达同一作者输入合同，控制生成字段不再让Agent填写。

### B：设计者获得准确能力边界

从编译目录与领域能力记录投影当前可执行动作、分析计算、开发诊断及尚待验证能力，不新建白名单。作者验证具体实现，计划审查不要求未编写源码先提交运行证据。未知能力与物理机制被否定必须分开，implementation_gap可正常交付和审查。

### C：默认决策视图而非完整对象展开

Root一次读取必要正式结论、限制、矛盾与后续理由；精确请求保存在编排存储。formal payload是科学内容权威，handoff/status按需引用，删除机械重复表达。

服务端限制注册工具返回；native shell/functions.exec不能被虚称为框架硬限额，公共指引和原生行为验收约束连续翻页后统一打印。更换/复用Worker保持目标和原件入口完整，未变材料不机械重读，不能用hash证明模型记忆。

## 8. 验收：证明不会越读越大，也不会丢证据

1. **历史膨胀反例**：报告来自很长父链，创建任务仍只含选中根输入；第一页引用索引有界，不访问全部祖先。
2. **科学审查路径**：Agent选一条结论引用，能读到准确原件；再选择另一报告才逐步深入。控制层不替它挑“支持结论”的证据。
3. **复算路径**：选一项计算记录，准确得到该项算法/输入/参数入口，不加载报告内其他计算；未知版本/缺原数据可定位。
4. **来源安全**：同名alias来自两个报告、同内容不同Ref、错误hash/manifest、其他Run或未封存记录、越实例、无权限均有正反例；无需重复父链证明，但不能仅凭任意manifest hash匹配就授权。
5. **预算和循环**：同Ref唯一材料成本去重，重复返回仍计IO；不同Ref不按hash合并，循环不自动遍历。串行/并发/崩溃恢复均不超预算；目录与后台读取不生成原件提供收据。
6. **冻结与恢复**：读取不改inputs/原Ref/producer，不进入当前Run生产输出。A→B→C在保留根与权限时可恢复，移除A或能力不再许可时旧C仅留历史；额度不重置、审批不继承。字段成功、全文入口、后台读后异常、交付未知和同请求取回分别验收，不产生全文已读断言或重复来源。
7. **免填表**：真实Worker调用记录证明发布不再重复列已知sources、算法和参数；普通shell缺记录不新增依赖填表，也不虚报自动复现。
8. **生命周期**：开发失败A→B→成功，具体错误留存且不重复；合法开发预检不要求科学summary，非法最终成果仍拒绝。
