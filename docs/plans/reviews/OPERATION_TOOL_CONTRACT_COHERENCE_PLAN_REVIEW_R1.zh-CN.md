## 2. 唯一阻断：原恢复清单与 prior_analysis 证明清单的职责冲突

**优先级：P1。计划位置：**§5.2 第 105—109 行，§7.2 第 159—165 行，§8.1 第 205—215 行。

R1 明确了清单自产生、记录为空仍发布、attempt 来源核对及旧别名隔离重放，这些决定有效。但是 §7.2 继续让 TCAD 复用唯一的 recovery_manifest，且规定它必须是 prior_analysis 的同一 producer 的直接封存父件；原文件恢复证明仍依赖最初接收文件的清单。两个身份在连续分析中不会一直相同。

**源码位置与证据：**

- `plugins/tcad_artifact/tcad_artifact/result_analysis.py:73–85`：恢复文件需在恢复清单 parent_refs 中，并要求文件与清单的 tool_producer_run 相同。
- 同文件 `:202–214`、`:239–252`：原恢复来源、声明路径、output_name、案例及字节属性由该清单的 records 提供。仅知道完整 ArtifactRef 和输入端口，不等于已有这份原接收证明。
- 同文件 `:427–429`：现有 recovery_manifest 是单值可选输入。
- `src/scidiscovery/artifact_agent/service/tool_evidence.py:122–147`：新清单的 records 来自本 Run 的接收记录；清单 parent_refs 包含当前输入，tool_producer_run 是当前 Run。§5.2 允许 records 为空但 attempts/bindings 非空，并没有声明将旧接收证明复制或转换为新清单的接收记录。

**可达场景（静态推导）：**

1. 分析 A 从终态执行恢复原文件 F，封存分析 A 和接收清单 MA。
2. 分析 B 显式绑定 A、MA、F，补充案例依据或重新评分；本轮无需再次接收 F，因此封存 MB 时 records 为空、bindings/attempts 非空。
3. 分析 C 要复用 B 的封存映射/尝试，按 §7.2 必须绑定 B 和它自己的 MB；同时仍需 MA 证明 F 的原接收来源。

若 C 绑定 MB，现有来源检查找不到 F 的原接收记录，且 F 的 producer A 与 MB 的 producer B 不同；若改绑定 MA，又不满足 B 与其同生产者父清单配对。MB 把 MA 作为父件，并没有自动授权插件读取未绑定 MA 的字节，也没有规定 MB 可替代 MA 的来源证明。相同冲突也会出现在“上一轮只评分、原文件早已在更早一轮恢复”的现场续接中。

**影响：**R1 可以覆盖恢复后第一次分析，却不能保证所承诺的连续跨 Run 复用。临时绕过 producer 检查、把旧回执改成当前生产者或直接读取未绑定父清单，都会改变已承诺的确切来源/权限边界。

**最小补齐：**明确分开两种输入职责即可，不需要新 Operation：

- 原始产物的 recovery_manifest 继续证明恢复文件及原执行来源；保留既有单清单历史路径。
- prior_analysis 的同生产者证明使用一个独立、可选的清单输入，验证它确实是该分析直接封存的证明父件；用于 bindings/attempts 和来源别名投影。
- 如两种用途引用同一完整 Artifact，复用一次绑定并由明确规则识别两个用途；当前 `operations/invoke.py:165–168` 拒绝同一 Artifact 在不同端口重复绑定，不能要求调度者重复绑定才能走最常见的 A→B 路径。
- 原回执、原工具生产者和分析尝试生产者各自保持原身份。后一轮清单不能把前轮恢复文件伪装为自身接收产物。端口的配对条件、上下文来源及历史重放选用哪份清单应同步写入计划。

**必须补充的验收：**A 恢复→B 不重复接收、只评分/补映射→C 重用 B 证明及 A 原恢复证据，完整经过 preflight、工具和 submit；同时证明 A→B 只有一份清单时不因重复绑定规则受阻。对换 MA/MB、使用不同 producer 或缺失所需原恢复证明应明确拒绝相应复用，诚实有限报告仍能提交。

## 4. 非阻断实施注意事项

- **attempts-only 清单不应扩大字节接收权限。**现有 `operations/tooling.py:265–269`、`operations/catalog.py:466–475` 和 `service/local_workspace.py:108–115` 将附属清单与原 tool_evidence 权限成对判断。R1 已授权修改相关接线并明确“不授权接收任意字节”，实现时应让 record_attempts 只开启控制侧证明清单，不借给评分工具 evidence_ports 来绕过旧判断。验收沿用计划要求的普通 Operation 不退化和权限负控即可，无需新增通用机制。
