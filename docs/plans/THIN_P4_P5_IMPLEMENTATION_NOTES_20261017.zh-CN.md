# P4/P5 最小接线方案

状态：[独立设计审查](evidence/P4_P5_THIN_DESIGN_REVIEW_20261017.zh-CN.md)通过 P4b/P4c1/P5 范围；P4c2 可写恢复未通过、未实施。不授权动态测试或真实计算。P4a 公共浏览凭据原语已独审提交 `002284e`。本文件细化主迁移计划的剩余节点，不新增科研流程。

## P4b：CLI 拥有实例页面

- `scid-research serve-ui --root ...` 只绑定一个明确实例，监听 loopback；端口与 UI 生命周期由命令拥有，不建立旧 session/Root/实例数据库。独立 UI 进程锁不占科研推进锁，科研写操作继续复用现有 `controller._writer`。
- 浏览凭据使用 `scidiscovery.browser_access`。每次服务启动有新 boot identity；管理链接交换成实例 cookie 后跳转到不含凭据的地址。只读与管理权限分开；管理写请求必须同时验证当前实例凭据、CSRF 与精确 Origin/Host。浏览权限不授予执行许可。
- 先提供有界状态和明确节点入口：角色、状态、用量、剩余授权、等待/失败原因。原件不嵌入状态页，完整历史不截断；分页来自同一实例记录，不做第二份 UI 状态投影库。不公开宿主凭据、原生私有聊天或任意本地路径读取入口。
- pause/continue 等操作从现有 CLI 内联分支抽为共享控制函数，CLI 和 UI 调同一实现。耗时推进在后台控制线程执行，HTTP 不持锁等待模型；每个实例服务最多一个进行中的控制请求，不排队。实例写锁仍决定是否可推进，UI 只显示请求结果并刷新权威状态，不维护另一套调度队列。UI 停止不通过 daemon 退出或信号取消已接受控制 owner / 科学工作；原接受工作继续由现有运行生命周期持有。
- P3c 的人工执行授权页面复用同一服务器安全边界，调用唯一授权 owner。P3c 未完成时页面明确显示该能力不可用，不提供能写任意 JSON 的替代入口。
- 负控只围绕真实边界：错实例/过期/重启前凭据、跨 Origin、并发推进、重复暂停、服务停止后 accepted 工作的原恢复路径。当前只编写必要用例并静态审查，不运行 HTTP/浏览器或子进程测试。

## P4c1：完整记录归档与包内只读查看

- 使用同一实例目录作为归档对象。从旧归档实现抽取路径检查、分块 hash/copy、稳定文件检查、原子发布原语到中立模块，旧调用方复用；不导入旧 SQL/Run/CAS 归档 owner。
- 导出取得现有实例写锁并确认无活动原生/执行/交付写者；不能因为取得控制器锁就假设后台子进程停止。无法证明静止时拒绝这次导出，原研究状态不变；发布包前再次核对完整目录清单和文件稳定性。归档不是暂停/取消执行命令。
- 使用目录包和逐行清单流式复制完整文件；不把大型原件拼成内存 JSON，不设隐含文件数/字节截断。显式磁盘配额不足只影响本次归档，不损坏原实例或旧封存。符号链接、特殊文件、越界路径不能静默跟随；包记录完整性及范围缺口。
- 核心实例文件与插件声明拥有的存储分别列范围；外部依赖只按精确冻结引用登记，不递归扫描用户 home、平台缓存或任意工作区。缺少必要外部原件、缺插件、未知所有权时保留归档可读，但不能宣称可恢复推进。
- 本小节点只导出和在包内只读查看；payload 使用归档布局，不发布为可被原 CLI 当作 live 实例读取的 settings/jobs 目录。不覆盖现有实例，不改写旧原件。只读边界不能只依靠隐藏按钮、chmod 或可删除的标记。
- 归档操作不调用 native、submit 或 reconcile，也不授予恢复推进权限。缺少平台 session 或外部执行原件时保持原 unknown，不重新执行。相同绝对路径不证明相同实例 owner，不能据此复制预算/执行身份。
- 不导出临时 UI 浏览凭据作为持久授权。重启服务重新签发浏览凭据；P3c 的科学决定按原件恢复并重新核验，不因解包而扩大预算/权限。
- 负控：导出中原件变化、后台写者、路径/哈希篡改、重复路径、包目标已存在、缺插件或外部源、包不能作为 live 实例启动。当前动态验证未运行，不以代码完成替代恢复资格。

### P4c2：可写恢复仍须独立解决

可写恢复不能凭路径相同或 UI 标记批准，须证明原 owner 独占，并让所有科研/执行/预算写入口共用该身份判定；跨 host/boot 不能猜。未冻结这一方案前，不实现可推进副本或声称 P4 归档恢复已完成。现有原目录跨重启继续由 P2 原调用恢复处理，不等于从副本复制新 owner。
