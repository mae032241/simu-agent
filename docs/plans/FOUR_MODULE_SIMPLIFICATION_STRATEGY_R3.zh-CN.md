## 2. 目标：四个模块承担完整任务

任务以一个可验收的科学问题为单位。一个作者在同一工作区连续完成检查、工具调用、保存、自检和交付；只有科学问题改变、需要独立评审或跨越执行权限边界时才交接。

| 模块 | 作者应连续完成的工作 | 交付与必要边界 |
| --- | --- | --- |
| 证据 | 查阅原件、选取图/数据、标定与提取、保存文件、检查来源和质量 | 封存 Intake 与选定证据族；需要资格判定时交给独立审查。 |
| 假设 | 消化已有证据、比较竞争解释、形成预测和可判别条件 | 提交假设；独立批评保留，修改形成新版本并重新审查。 |
| 实验 | 将科学骨架落实为 deck 和执行计划，在预算内完成语法与数值调试、自检和交付 | 独立综合审查；控制层授权后由适配器执行。科学目标或判据改变时返回设计决策。 |
| 分析 | 读取已收集结果、计算、保存中间产物、绘图、解释与出报告 | 交付结论、局限、剩余矛盾和调度信号；绘图失败复用已有计算，不强制进入调参。 |

四模块是职责划分，可按问题产生多个任务和版本；不要求四个常驻 Agent、恰好四个 Run 或固定串行流程。

- **Root：**维护研究目标，选择下一项科学问题、绑定必要输入、派发完整任务、读取封存结果并决定继续或停止。
- **控制层：**保有不可变身份、来源、Run 生命周期、资格、预算、授权和恢复。作者不能自授资格，独立 reviewer 不能复用作者身份。
- **领域适配器：**落实文件、进程、远端提交、采集和停止等副作用，执行控制层下发的约束。
- 复用现有 Run、Artifact、Worker、tool evidence 和插件注册机制。每合并一条生产路径，同时删除其被替代的公开小步骤、重复提示和胶水；不能只加一个外层总入口。

## 3. 实施顺序与工作包

首批 A、B 没有合同上的相互等待关系，可以分别交付；用户随后要求因 OOM 串行执行，实际按 A→B→C→D 实施与独立审查。C 在所用作者/授权合同稳定后继续；D 根据已经内化的步骤收简 Root。

### A. 图证据：先交付一个完整作者任务

**现状依据：**`figure_science_operations.py` 中仍有 `science.figure.request.prepare.v1` 和 `science.evidence.extract.figure.v2` 两个作者；确定性 materialization、family parentage 和 audit/downstream 各自绑定旧流程。现有 preview 不能直接冒充正式证据族。

**实施内容：**

1. 定义新版作者交付合同：ScientificIntake、显式选定的不可变提取 manifest、原图/请求/算法版本/结果身份及必要质量记录。失败尝试作为恢复记录保留，不能按“最后一次工具调用”猜测最终结果。
2. 在同一作者工作区开放检查、提取、保存和自检；复用现有数字化算法。扩展受控工具证据封存路径，使正式证据文件与 manifest 能被精确回收和引用。
3. 同批修改独立 audit 和 bundle 消费者，使其检查选定证据族的完整性、父链和审查身份；保留缺件、篡改、错绑定、旧审查不能复用的拒绝语义。
4. 同批替换该路径的生产者、消费者和注册声明，删除双作者的旧公开入口及专属字段搬运逻辑。确定性算法可留作内部工具，不再要求 Root 为它派发一次任务。

**范围：**首先闭合当前支持的单个栅格面板路径。仍有实际消费者的 PDF 恢复等能力继续保留到等价路径完成；可选 figure 插件的安装范围保持显式声明。

**主要落点：**`plugins/curve_figure_evidence/curve_figure_evidence/` 下的 `figure_science_operations.py`、`figure_worker_tool.py`、`operation_transforms.py`；core 的 `artifact_agent/operation_tool_context.py`、`artifact_agent/service/tool_evidence.py` 和 `operations/tooling.py`。

**完成条件：**一份受支持的图证据由一个作者任务完整交付，独立审查和下游绑定闭合；Root 无需重建提取参数或再次交给 Intake 作者。新版路径中不存在旧双作者入口，保留能力的消费者有明确归属。

### B. TCAD：配置内自主授权，并落实资源边界

**现状依据：**执行服务和 Root routes 仍以人工批准为授权依据；当前 policy 没有自主执行字段。开发调试存在固定时间/次数额度，runner 有传输大小限制及整文件读取，单文件 `RLIMIT_FSIZE` 不能约束任务总存储。

#### B1. 配置与口径

由管理员配置统一策略，经严格校验后生成不可变 policy 投影及 digest，下发本地和远端。Agent 的任务参数不能提高此配置额度。拟新增配置示例：

```json
{
  "agent_execution_policy": {
    "enabled": true,
    "max_storage_bytes": 2000000000,
    "max_wall_time_seconds": 3600,
    "outside_limits": "require_human_approval"
  }
}
```

- **两项均小于或等于上限**且合同、资格和科学审查有效时，Agent 自行决定执行，不创建人工执行审批、不等待 UI，也不伪造 HumanDecision。2GB 按十进制 2,000,000,000 字节计算，不能混用内存额度或 2GiB。
- 关闭自主授权或超额时按配置进入人工执行审批或拒绝。缺失/非法配置、无法确定预算或能力不足应给出明确诊断，不能静默放行。新配置严格切换，不新增旧配置自动迁移回退。
- 存储按单任务输入、工作目录、中间产物、输出和日志的逻辑文件占用计费；CAS 去重不免除输入计费，同一逻辑文件的传输镜像不重复计费，实际落盘副本另受传输/缓存限制保护。
- 墙钟从求解进程启动至终止计算；排队、作者推理、采集分别使用自己的配置。多 case 共用任务额度；重试、恢复和重新命名不自动重置累计额度，控制层保存稳定的预算归属。
- 调试模式时限、尝试次数、累计调试时限、轮询周期、终止宽限、采集超时、传输分块和日志/manifest/预览限制均有具名配置及消费点。示例默认值可保留，执行路径不能藏有无法配置的另一套阈值。

#### B2. 授权与执行一致

1. 在控制层增加策略授权记录，与现有人工授权共用执行生命周期；记录 exact request、资源预算、policy digest、审查身份及授权来源。核心提供通用机制，TCAD 插件拥有领域限额和判断。
2. preflight 与 invoke 使用同一判断函数；submit 前校验绑定与当前策略，策略收紧时重新判定。已经启动的任务遵守冻结额度，策略变更不扩充其额度。
3. 保留独立科学审查、来源/资格检查和副作用执行边界。UI 能区分“策略授权”和“人工批准”；额度内执行不得通过暗中创建人工 approval 来实现。
4. 提交结果未知时查询原任务，恢复使用原身份和剩余额度，不能重复启动求解器或获得新预算。

#### B3. 本地与远端都实际执行额度

1. 请求阶段做预算准入，runner 阶段监测任务目录总占用和累计时间；超限时按配置停止整个进程树，并保存可诊断的终态和产物清单。
2. 采样监控只报告**观测高水位**、采样间隔和可能超调，不能声称精确瞬时峰值或严格磁盘硬配额。若部署需要硬配额，使用已有部署能力并声明支持范围；不把另造配额基础设施设为本轮前提。
3. 对科学文件采用流式读取、分块传输和 CAS 入库，打通 2GB 预算范围内的交付路径。逐项核对现有传输门槛与整文件读取，禁止把大文件塞进 JSON/base64 或模型上下文。
4. 小 JSON、预览和日志继续有独立可配置上限。不能用放大全部消息限制来替代文件通路；远端不支持所需计量/停止能力时报告不支持，不能假称已获得资格。

**主要落点：**core 的 `operations/`、`artifact_agent/interfaces/mcp_root_execution_routes.py`、`artifact_agent/service/executions.py`、执行 schema 和 UI 授权展示；TCAD 的 `execution_control.py`、`plugin.py`、`execution_adapter.py`、`worker.py`、`remote_runner_py36.py`、`debug_adapter.py`、`local_debug_service.py`、`deploy/configure_runtime.py` 及 `config/` 示例。

**完成条件：**相同有效请求在本地/远端作出一致授权判断；额度内无人工审批依赖，超限/禁用/配置变化有确定结果；runner 可停止并报告超限，恢复不能刷新预算；文件通路与声明额度一致。仅修改 policy JSON 或跳过 approval 检查不算完成。

### C. 实验与分析：连续工作，复用已完成产物

**实验：**沿当前科学骨架、deck 作者、独立综合审查和执行路线收敛。作者内部完成普通语法/初始化/数值调试；执行计划从最终 deck 交付中精确投影，机械投影和打包逐步成为内部命令。审查后修改 deck 或计划须生成新身份并重新满足适用审查，不能用“继续任务”修改已封存对象。

**分析：**当前已有单 Run 内读取、计算、保存、绘图和解释能力，先补实际断点复用与交付缺口。已有计算结果在绘图/报告失败后应可精确恢复；Root 只读取完整结论与剩余问题，避免重新搬运全部原始结果。

**假设：**作者内部合并证据消化、竞争解释和预测整理；保留独立 critic 与修改后的新版本审查。先复用已有 propose/critic/revise 合同，不为了四模块外观另造统一巨型 schema。

**主要落点：**`general_science_experiment_operations.py`、`general_science_agent_operations.py`，TCAD 的 `plugin.py`、`operation_workspace.py`、`result_analysis.py`，curve-score 的 `science_operations.py`、`analysis_workspace.py` 及所用恢复路径。

**删除范围与保留能力：**删除被新作者路径真正替代的机械公开节点、重复 workspace 重建和重复交付字段。SDevice 目前仍使用的详细实验计划路线属于有效能力，不能作为旧格式直接删除；在新路线达到等价支持后再整体切换。

**完成条件：**同一科学问题的局部调试/报告修复不再反复交回 Root；已完成产物可复用；独立审查和实质科学修订仍有明确边界。

### D. 最后收简 Root 与公开合同

根据 A–C 实际交付，移除 Root 中已经内化的参数搬运、机械投影、重复检索和显式小步骤入口；同步 catalog、invoke 合同、scheduler guides、角色提示和中英文当前文档。内部工具有权限和输入合同，但无需全部作为 Root 可派发的 Operation 暴露。

逐项登记删除入口的最后一个消费者；替代后的 producer、consumer、注册和测试同批删除。保留发现合同、精确绑定、状态读取、资格、必要恢复等真实职责，不先写一层新路由包装全部旧流程。

**完成条件：**Root 可按四模块的完整任务推进目标；公开目录无被替代的小节点，提示不再要求旧交接；能从合同和终态解释停止、失败或下一科学决策。

## 4. 验收方法与测试约束

**实施初期用户禁止执行测试；2026-09-25 随后授权受限源码验证，并进一步授权串行、受限的隔离构建安装和短 TCAD，以及远端临时短任务。发生 OOM 中断后，用户将大文件实测改为 512MB，要求该项严禁并发。** 本地安装仅使用当前目录下的临时目录，完成后删除；现有服务不改。已执行范围与结果见[源码验收记录](FOUR_MODULE_R3_SOURCE_ACCEPTANCE_20260925.zh-CN.md)和[最终验收记录](FOUR_MODULE_R3_FINAL_ACCEPTANCE_20260925.zh-CN.md)。512MB 实测使用进程地址空间硬限额、进程树 RSS 和系统内存采样熔断及超时；环境不支持 cgroup 聚合硬限额，不能声称总内存硬隔离或保证不会 OOM。下表保留原分层设计，不构成全套测试、2GB 重测或持久部署授权；静态通过仍不能写成运行通过。

| 层次 | 必要覆盖与执行边界 |
| --- | --- |
| 静态检查（当前可做） | 新旧入口消费者、配置字段定义到消费点、schema/角色/文档一致性、AST、链接和 diff；不加载项目模块。 |
| 源码行为（解除限制后） | A 的完整作者交付、错身份/缺件/旧审查负例；B 的边界相等/超额/配置收紧/策略禁用、累计恢复和幂等提交；C 的产物复用与科学修订边界。复用现存测试，规则矩阵只在所属层测一次。 |
| runner 边界（解除限制后） | 用小配置额度验证真实进程停止、总目录计量、流式采集与恢复；本地与远端分别验证适配器职责，不重复整套科学业务。 |
| 安装与真实执行（单独安排资源后） | 仅覆盖变更实际影响的资源打包/插件发现/协议入口，以及代表性的短 TCAD 闭环。按最新授权，大文件实测为独占 512MB，生产配置的 2GB 自主执行上限不变；512MB 本地 helper 结果不证明 2GB 路径、真实 SSH 传输或真实 solver 能力。 |

不得以测试行数、固定 Operation 数量或源码字符串快照作为成功条件；不恢复已删除的安装业务矩阵，也不自动启动全套测试。待运行验证时记录精确候选、配置、安装态和剩余限制。

## 5. 破坏式切换与完成标准

- 每个工作包按一条完整生产路径交付；新合同、读写方、注册、角色、配置和文档同批切换。已替代旧格式直接删除，不新增 alias、双写或静默字段修复。
- 部署前处理受影响的在途任务，禁止混合 ABI、job wire 或 policy digest 继续执行。回退使用完整旧安装及匹配配置，不在新代码里维持两套语义。
