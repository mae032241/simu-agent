## 本轮范围

落实用户要求的前三项：诊断详情不再挤入短报告；保存原生分析脚本和派生数据；取消 Agent 对计算请求、哈希、结果数组和回执的重复抄写。沿用现有 tool_evidence、Artifact、manifest、Run 恢复和历史输入端口。没有新增评分阶段、状态机、执行审批或数据库迁移，也没有修改 VM runner。

保留进入本轮时已有的工作区修改。本轮精确差异见 [任务差异](ANALYSIS_ARTIFACT_REFERENCES_TASK.diff)，基于开始实现前的文件快照，不把此前未提交开发算作本轮修改。

## 实现后的职责

| 内容 | 处理方式 |
| --- | --- |
| 计算请求、源摘要、数值结果、终态回执 | 工具保存为不可变 calculation_record，返回 calculation_ref |
| 完整残差序列、区段诊断 | 单独保存 calculation_details JSON；短记录引用详情 |
| 叠加曲线与残差图 | 保留 PNG 和可供 native view_image 打开的只读预览 |
| 筛选、加权等原生分析 | Agent 选择方法并生成脚本/数据，用 worker_analysis_publish_files 保存 |
| 科学报告 | 引用 evidence.locator=calculation_ref，说明方法、结论及局限；新调用不填写 calculation_records |
| 参数阶段拒绝 | 引用自动记录的 tool_recovery_manifest，说明实际错误，无需手写失败记录 |
| 后续复用 | 绑定保存的文件、对应历史分析/manifest 和原始来源；控制层解析回执与历史别名 |

提交时读取已保存记录并验证来源和回执，不重新计算、不重新准入输入、不改写 Agent 的科学报告。保存的计算以产物身份区分，两次调用同名无需改名。旧内嵌 calculation_records 和 v1 诊断记录仍可读取。

脚本保存工具只收取本 Run scratch/ 下的普通文件，拒绝越界路径、符号链接和未绑定来源。脚本最多 1 MiB，派生文件最多 16 MiB/项，每次连同脚本最多 32 MiB，并遵守已有集合预算。保存本地文件标明 execution_proof=agent_reported：它保留字节与声明的派生关系，不将保存动作当成程序执行或科学正确性的证明。派生表格可立即供评分/诊断工具读取，后续通过 reference_material 绑定。

诊断详情最多 4 MiB，2–257 点计算网格上限保持不变。旧的单条 32 KiB、报告内嵌记录合计 96 KiB 限制保持不变；完整详情通过独立文件保存，不为适应报告体积而降低采样数。
