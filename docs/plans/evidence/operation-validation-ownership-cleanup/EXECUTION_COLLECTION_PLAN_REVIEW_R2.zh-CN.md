## 跨边界可实施性

1. **同步和收集分工一致。** `execution_status` 保持本地纯读；`execution_sync` 更新观测且不下载；`execution_collect` 显式启动后台工作；`execution_outputs` 沿用语义名称发布。未 collected 的输出不可读仍是有效状态事实，计划要求给出具体诊断，没有把此状态伪装成科学失败。
2. **恢复路径有现有存储基础。** `service/artifacts.py` 先发布并验证 CAS 字节，再登记元数据；`storage/cas.py` 有临时文件、同步及原子发布；`storage/sqlite.py` 在事务中处理幂等记录。计划因此可以在现有机制上补稳定输出清单、collected_at 和执行状态提交恢复，而无需重构存储。源码检查不等于进程终止测试已经通过。
3. **实际预算消费者被纳入。** 当前 `local_debug_service.py:122` 的同步收集、`debug_adapter.py:405` 的结果转换、`output_recovery.py` 的间接 timeout 裁剪均在修订范围内。`runtime_plugin.py` 已从配置构造两种 TCAD 适配器并装配调试/恢复服务，为子进程重新打开所需适配器提供既有路径。计划未要求复制活动连接或传递 Worker 聊天。
4. **本地传输与远端求解没有混淆。** socket 收集读取本地终态描述符；command/SSH 在本地消费预算并监督传输。计划不把本机单调时钟送给 VM，不把客户端超时当服务端停止证明，也不因收集失败再次启动 solver。
5. **维护与科研边界保持。** 现有 StateMaintenanceLock 提供跨进程共享/排他锁，实例关闭本来就拒绝未收集执行。计划要求后台执行覆盖原维护范围，不引入新的科研完成条件。工程错误、收集进度和观测缺失均不进入科学结果必填合同。
