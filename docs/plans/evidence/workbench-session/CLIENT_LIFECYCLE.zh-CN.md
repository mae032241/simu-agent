# 科研客户端在线状态补全（2026-09-15）

基于 `90a7b3a` 的增量修改。本记录更新此前验收中“尚未判断客户端在线状态”的限制。

## 行为和边界

- 实例持久保存研究资料。会话目录只投影在线客户端，保留在线但暂停调度的客户端；不提供历史会话目录。
- MCP 初始化和工具目录读取不登记科研会话；首次实际 Root 工具调用登记。
- stdio proxy 每 20 秒独立发送心跳，不需要 Agent 调用工具或报告在线状态。正常 EOF / SIGTERM 尝试注销；异常失联在最后一次服务端心跳 90 秒后过期。列表在打开或刷新时按在线状态筛选。
- “在线”表示客户端连接存活，不等于 Agent 正在推理或 solver 正在运行。心跳和注销是内部传输消息，不增加模型可见工具，不写科学结果，不触发科研重试。
- 客户端侧报错沿用工程诊断，重复心跳失败每个连续故障期只记一次；控制服务不可达时，正常注销也依靠租约过期兜底。
- 独立客户端 sidecar SQLite 添加 `last_seen` / `disconnected`，旧行没有心跳证据时不列为在线。迁移保留暂停和绑定；不改实例数据库和归档格式。
- 心跳不会解除暂停，不会创建未登记客户端，也不会复活已正常注销的传输。服务端重启后，仍在连接的已登记客户端可通过心跳恢复在线显示。
- 掉线和过期不删除实例、绑定或历史成果。归档继续检查 Run、执行和文件写入等原有保护；正式归档重新检查在线客户端，预览后恢复连接仍阻止归档。

## 补充修订：页面归属与离线记录清理

本段更新前文“离线后保留绑定”的管理行为：自然断开仍保留记录，用户可在会话列表主动执行“清理离线会话”，删除离线客户端行及其临时会话绑定，不删除实例、成果或 Run。心跳过期、正常注销以及无心跳的旧记录都可清理。在线客户端不在删除范围，处于归档/恢复维护中的绑定暂不清理。实例仍可由新的会话通过工作台重新绑定。

首页只提供实例创建和各管理入口，不再承载绑定表单。每个客户端的 `/sessions/{session_key}` 子页面承载实例选择、绑定和切换；页面必须对应 capability 中的会话。`instance_current` 和会话列表都指向该子页面。旧 `/instances?capability=...` 链接仍兼容读取会话页面，原 POST 授权、接管确认和绑定快照检查保留。

双客户端真实 proxy/daemon 测试确认：独立会话标识、独立暂停状态，一个退出并清理后另一个继续心跳。心跳由 proxy 线程发送，模型不参与。测试使用两个 proxy 和一个隔离 daemon，不属于多路测试套件并行。
