交付四项：科学报告语言、Agent 模型、推理强度、现有最大尝试次数的默认配置。模型与推理强度按新 Run 分发，不通过新增角色实现；实例设置只影响后续任务。

本文负责新的执行配置方案。[内容展示修复计划](INSTANCE_RESEARCH_CONTENT_DISPLAY_REPAIR_PLAN.zh-CN.md)继续负责已交付的参数来源和 CSV 展示；其 P3 历史正文翻译仍暂缓。本方案解决新生成报告语言，不翻译历史记录，不替代原展示验收。[用户文本接入计划](USER_TEXT_CONTEXT_INGRESS_PLAN.zh-CN.md)继续负责原始用户补充材料登记；执行配置不作为科学 Artifact 或 user_context 登记。

基线是当前已安装的工作树。HEAD 为 `da220ce31c8cc9f9a60542a018b279e2f331f4c0`，仍有已部署但未提交的工作台与内容展示改动。实施前冻结精确基线，不以 HEAD 差异当成本轮改动，不撤销既有修改。本计划不授权部署、Git 提交、真实 Fig.4 执行或人审决定。

本轮不做：单轮时间预算可调、并发/内存管理、通用资源调度器、自动模型选择、模型价格查询、翻译服务、历史审批入口修复、权限修改、删除历史记录。保存配置不启动 Agent、审批或仿真。

- [Root 调用](../../src/scidiscovery/artifact_agent/interfaces/mcp_root.py)已经提供 `max_attempts`；省略时恢复链继承以前预算，不能被新增实例默认值悄悄覆盖。
- [平台文件管理](../../src/scidiscovery/platforms/common.py)已清理废弃的受管角色文件，但并不等于销毁平台 Agent 会话。当前暴露的 interrupt 工具仅中断，不能当成关闭/回收。

官方说明允许 spawn 显式模型/推理参数，但自定义角色文件中的同名设置优先，见 [Codex Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)。这是实施依据，不代替当前安装版本的实际验证。

## 3. 配置形状、所有权与优先级

### P1：一个解析器、两处存储

新增一个小型纯解析模块，建议 `src/scidiscovery/agent_execution_settings.py`，集中定义允许字段、默认值合并和有效配置结构，不建立新插件注册表。

全局文件建议 `${SCID_CONFIG_ROOT}/agent-settings.json`；由安装器首次创建，升级保留用户内容。示意结构如下，属于拟实现格式：

```json
{
  "schema_version": 1,
  "defaults": {
    "narrative_language": "zh-CN",
    "model": "gpt-5.6-sol",
    "reasoning_effort": "medium"
  },
  "operations": {}
}
```

`operations` 以现有稳定 Operation ID 为键，可逐字段覆盖 model、reasoning_effort、max_attempts。不按带摘要的 agent_type 配置，不另建“设计者→多个 Operation”的隐式角色映射。语言第一版只提供实例统一值，避免同一研究报告语言混杂。全局 `defaults` 也可选填 max_attempts；缺省仍沿用原 Operation 策略。

实例覆盖使用相同形状的稀疏字段，存入现有 scheduler 数据库，优先给 `scheduler_instances` 增加 nullable 配置 JSON 与整数修订号，避免新增数据库、后台服务或配置历史系统。保存时间随记录保存。不存在的字段表示继承，清除覆盖表示恢复继承，不使用 null 同时表示多个意思。

普通配置优先级逐字段为：实例 Operation 覆盖 > 实例默认 > 全局 Operation 覆盖 > 全局默认 > 原 Operation 模型默认/已定义的适配默认。全局缺文件时明确走兼容默认；存在但格式错误时报告具体文件/字段，不悄悄回退。推理强度需要确定值，不再无意继承 Root 的偏好；实际模型支持范围以 P0 验证的适配能力为准。

max_attempts 独立沿用原恢复语义：本次显式调用值 > 恢复来源已有调度预算 > 实例/全局默认 > 原 Operation 默认。非恢复的新 Run 才自然采用最新实例默认；恢复链预算变更仍通过现有显式参数表达，不自动加次数。页面标注“恢复链 Run 总数，包含首轮”，不是单次工具调用重试次数。

配置加载时只检查字段名、类型、正整数次数、已支持语言值及推理枚举；Operation 选择来自当前 catalog。停用插件的既有覆盖保留但不生效并显示原因，不让它阻断其他任务。不要维护第二份长期硬编码模型列表；模型不可用或组合不支持时保留平台原始错误及位置。不要替换成其他模型伪装成功。

全局文件作为启动时默认快照加载，修改该文件后重启服务生效；实例设置写入后供后续预检使用，不需重新生成角色或重启服务。页面分别标出这两种生效方式。首次安装/升级生成文件的行为必须在安装说明中明确，新配置不能直接改写历史任务。

## 4. 配置进入 Run 与分发

### P2：冻结执行参数，避免配置漂移

1. 在现有 Agent 预检/调用服务共同入口解析配置。科学 ports、parameters 和 validator 不接收配置；不借用空科学 parameters 字段承载运行偏好。
2. 给 Root 的 Operation 调用增加一个可选、明确命名的控制参数 `execution_profile`（模型、推理强度、报告语言三项完整有效值）。预检返回控制层生成的紧凑标准调用参数，其中包含解析后的 execution_profile 和现有 max_attempts；调度方原样复用该请求调用 invoke，不要求人工搬运。
3. 预检时未指定 profile 才读取当前默认值；已给定完整 profile 时按该快照检查执行配置，不因页面后来修改而替换。正常交互链必须把预检返回的标准请求用于 invoke。兼容旧直接调用仍可省略，但其采用调用时配置，不得宣称使用了此前另一份预检授权。
4. 不引入有状态预检票据或第二个配置注册中心。共享解析器负责 preflight、invoke、Run 入库的同一结果；控制参数不会授权新工具或放宽独立审查与执行审批。
5. 新 Run 增加 nullable `execution_profile_json`，保存三项有效值及配置来源说明；max_attempts 的权威仍是既有恢复策略，不能存两份可独立修改的预算。配置三项行为值进入新请求指纹；来源说明本身不制造重复任务。相同名称、相同完整请求幂等，改模型/语言需有意创建新 Run 修订。
6. `operation_invoke` 的调度返回、紧凑 `run_status` 和 UI Run 元数据从这一份快照投影。Root 直接取得 agent_type、model、reasoning_effort；不复制完整全局配置或各角色配置表。
7. Worker assignment/紧凑任务入口仅追加本轮报告语言要求：新生成目标说明、summary、结论、理由、局限和建议使用该语言。字段/枚举、标识、公式、代码、单位、原文引述、要求精确复制的目标与历史段落保持原样。机械摘要继续引用现有正式摘要，不增加 summary_zh 或另一份科学报告。

控制层不翻译原文、不生成科学叙述。输出校验不检查语言，不因执行配置与最新实例设置不同而拒绝已完成成果。

### P3：保留编译角色，分发时设置模型

- `platforms/codex.py` 生成的 Agent 配置不固定 model/effort；保留提示词、工具、权限与 Worker MCP 路由。相应安装核对检查新的生成约定，不再要求 profile.model 等于编译模型。
- 第一版保留 `ExecutorRef.model` 和 permission 中的旧值作为**兼容默认**，不从旧摘要算法删除它，也不对每个实例重编译 Operation。执行覆盖只进入 Run，不反写该默认。仅调整模型设置时，同一安装版本的 Operation digest、agent_type、Worker 名称和角色文件数量不变。
- 目录里原 executor.model 明确标成 Operation 默认，不能继续宣称是“本 Run 实际模型”。从 Run 调度返回取生效值；所有消费默认模型的已有位置逐一核对，避免两个权威。必要的目录说明变化单列，不借此改科学 Schema。
- 在生成的调度说明中要求 `spawn_agent(agent_type=返回角色, model=本轮模型, reasoning_effort=本轮强度, fork_turns="none")`。字段名称按 P0 实际接口适配；不改用通用角色绕开 Worker 权限。
- 复用要求编译角色和模型/推理配置均匹配且不违反独立审查规则。语言变化由新 assignment 读取，不必单为语言新建 Agent。旧 Agent 的实际配置未知时不声称匹配，不用聊天记忆代替输入。
- 新 Agent 不等于新 role。平台关闭能力可用时才释放闲置 Agent；当前只有 interrupt 时明确记为“不再复用”，不能报告已销毁。第一版不实现自己的进程池、回收调度器，也不无界反复 spawn。平台容量用尽时报告分发容量问题，不能转换成科学提交失败。
- 运行参数是调度请求事实；只有获得平台可观察信息时才能标注“实际模型已核对”，否则显示“请求配置”。不伪造运行遥测，不要求 Worker 填写模型自证表。

## 5. 实例管理页面

### P4：可读配置表单，不展示大段 JSON

沿用现有服务、端口、实例入口和权限。实例管理页新增“Agent 设置”：

1. 顶部显示科学报告语言、默认模型、推理强度及默认尝试次数；每项显示有效值及来源。
2. “按任务类型覆盖”默认折叠，列表来自已编译的 Agent Operations，显示用途与稳定 ID；只展开用户选择的项，不默认铺开所有角色。保留技术名称，不引入翻译 Operation。
3. 保存、清除单项覆盖、恢复实例默认继承；提交前展示这次变更和“仅影响后续任务”。恢复默认也只操作实例覆盖，不写全局文件。
4. 使用既有实例管理权限、同源与 CSRF 保护；普通浏览权限只能查看。更改设置不是人审决定，不提供自动批准。保存不改变会话绑定。
5. 后端以配置修订号进行并发更新比较，旧页面保存冲突时显示“设置已更新，请刷新”，不覆盖别人修改；保存和归档互斥使用现有维护边界。活动实例可保存后续配置，正在执行的 Run 不改；归档实例只读。
6. 文件/字段错误、权限错误、配置冲突、分发错误各自在对应位置显示，不包装成科学合同失败。不增加“确认每项设置”的登记表。

## 6. 历史、恢复、归档与部署

### P5：兼容与生效边界

- 新增列允许空值；历史 Run 无 profile 时显示“历史未单独记录”，不拿当前配置回填。旧成果、引用、资格、审查和 approval subject 字节不变。
- 普通恢复省略 profile 时先采用来源 Run 已保存 profile；旧 Run 没记录才使用明确的兼容默认并标注来源。主动改变模型/语言可创建新 Run，沿用原 draft_from/resume_from 的输入、草稿和预算检查；不因模型变化丢弃可用工作，也不把旧 Agent 配置当新配置。配置变化影响 Agent 复用，不自动否定科学输入资格。
- queued/running Run 已冻结 profile，实例设置更新不重新计算；提交只按原 Run 合同执行。服务重启读取已保存 profile。新配置不得通过更新同名 Run 覆盖旧结果。
- 归档导出/恢复覆盖 scheduler 实例配置与 Run profile；旧档缺新增列按默认读取。缓存清理不删除执行配置，恢复实例后保留覆盖。导入旧档到新 schema 需实际测试，不能只验证新档循环。
- 安装器仅首次创建全局配置，不覆盖用户定制；为控制服务/UI 增加同一配置路径，Worker 从 assignment 获得本轮值，不各自重读全局文件。更新两种 Worker 后端的 assignment 消费路径。
- 首次部署需要安装、重新生成角色配置并重新加载 Codex，使原固定模型配置退出。此后实例修改模型/语言无需新 role。部署前妥善结束当前活动任务，备份数据库和配置；回滚用匹配的代码、生成配置及数据库备份，不许旧代码静默读取不兼容的新归档。
- VM runner、TCAD 执行参数与许可证不变，本轮无需同步 VM。

## 8. P6 验收矩阵与资源约束

| 场景 | 必须证明 |
|---|---|
| 两实例、同一 Operation、不同模型/强度 | 使用同一 agent_type/Worker 路由；各自实际配置生效且隔离 |
| 预检后页面改设置 | 原标准请求仍执行原快照；下一次新请求使用新值；幂等不混淆 |
| 运行中改配置并提交 | 当前 Run 正常按旧快照封存，不因最新设置拒绝 |
| 中文新报告 | 语言从 assignment 到正式摘要及页面；引用、单位与复制字段不变；英文历史不改 |
| 重试与复用 | 显式次数/来源预算优先级正确；同配置可复用，异配置不误复用；无自发预算扩张 |
| 历史兼容 | 旧 Run 可读、草稿可用；原资格与审批不因新配置失效；旧档恢复通过 |
| UI | 只读者不能保存、跨实例拒绝、过时表单冲突；有效值/来源清楚，手机无整页溢出 |
| 升级与清理 | 默认文件不覆盖用户值；缓存清理不删配置；多次改设置后受管 role 数量与编译 Agent Operations 数量一致 |
| 故障诊断 | 无效配置在配置阶段定位，平台拒绝保留原错误；未确认的实际模型明确标记，不伪装科学失败 |
