# 设置与归档入口拆分（已完成，生产页面验收通过）

用户反馈：设置不应通过“资料整理与归档”入口取得权限。此前浏览或绑定只发 read grant，新设置页却复用 maintenance grant；合并页面让用户误认为配置需要先归档，笼统只读提示也混淆原因。

本轮仅改四个 UI 模块与一个所属测试文件，精确前后散列见 BASELINE.json / CANDIDATE.json、差异见 CHANGE.patch。前轮执行配置源码审查证据保持原样，不将本轮新 UI 差异算作已由前轮复审覆盖。

- 实例列表有独立 Agent 设置与资料整理/归档入口，前者按现有授权交换进入 /settings，后者进入 /manage。
- 管理权限、CSRF、Origin、绑定和归档确认机制保留，不新增权限类型或控制状态。点击入口本身不启动科学工作或归档。
- 归档页移除配置表单；保存配置回到设置页，保留当前选中的 Operation。
- 只读原因分别显示：缺权限、归档、关闭或维护，提供返回实例管理入口。

定向回归30项通过，新增入口测试修正两个测试自身问题后通过（management_cookie 缺 max_age；未请求归档预览时不应期待确认表单）。原失败日志保留。实际安装包 Chromium 经“实例目录→设置授权→编辑→保存”通过，无 JS/HTTP 错误，412px 页面无横向溢出；两次 POST Origin 均有效，没有预先发放实例管理 cookie 冒充入口通过。参见 browser.json/BROWSER_RESULT.json 与截图。
