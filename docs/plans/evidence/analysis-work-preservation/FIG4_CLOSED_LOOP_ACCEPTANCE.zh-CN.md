## 完成标准

本轮必须同时交付有证据支撑的 Fig.4 仿真结论和可追溯的故障定位记录。
拟合成功、部分还原、在当前模型与证据范围内无法达成目标，均可成为明确结论；
必须说明适用条件、实际差距及证据边界。框架中断、程序返回成功、一次部分报告封存，
均不能单独证明科学闭环完成。“未找到可行参数”不能自动推广为所有模型都无法解释。

科学结论由受控分析角色形成并封存，Root 只汇总 completed Run 的正式输出及其交接。
沿用原研究目标，重点回答下列问题；量化方法、区域划分和不确定性处理由科学 Agent 依据材料选择：

| 结论对象 | 必须给出的证据与判断 |
| --- | --- |
| 掺杂深度 | 说明比较的深度特征、单位、参考证据和模拟结果；区分原始坐标偏差与对齐后残差，不能用平移隐藏物理深度差异。 |
| 曲线形状 | 给出可检查的叠图及相应数值依据，解释过渡区、斜率或变化点等与本目标相关的差异；采用哪些指标及其局限由分析者判断。 |
| 前部、尾部平台 | 分别说明平台区间、浓度水平及一致性，记录覆盖不足、截断或参考提取不确定性，不能只用全曲线平均误差概括。 |
| 可解释性与剩余困难 | 列出已检验的条件、参数/模型范围和敏感性证据，区分支持、反驳和仍无法判定的判断，解释未覆盖项是否影响总结论。 |

decade 误差可作辅助，不能凭未经来源支持的 0.15 decade 等阈值决定通过。
数值比较不能替代对图像、坐标、平台区和曲线身份的核对；绘图故障不应使已完成数值分析丢失。
若关键图表或数据不可取得，必须说明其对具体判断的影响，不能以一个无解释的 inconclusive 收尾。

最终科学交付应能追溯到确切的论文/图证、执行计划与匹配审查、实际执行与原始产物、
分析脚本和数值文件。图表、残差及敏感性材料按科学需要交付，不要求 Agent 重复手填控制层已有身份。
修改实验需要相应审查和执行审批；审查只使用目录中实际声明的边和可准入操作。
分析条目没有结论审查边时如实记录，不能把同一作者自检、计划审查或另一份分析称为独立结论审查。

## 全过程错误账本

复用现有工具返回、Run 诊断、原生命令日志、恢复覆盖记录及安装摘要建立账本，
由调度/工程侧记录机械事实，不要求科学 Agent 为此填写新科学合同。
每次事件保存：时间与实际版本、具体 Run/操作及失败动作、原始错误码和诊断出处、
具体端口/字段/文件或调用位置、已证实原因及未决项、受影响的成果、采取的修复与复测证据。
只保存定位所需内容，不传播凭据、隐藏推理或失败草稿中的科学结论。

必须分别记录 preflight/invoke 拒绝、工具参数或发布失败、成果提交拒绝、原生异常、
Run/子进程超时以及日志不可见；不能全部归为“校验失败”或 checker_failure。
科学审查成功提交的 revise/negative 另列为科学判断，不计作框架拒绝。

超时应区分任务预算、子进程时限和传输等待，并记录可取得的起止、退出码、最后活动及日志覆盖。
无日志时沿“是否产生→是否捕获→是否保存→是否通过接口展示→是否交付给下一角色”定位断点。
原始日志确已丢失时，定位丢失环节与可证明的边界，明确底层异常无法追溯；
不能把空摘要当作没有错误，也不能伪造完整因果链。
