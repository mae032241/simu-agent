# F1a 只读线程观察与恢复计量：源码节点

日期：2026-10-10。基准：dev `4788f27`，最终关联回归期间 HEAD 为 `df2f9a3`。状态：源码语义独立审查通过；原生容量退出条件仍未关闭。

## 改动

- 轮换检查不再 resume 已完成的历史线程。先检查活动任务；仅检查当前 AppServer 已加载的相关身份及 runtime status，保留历史计量和谱系。
- 单连接内的临时扫描按初始分页清单、元数据、第二遍清单分批推进；每次探测受 RPC 上限约束。pending 时继续预算、截止及控制检查，不启动新的 Root 回合。
- 连接、原生生命周期、当前实例绑定或控制代次变化使扫描失效；锁内重验当前权限、预算、host 证明和各身份。空子线程集合也必须复验证明，同一 probe 不重复执行扫描预算。
- 断线后保留累计值，单独标记 `recovery_usage_unconfirmed`，包括当前及退休 Root、断线期间已封存的 owner、终态 helper。完整且不回退的新累计观测可补算差值并清该恢复标记，不能清洗既有 sticky 计量缺口。
- 严格预算在覆盖不足时拒绝新增工作，已接受工作的收集、心跳和终态处理仍可继续。终态线程不会为了补计量而被恢复。

## 明确限制

本地 Codex 0.160 的 Thread read/resume 不提供 token usage，usage 通知也没有最终值标志或与 completed 事件的顺序保证。旧 observed 与 terminal 记录不能组成可靠的最终计量证明。

因此，没有重新观测累计值通道的终态历史线程保留 partial；本节点**不提供无条件 strict 重启后新增派发资格**，不自动放宽预算。扫描证明只适用于当前 AppServer 的受控入口，不扩展到其他 AppServer 或任意外部原生调用。

无模型协议及模拟进程不能证明实际 slot 回收。F1a 的原生容量退出条件仍 OPEN，留待 F4 的真实 cov 场观察；没有恢复已停止的 o4，也没有新增非 cov 模型场次。
