# 下一步第一优先级：缩减续接内容与准备成本

用户已明确指定；本轮先完成预算控制与 Fig.4 闭环，不顺带实施上下文重构。

本轮观测基线来自 ../analysis-work-preservation/fig4-closure-1-preparation.json 及现场记录：

- 首次原生计算距 Run 创建约 6 分 17 秒，其中约 29 秒为分派/打开、约 3 分钟为阅读和组织输入，
  其余包括准备修改及只读副本返工，不能全部称为“读取耗时”。
- 读取返回约 242749 字节工具文本（包含重复/包装，非净上下文或 token 数），3 次返回截断。
- 单次文件读取通常 0.1—0.2 秒；模型处理、生成与平台等待无法由这些日志精确拆分。
- cp 保留输入 0400 权限，造成第一次补丁失败，再 chmod 并重新发出约 11 KB 补丁，浪费约 80 秒。
- 读取范围包含 assignment、合同、原计划/进度、恢复覆盖、源码与结果。应保留可追溯性，避免默认重复全读。

优化目标：新 Agent 不继承聊天，也能迅速辨认当前剩余工作、可复用结果、实际失败与完成条件；
精简入口必须能追查完整原记录，工作副本应可直接继续修改。完成过的数值计算不会因补图或环境问题再做。
以首次有效动作时间、重复读取量、截断次数、准备失败和无效重算衡量；角色数、重试次数不是优化成果。
下一轮先针对本次实际数据形成最小方案，再验证，当前未声称这些优化已实现。
