## 恢复原则

- 已完成且有效的科学审计不合格，才作为科学拒绝；审计跳过、结果不完整不算通过。
- 控制层能修复的路径、复制、引用和提交确认由控制层处理。
- 原线程的已知异常可以续接；已封存节点不改写。修改候选内容必须形成新候选，不能继承旧审计或授权。
- 未知提交、取消未确认或回执冲突先核对事实；不能自动重复外部副作用。
- 修复消耗原有预算，次数持久化；不自动扩额。达到恢复边界时留下可恢复状态及明确诊断。
- 日志计量只是可观测下界：单次模型请求尚未返回或日志不可见时，不能声称完整实时用量。

## 验收与后续

每线按“实现→独立审查→必要回归→git节点”推进。集成再检查安装入口，避免只测源码。独立评审重点是副作用幂等、预算不重置、状态不伪成功及角色配置一致性。

本轮先完成开发和无模型验收，不自动启动新收费场次。真实验收须冻结新安装产物、模型配置和场次预算；正常链路通过与故障注入恢复分开记录。科学选择质量、泛化性和不同模型的因果比较仍是独立未解决项。

### R1/R2 最小实现边界（已实现并独审通过，安装测试通过）

- 复用已注册 `local_execution:command`、受管实验 CLI 与原始调用记录，不新增平行执行台账。
- prepare 冻结 local/external 选择。标准 Codex 入口默认 local；既有自定义 launcher 保留 external 兼容，可显式选择 local。外部适配器配置不被默认值抢写；旧场不重解释。
- 明确选择的实验目录形成有界输入快照，执行绑定 argv/cwd/参数。目录外运行环境不宣称已冻结。结果 JSON 的指标/成果由科学代码产生，哈希、登记、归档由控制负责。
- 没有 search/breadth 的本地调用仍形成完整受管事实，但不虚构机制归属或计入科学覆盖机会。
- 执行成功、结果采集成功、科学资格分别记录；非有限指标、缺文件、坏JSON、路径逃逸不能静默通过。
- A 接收小型结果概览和封存成果读取入口。普通计算不自动升级成排名候选；指标缺评价口径/方向时不比较。
- 本地交付指精确成果封存和导出，复用 `exported_unsubmitted`。未配置外部提交/审计时不伪造 confirmed 或审计通过。
