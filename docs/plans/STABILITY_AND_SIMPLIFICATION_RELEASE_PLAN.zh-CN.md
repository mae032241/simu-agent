## 1. 发布目标与文档归属

本文件拥有[总路线](SCIENTIFIC_CONTINUATION_AND_SIMPLIFICATION_PLAN.zh-CN.md) P0、P1 和 P4 基础精简的详细实施计划。
[B 版](AUTONOMOUS_RESEARCH_RELEASE_PLAN.zh-CN.md)负责自主推进，
[C 版](RESEARCH_DELIVERY_EXPERIENCE_RELEASE_PLAN.zh-CN.md)负责增强交付体验。
A 可以独立发布：现有交互研究不依赖后台 Root，也应更稳定、入口更简洁、问题更容易定位。

完成标准：

- 必要科学字段的合同、实际填写表单和校验一致；机械身份、绑定、预算字段不要求 Agent 填写。
- 精确输入、用途限制、阶段交付、附件封存、下游消费及 UI 读取贯穿同一对象身份。
- 系统故障有明确诊断；未知提交先查回，不能靠重新命名或重新执行解决。
- 收敛重复上下文、诊断与基础用量处理，为 B 提供可直接复用的能力。
- 退役 hardened 专属执行实现，保留共享协议、原生权限和历史证据读取。
- 精简有实际调用者证据，不用减少行数代替功能验收。

保留插件平台、Operation 编译器、catalog ABI、版本化 Schema、不可变证据和确切审查绑定。
不实施后台循环、全面合并数据库、安装器整体改写或 OS 强隔离；[SEC-002](../../SECURITY.md)保持独立未关闭事项。

- [ ] 沿 Agent、Transform、Approval 路径检查确切引用，修复按名称重新解析导致身份丢失的剩余情况。
- [ ] 检查 scientific_files/materials 的用途限制传播：探索和诊断仍可使用，主张证据资格不能通过派生附件洗掉。
- [ ] 核对自主附件登记、封装、阶段交付、最终封存与下游/UI 消费；已被当前修订解决的项只补缺失的组合验证。
- [ ] 对缺配置、连接失败、执行前拒绝、发送后结果未知分层诊断，保留安全的修复责任和接续入口。
- [ ] 仅对能够确认尚未发送的连接失败使用有上限退避；其余先查原身份，不盲重发。
- [ ] 配置、运行资格、文件额度及超时解释同源；不把临时测试参数硬编码成新的产品限制。
- [ ] hardened 不可用的 chunked patch 等专属选项在 A4 整体退役，不先修一套随即删除的实现。

**删改：**被统一处理替代的按名称查回、宽泛错误包装、重复附件特判和无效合同选项。
**验收：**原件 → 完整任务 → 可选精确审查 → 转换/附件 → 后续消费 → UI 的组合路径；同名不同对象、受限来源、附加文件和提交未知负例。
**Git 节点：**输入/交付一致性与明确故障恢复；未涉改动的既有修复不重复提交。

### A2：统一科学合同、启动材料与决策投影

**依赖：A1。所有权：现有 Operation 声明、表单生成、worker_start、run_status 和输出投影。**

- [ ] 为当前生产合同建立声明 → Agent 表单 → 校验 → 封装的对应关系；缺规则不能靠试错提交补齐。
- [ ] 科学字段的类型、必填/条件必填、含义和限制完整可见；输出表单不等于控制层完整输出 Schema。
- [ ] 从 Root/Worker 的默认视图、表单、修复建议和启动文件中去掉内部端口、绑定、租约和凭据。
- [ ] Worker 保持一个启动入口，助手只拿完成子问题所需的新上下文；保留声明的原生能力。
- [ ] Root 默认只读目标、变化、相关结论、限制、证据入口与阻塞；详细合同按需完整读取并按版本复用。
- [ ] 分页、省略、未知和条件字段有明确说明与读取方式；精简不静默截断重要科学内容。
- [ ] 输出摘要和 UI 基础读取复用同一语义来源，覆盖 checks/evidence 等实际输出形态，不只找固定 summary 字段。

**删改：**重复指南、重复 Schema 副本、各端独立拼装的同义摘要和机械字段提示；不新增 Agent 正常必读 MD。
**验收：**全部当前生产表单的静态对应检查，加代表性真实 Worker 填写与封存；没有隐藏必要规则或新机械填表要求。
**Git 节点：**科学表单与精简材料统一；对外合同有变化时按既有 ABI 规则处理，不维护旧格式执行分支。

### A3：统一安全诊断、只读健康与基础用量

**依赖：A1、A2。所有权：现有 diagnostics、插件运行 API、观测与配置模块。**

- [ ] 公共错误表达故障层、是否可重试、责任方和恢复条件；工程详情通过授权入口按需读取。
- [ ] 插件提供声明式只读探针，核心汇总配置、连接和能力可用性；不因健康查询提交/收集/取消作业。
- [ ] 探针有配置化频率、超时和总预算；成功只证明该探针范围，不推导科学执行必定成功。
- [ ] 采集实际请求/快照身份下的输入、缓存输入、输出、时间和回包体积；累计转增量，重复观察去重。
- [ ] 关联 Root、负责人、助手及失败请求；不能归属的保留未归属/缺测，不制造调用数或 Token。
- [ ] 账本不保存原始对话和秘密；已有观测入口复用，不要求 Agent 回填消耗。
- [ ] 明确交给 B 的用量读取接口与缺测语义；A 不实现第二套目标循环或预算调度器。

**删改：**重复错误分类、监控脚本和指标换算；只在新入口覆盖实际消费者后删除旧实现。
**验收：**重复快照、累计回退/新会话、失败请求、助手和缺测；错误不泄露隐私，探针没有外部写入。
**Git 节点：**统一诊断/观测与对 B 的稳定接缝；缺实时 Token 时明确能力限制。

### A4：退役 hardened 专属执行路径

- [ ] 历史 Run、Artifact 和实例归档仍能读取；历史 backend 标识仅解释历史，不重新启用旧执行入口。
- [ ] 旧 hardened 配置在切换服务前明确拒绝并给出迁移说明，不能静默降级到权限更宽的 local。
- [ ] 替换仅证明已删除后端存在的测试；将有效的生命周期、错误和文件安全不变量迁到保留路径。
- [ ] 同步安装文档与能力声明；不把删除不可用后端宣传为实现强隔离。

**交付与验收：**保留路径可执行当前任务；动态入口不再指向旧模块；历史样本可读；旧配置失败不破坏现有服务。
**Git 节点：**hardened 退役及配置迁移。回滚必须核对配置和在途任务，不能把新候选的任务交给旧后端猜测恢复。
