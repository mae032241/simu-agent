# 最小支撑集与低开销调度改进计划

日期：2026-10-08；基线：dev `9b5c272` / s27。状态：既有计划修订（含 M0 历史真实延迟）独立审查 PASS；M0 已完成并独立审查 PASS；D0/D1 职责补充独立增量审查 PASS；M3a 实现、定向验证与独立复审 PASS；M3b-1 分拆设计独立复审 PASS，a 实施中。计划通过不代表实现或运行验收通过。

本计划拥有交接工作集、按需读取、机械交付和 Root 调度开销修订。
[探索与收口计划](SCIENTIFIC_EXPLORATION_AND_CLOSEOUT_PLAN.zh-CN.md)继续拥有科学角色职责、E5b 计数和 E6 行为标准。
本计划是下一次真实试验的前置项；不另建 Agent 引擎、记忆库或数据库，不把全文放进启动材料。

## 1. 问题与目标

s27：30 次实验，约 1800 万累计 token，75.9 万非缓存输入，13.2 万输出，峰值输入 11.4 万。
Root 约 74 次用量增长、平均输入 5.48 万；W/A 多次读取启动文件、输出结构、历史和原件。
用量增长不等于严格账单请求数；工具返回序列化字节不等于 token，读取次数不等于无意义重复次数。
现有 compact/分页限制了单次返回，却没有组织完成当前决策所需的材料；新角色反复重建工作集。

目标：保留 H–W–A、独立科学判断、精确来源和状态恢复，减少重复拼装、全面重验、机械往返。
用户认可同等条件下约原生三倍总 token 作为成本目标；历史 s11 的 207 万不能充当同期统计结论。
不通过降低总预算、截断必要证据或取消分析，制造省 token 的表象。
本计划直接验收效率和工程可靠性，不承诺隐藏分数提高；科学质量与角色决策由主计划单独验收。
证据边界：250–360KB 等统计是角色全程工具返回序列化量，启动占比由 M0 另测；
s26/s27 的 run17 是不同模型，不能据两场结果断言“精修导致退化”。H1 已提出目标条件机制，
真实缺口是持续暂缓与选择依据冲突没有推动充分纠偏，不是完全没提出机制。

## 2. 最小支撑集：内容与职责

“最小”指当前任务足够且针对性强，不声称算法能求得数学最小集。

| 内容 | 谁负责 | 默认交付 |
|---|---|---|
| 当前问题及可改变的决定 | 上游科学负责人，首次 H 依据原始目标 | 一段明确问题，不复制全部历史 |
| 目标与边界 | 原始用户来源、当前 H；控制层精确绑定 | 必要目标、限制、条件和来源等级；原文入口始终存在 |
| 本轮变化与未解矛盾 | 科学负责人 | 观察、结论、限制、下一步依据；区分报告与独立验证 |
| 结果概览 | 控制层汇总控制回执、声明范围内自动采集记录及作者关联，不依赖作者逐项挑选 | 本轮全部尝试的状态/已有指标/候选身份/失败与缺失；长历史提供覆盖统计及完整分页索引 |
| 主张的支撑和反对证据 | 科学负责人选择；控制层解析 | 精确片段与主张绑定；作者所选材料不是全部证据，也不作为独立评价 |
| 已有核验 | 控制层记录机械事实；A 标明科学核验范围 | 内容/接口/执行检查与科学判断分开，不继承不存在的资格 |
| 补读入口 | 控制层 | 名称、内容类别、大小、适用问题、精确原件定位；默认不展开 |

复用 RoleHandoff、payload 中现有 evidence/source references、boundary_references 和阶段材料。
M1 先证明现有字段能否表达“主张—直接证据—相关片段”；只有真实消费者缺口才增最小可选字段。
不要求 Worker 填 Artifact ID、哈希、端口、路径、完整来源图或全历史摘要；不设字段齐全才可研究的 gate。
控制层做确定性组装/去重/提取，不替科学负责人总结、选择结论或自动认证支撑充分性。
未知、缺失与省略显式展示；不能把摘要里没提到解释为约束不存在。

不同角色使用同一组装规则、不同任务投影：
- H：原始目标、主要矛盾、已有机制/失败边界、A 请求修订的依据。首次入口可先提取证据，也可直接使用充分原题。
- W：当前 H 的可操作边界、实验问题、相关候选/实现、上轮变化和必要对照；不默认重读全部 H/A 历史。
- A：先看到不经作者逐项挑选的采集/执行结果概览，再看作者主张与直接依据；对照失败、遗漏、候选排名冲突，决定复核范围。
  必须判断本轮行动对全局目标的贡献；无法判断时给出缺失的区分性证据及补实验/修订/补材料方向，
  或说明实际不可行条件。局部代理改善和完成 W 任务不能自动提升为全局进展。
  本轮量大时概览只压缩字段，不静默删实验；显式覆盖数与分页。机械指标方向仅按已声明合同解释，
  不自动选科学冠军。逐项保留来源、信任等级及覆盖缺口；声明范围外或未留下可采集记录的 shell 工作属于观测范围外。
  A 可独立读取完整索引和原件，无须作者同意；盲审任务按其既有合同过滤评价，不泄漏被隐藏信息。
- 正式独立审查：保留既有独立性/盲审规则，不注入作者或 Root 的评价充当结论；必要科学主张与证据仍可读。
- Root：目标摘要、当前状态、负责人方向、所需操作/异常；不接收科学附件、数组或完整输出 schema。

### 机制覆盖与脚本证据

概览逐个列出当前 H 的假设键及版本，统计明确关联的已登记尝试（计划/启动/完成/失败），
并列关联未知数、批次/参数条件数与来源入口。一次 W、一次正式实验、一个压力条件分别计数，
不得把 192 个压力条件冒充 192 个独立科研尝试。共享尝试可关联多个 H，但总数按精确身份去重。
“已登记关联完成数为 0”只表示当前记录未显示完成；完整性不足时标未知，不能声称从未执行。
标注关联也不证明真正检验了机制或得到了独立证据，这由 A 判断。
M1 优先读取已有设计/预测/实验记录的显式关系，不按自然语言猜测；缺口时由 W 在批次设计或
现有证据元数据中声明一次假设键，控制层向已关联批次条目传播；混合机制批次按已有条目映射，不给所有条目自动套全部 H。
科学关联是作者声明，执行状态分别注明控制回执或作者报告，不能机械汇总后冒充独立核实。
不为每条 shell 命令新增填表/gate。
当前组合的完整机制身份和覆盖索引在 H/W/A 交接中持续可见，配以负责人最近的选择/延期理由及出处；
不只保留当前路线的 next_actions。状态与计数由控制层形成，优先级和实验是否有效由科学角色判断。
默认摘要有界，大组合可分页，但未默认展开不等于不存在；不强制把所有历史全文装进工作集。

M0 对 s27 封存报告中的决策关键主张逐项核对：正式实验记录、已封存脚本证据、已封存但缺
结构化索引、确实未登记、无法判断，报告条数和分母。shell 执行不等于未登记：本轮压力测试
已有脚本、指标与逐行材料的 tool_evidence，先查可发现性/关联缺口，不重复封存同一材料。
M3b 自动采集、M1 概览消费复用同一封存清单和 tool_evidence，不再要求 W 为本地输出逐项
调用发布工具、写用途说明、复制 alias。W 写科学判断、假设关联和所引用的任务内文件/运行名；
控制层在同一阶段或最终封存中解析到精确版本，歧义明确报错，不按最近文件猜测。
发布工具仅保留确有消费者的远端材料导入、显式早期交付等用途，不在确认调用方前整体删除。

### 控制层自动采集边界

- 编译合同可选声明台账默认位置/解析方式；已授权宿主或用户任务配置确定实际位置；W 可补充
  作者声明的位置。优先复用现有扩展点，确有缺口才增加 result_ledger 等最小声明。配置覆盖必须
  显式且兼容合同，冲突不能静默替换。W 声明路径不授予新读取权限，外部路径须满足现有访问边界。
  声明者、内容生产者及信任等级分别记录；插件声明位置也不使可写日志自动成为可信执行回执。
  covshift 可由宿主配置指向 /opt/exp/runs/results.jsonl，不要求题目先成为领域插件。
- 受管理输出目录是控制层分配并在启动材料中明确的默认产物目录，优先复用已有输出目录；
  代码、结果和日志默认写入此处，缓存/临时数组另放排除目录。M0 核对已有 output/scratch 语义，
  M3b-1 冻结具体路径与插件约定，避免与仅放提交表单的目录规则冲突。启动只需一句位置说明。
  现有 scratch 产物显式迁移或声明采集子目录；既不默默漏采，也不把整个 scratch/工作区纳入。
  无台账声明时仍采集该目录，但只建立文件清单，不从任意文件猜出完整运行台账。
- 阶段/最终封存自动流式采集声明范围内台账、代码和结果文件的变化，复用已封存内容；登记
  文件版本、大小、类型与可解析的参数/输入/结果关系。不存在的信息记未知，不让 W 补机械表单。
- 配置控制单文件/总量/条目数/时间及排除规则；沿用路径隔离、符号链接和私密文件保护。
  超限文件可仅记安全元数据与省略，但被科学结论引用的文件必须真正封存或明确交付未完成，
  不能用一个哈希冒充可读取的证据；禁止静默截断台账后宣称完整。
- 文件变化期间使用既有一致性机制或检测后明确未完成；不整文件读入内存，不自动终止求解器，
  不因此重复实验。具体方案在 M3b-1 独立评审，模型上下文只接收紧凑回执而非完整清单。
- 采集方式 auto_captured 与是否被作者引用 author_cited 是两个独立属性，同一文件可同时具备。
  自动采集不等于可信执行：作者可写台账保留其信任等级；控制执行回执、外部台账、作者报告
  分开标注。软隔离无法证明作者未删除文件或未登记运行，不宣传为“W 无法筛选的全部记录”。
- 对已登记范围，阶段采集无需作者逐条挑选，失败和负结果也进入概览；原生 shell 命令记录只在
  实际可观测通道补充，不将没有命令回执等同于没有实验。


## 3. 读取与交付原则

1. 启动使用一个规范入口：任务、最小支撑集、当前表单、少量必需工具指引；其他文件仍可作恢复原件，避免重复投递。
2. 科学补读依问题选择对象和片段；已有 reader 支持的 pointer/范围/目录足够时直接复用。
   完整读取保留给确实需要的程序检查和原文核验，不默认自动追随全部分页，不增加读取审批或强制理由表单。
3. 控制层标识已投递的精确对象/片段与变化；需要重新查看可以显式重读，不能因“读过”拒绝恢复或遗漏关键材料。
4. 单项较大时返回结构、相关片段和省略说明；不继续使用“摘要超限就整段消失”作为默认交接策略。
   科学负责人提供短交接；对已有长报告控制层只能投影完整字段/条目，不能伪造语义摘要。
5. 原件可供脚本计算，默认返回计算摘要及选定差异；不把矩阵/逐行结果先塞进模型再由模型压缩。
   这是默认工具行为和角色指导，不承诺阻止软隔离下任意 shell 全量打印。
6. Worker 填科学结果和必要直接证据。控制层按同一编译合同组装外层、绑定、附件清单和序列化；
   精确报告科学字段错误，不让 Worker 编码机械包装。保留 H/W/A 阶段结论和可追溯原件。

## 5. 来源校验修订边界

本次直接依据必须保留，不把“少读”实现为“少记”。历史引用图保留供审计。
控制层只复用自己签发/维护、绑定精确内容与有效规则的校验结果；不得相信作者自填 admissible 标签。
引用限制、未知来源和审查解除范围准确传播；动态 currentness/撤销/权限不能被不可变内容缓存绕过。
缺少可复用结果时采用有界可恢复检查或明确未验证状态，不能默认允许，也不能只是增大 128。
现有方案只表示修订方向；具体缓存键、失效规则及恢复过程在 M3a 设计评审确认，不承诺二十行修好。

## 6. 预冻结验收与成本目标

M0 固定 s27 代表性交接的输入和必须保留信息；同时使用通用非 covshift 合成任务覆盖改进/诊断/
原文及提取后入口。验收数据不进入被测科学角色。隐藏评分只在研究停止后隔离执行。

M0 将发布工具的调用数、批次数、文件数分别核对；不把“137 条”直接当137次模型调用，
也不把1KB重复50次视为固定放大系数。直接输入/输出与后续上下文累计影响分开报告，不能重复计费归因。

无模型通过标准：
- 三次尝试只引用两次：声明台账与输出自动采集仍展示第三次（含失败/负结果）；作者无须额外发布。
  纯 shell 留存文件可捕获而无执行真实性背书；台账截断、采集超限和采集中修改均不假称完整。
- 已有 s27 W3 来源规模可完成合法阶段封存；不得通过删除引用或增加单纯历史长度上限过关。
- 补读能找到未入默认视图的关键反例；来源标签不升级语义权威；恢复不丢用户指令或审批。
- 机制覆盖负例：缺关联不当作未执行、计划不当作完成、失败不当作支持、跨 H 修订不混计、
  混合批次不笼统归属；同一脚本/结果复用原封存对象，未知状态保持未知。
- 默认不输出全 schema、原件数组或整个历史；启动→读取→提交只使用同一权威合同。
- 对固定样本，默认启动投递和关键证据工作集字节相对旧版至少降低 50%；若任务不适用必须事前列明。
  该数字为验收目标，不是产品截断阈值；不足时缩范围/修投影，不丢必要证据。

M6a 固定为小型合成任务，**不跑 covshift，不套用其 25 次实验要求**：
- 数据和小程序由宿主预先冻结；含两个已登记候选、两种公开条件，平均分与最差条件排名冲突。
- 夹具留存三次尝试、作者主张只引用两次；控制层从声明台账/输出自动采集第三次不利记录，A 可追到原件。
  该遗漏为显式标注的验收夹具，不冒充真实模型的自然失误。
- H 提出可检验机制，W 实际执行少量秒级评估，A 识别冲突并提出可改变判断的补充实验，
  A 完成独立分析和交付；本场仅执行一次 H→W→A。若需补充实验，A 提出具体方向和依据，
  不在本场强制续接 W 或创建 H2。W 在本次任务内部可依据观察迭代，不要求一次固定网格结束。
- 增加“提出但未执行的关键机制”夹具：在独立可控的无模型交接夹具中固定该覆盖缺口，
  核对 A 默认概览可见；M6a 同一场中若出现该缺口，A 必须给低成本辨别实验或具体不可行理由，
  泛称 deferred 不合格。若 W 已合理覆盖全部机制，该项记未观测，不强迫 W 故意漏做或临时加场。
  不因此增加第二轮执行；需要真实缺口行为资格时另冻结场景，不能用无模型夹具代替模型行为。
- 同对象超过旧来源规模、重启恢复和权限负例由 M3a/M5 无模型夹具验证，不同时塞进模型短场。
- M0 冻结确切数据/种子、正确答案与允许解释、必需交接、评分规则及版本；角色仅见公开任务，
  不见评分答案。代码单项耗时先由无模型检查确认；任务变化即重新冻结，不能事后改题判通过。

M6a 首场固定效率目标：总 200 万 token、20 分钟，串行单次、沿用资源守卫；Root 与 Worker
使用相同已冻结模型口径（候选全角色 6.1-sol/high/default，无 fast），不是科学效果对照。
M0 优先复用 s27 的真实轨迹，按同一任务与原生线程身份对齐：派发请求/接受、attach、
assignment 打开、首次有证据的模型活动、首次实验执行、提交请求/响应及持久封存时刻。
分别报告派发到开始工作的延迟、Root 每次交接耗时、提交到封存耗时，以及模型参与的材料准备/
整理时间；完整角色墙钟不能全部归为固定开销。原生请求时间戳缺失时用可观测事件作上下界，
不把 token 通知时刻冒充请求开始，不解密 opaque 内容。
按角色列样本数、逐项区间和中位数/范围；单个 H 样本不推断可靠分位数。沿关键路径去重，
排除嵌套/重叠计时，明确平台/版本变化与 s27 样本少的限制。
无模型检查补测候选的文件准备、可无模型运行的进程启动、采集、解析和封存耗时。对已优化
机械段使用候选测量，不与旧段重复相加；模型参与延迟保留历史区间，不预先假定等比例下降。
启动前形成单次 H→W→A 的预计墙钟区间：非重叠机械开销＋真实模型交接参考＋小任务科学工作
估计＋明确的余量，同时估计 token 范围。判断 20 分钟是否具有可行性；历史参考与秒级数值
评估仍不能保证模型理解/实现耗时。明显不合适时先改实现或任务并重新冻结，不盲跑。
模拟派发不能代表真实模型延迟，历史实测也不视为候选的确定耗时。
若固定开销已明显侵占预算，先优化实现或在启动前调整并重新冻结科学任务范围，不取消 H/W/A 职责。
200 万/20 分钟不因测量或超时自动放宽；若需 30 分钟诊断场，单独明确，不回写首场通过标准。
无模型工作结束、场景与必需交接冻结后才启动；到顶如实记未完成，不自动提高或循环重跑。
在总计 200 万 token／20 分钟内完成一次 H→W→A，三项任务均封存且交接正确才算完整链路通过；
预算不足不把局部链路包装为通过，也不以一次循环未产生续接作为失败。此预算是首场效率目标，
不是仅在无交接玩具任务上适用；M0 冻结有实际假设、实验与分析工作的小型任务，不削掉角色职责。
角色职责：A 明确本轮核心问题与“继续 W / 修订 H / 补证据”的比较理由，不以“还有参数没试”代替判断。
不强造 H 修订；需要修订资格时另用固定场景验证。

M6b 完整对照在 M6a 通过后冻结任务、版本、模型、推理、权限、CPU、时间与预算：
- 初始总 token 目标不高于同条件原生对照约三倍；不能只拿 s11 旧单场当公平基线。
