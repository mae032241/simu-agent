## 1. 目标与边界

使一次有预算的分析能够留下可复用工作、解释计算耗时，并将已完成部分交给后续 Run。
完成标准是一次真实的“读取封存进展—完成有限分析—保存成果—新 Agent 接续”，而非测试数量增加。

第一准则继续有效：preflight 负责输入准入，提交负责新输出；恢复和遥测故障不能变成科学输出错误。
不增加科学 Schema 必填项，不要求所有目标一次覆盖，不把计时记录、工具调用或评分作为提交前提。
科学方法、目标子集和结论由专业 Agent 判断；机械路径、绑定投影、计时和文件保全由程序承担。

沿用现有 Operation 目录、四状态 Run、workspace hooks、恢复包、发布工具与精确审批规则。
不新增科研角色、Operation、MCP 工具、数据库状态机、审批、外部执行器或 VM runner 改动。
本轮支持范围为当前 Local 后端的通用/TCAD 分析；保留其他角色与 Hardened 的现有行为。
曲线工具仍可选，原生计算仍在 Worker 进程环境执行，不把任意脚本送进控制服务执行。

## 4. P1：保全实际分析工作

### 修改位置与方案

- 在 `plugins/curve_score/curve_score/analysis_workspace.py` 增加分析工作区组件，复用已有
  `workspace_materializer/workspace_snapshotter` 协议和 general_science 的结果 finalizer。
- 在曲线插件的 `science_operations.py` 注册该 workspace；仅已有提供 analysis_files_tool 的分析
  Operation 使用它。`tcad_artifact/result_analysis.py` 引用同一公开组件，不复制 TCAD 版本。
- 从该 Run 的 `output/` 和 `scratch/` 选择可交付的普通文件，包括未发布脚本、完整局部结果及
  下述规范化日志。可交付草稿范围与原工作目录保留范围分别记录，不声称所有普通文件都能进入恢复包。
  不复制只读输入、整个旧恢复目录、平台配置或外部路径。
  快照只能保存已经写入的字节，不能恢复 Python 内存中的结果；阶段落盘由 P4 的任务脚本实现。
- 新快照使用明确版本与 `output/`、`scratch/` 分目录，避免扁平文件撞名；复用现有摘要及恢复存储。
  已有旧扁平快照和 author 专用快照继续按原格式读取，不迁移或重写历史字节。
- `runs.py`、`run_assignment.py`、`tool_evidence.py` 只调整必要的快照布局识别、恢复位置交付和
  工具清单读取；识别依据为明确版本，不递归猜测“哪个 result.json 才是草稿”。
- 恢复材料保持只读、非科学证据；Worker 从明确位置复制需要修改的文件到新 scratch 后工作。
  同一 Agent 复用也必须打开新 assignment。已接受提交候选不因失败恢复重新封存或改写。

### 边界与失败处理

复用现有匹配 snapshotter 路径的 132 文件、32 MiB 恢复上限，并在实施前核对 `_recovery_policy`、
创建/验证/清理路径的预算一致性；不提高普通输出预算。读取前检查尺寸，禁止先无界读入再截断。
目录逃逸、符号链接、超量、并发写入或不支持文件都必须记录覆盖不足，原目录保留；不能只凭机械清单
或包本身通过校验证明 scratch 全部工作已保全。

### B1：失败、停写、保存与清理的顺序

本轮 Local 分析采取保守保留策略：失败 CAS 封住 Worker MCP 写入口之后，原工作目录默认保留，
不立即执行当前 `snapshot → discard → 删除原目录` 的破坏性链条。复用 local_workspace.py 内已有
恢复复制与校验逻辑，把复制保存和原目录清理分开；不新增 Run 状态或全平台进程注册表。

1. 先记录 failed，保持精确 CAS；该状态不证明原生子进程已停止。
2. 对启动脚本管理的进程，终止并等待实际进程组退出。只有可核验的退出/停止结果才允许认定停写，
   不能用 Run 已失败、发送过终止信号、心跳不更新或一次文件枚举代替停止确认。
3. 未取得停止确认时，保留原目录（或已存在的 quarantine），清理保持 pending。
   可复制已完整写入的稳定文件形成有界草稿，说明它是该次复制的子集；新 Run 只读这份不可变副本，
   不读取仍可能变化的原目录。复制期间无法稳定读取的文件留在原目录，不冒充已保存。
4. 只有停写已确认且实际需要保留的文件已完整保存时，才允许后续显式恢复处理执行清理。
   外层启动脚本被终止、直接原生命令未受管、服务重启后无法核实停写时，继续保留，不猜测后删除。

已有 draft_digest 只证明草稿副本可读，不代表 complete_snapshot_digest 或清理已完成。
`_finish_failed_workspace` 的重复调用和 recovery_status 必须区分“副本可交付”与“原目录仍待处理”，
不能因 draft 存在就忽略 pending。沿用既有恢复元数据及显式失败/恢复命令，不新增自动垃圾清理；
查询保持纯读。已经交付的快照字节不变，之后新写出的文件仍留在原目录，不更新已绑定快照冒充旧版本。

### B2：恢复文件、日志与缓存的兼容范围

可交付范围先限于当前分析实际使用的 UTF-8 `.py/.csv/.json/.txt/.log` 及 PNG；
目录中的候选文件仍须满足现有 seal 与 verify 两侧的一致内容/类型规则。
不能只在 snapshot hook 指定 media_type，再让恢复验证按扩展名得到另一种解释。
对同一候选文件复用现有内容检查，不新增科学校验或放宽正式成果的发布规则。

- 启动脚本禁写 Python 字节码；已有 `__pycache__/` 和 `.pyc` 明确排除并计数，保留其原目录位置。
  不因一个缓存或不支持文件拒绝其他完整可用的脚本和数值文件。
- stdout/stderr 原始字节按现有上限留在原工作目录；另生成可交付 `.log/.txt` 规范化副本。
  副本将任务绝对路径替换为工作区相对路径，其他主机路径替换为固定标记，保留异常类型、调用位置、
  原因及截断/规范化标记。原始日志不伪装成已原样跨 Agent 交付，规范化也不改写科学 CSV/JSON。
- 规范化后仍含敏感内容、不支持编码或不满足现有发布要求的文件，不加入该恢复包；
  按相对文件名和有界原因记录遗漏，不回显敏感原文。脚本或数值文件不做静默内容修补。
- 被排除或未能封存的原文件继续保留；包可以交付合格子集，但不得宣称原目录全部保存或据此删除它。
  需要的脚本/数据恰好不在子集时，明确哪部分不能续接，不能用空包或机械清单冒充有效分析草稿。

上述处理位于分析 workspace 与现有失败保存路径；先筛选候选再 seal，并通过 verify、draft_from、
新 assignment 实际读取验证闭环。恢复文件不自动变成可信科学依据；正式发布和历史证据检查不放宽。

在既有 run_status 的恢复信息中提供有界的已保存文件类别/数量、字节数、遗漏原因以及原目录是否保留；
由已验证快照和既有 pending 元数据导出，不另存第二份恢复事实。旧包只能报告其实际范围，
不能补称包含 scratch。此信息不决定科学有效性。

验收：在尚未发布、只有 scratch 脚本与局部结果时受控失败，新 Worker 能逐字节读到它们；
旧工具收据、旧 author 草稿和已接受候选路径仍能恢复；超限/篡改负例不会破坏原工作或放行伪造证据。
另验证快照枚举后写出的下一完整单元仍可恢复或原目录确实保留；只有启动脚本退出但子进程仍存在时
不能删除。真实 traceback 加缓存经 seal→verify→复制保存→draft_from→新 assignment 后，数值文件
仍可交付，规范化及遗漏如实显示；全部内容合格且停写已确认的路径才验证后续安全清理。

## 5. P2：取得原生计算耗时，避免观测假象

### 最小实现

在 `src/scidiscovery/artifact_agent/service/local_process_observation.py` 增加一个标准库实现的
本地 Python 计算启动脚本及有界记录读取函数。P1 的 materializer 将脚本副本放入任务内只读工具目录，
并通过既有 domain workspace 描述交付调用方式。脚本源只有一份，打包和工作区副本均从它生成。
Worker 用现有原生命令能力调用；不新增 MCP 执行接口、服务器执行权限或通用任务队列。
`runs.py` 创建工作区时将已有绝对截止时间传给 `assignment_json` 的增量预算描述；旧 assignment
缺失该信息时报告预算来源不可用，不猜测剩余时间，也不阻断旧任务的原生执行或提交。

调用使用任务内脚本路径、参数列表和本次计算超时；提交余量作为该本地启动命令的可调整参数，
不增加 Operation/MCP Schema 字段或服务配置系统。使用 argv，不经 shell 拼接；cwd 明确为本轮
scratch。Worker 选择算法及本次预算，启动脚本自动处理以下机械事实：

- 在执行前写开始记录，执行后写结束记录：墙钟/单调耗时、退出码、超时、可取得的峰值 RSS及其单位。
- stdout/stderr 各有界保存至 scratch 的原始日志目录，并按 P1/B2 生成可交付副本；
  截断和规范化必须保留标记与覆盖信息，不能在内存无限累积。
- 数值子进程设置 512 MiB 地址空间上限、BLAS/OMP 单线程；一次只运行一个子进程。
  这不是整台机器/整个 Agent 的内存保证；无法取得的资源数据报告 unknown。
- 取消统一 180 秒硬上限。本次有效超时为 `min(请求超时, max(0, Run 剩余时间 - 提交余量))`；
  剩余时间由控制生成的本轮截止信息在启动时重新计算，不由 Agent 手填，也不能借参数延长 Run。
  有效时间不足时不启动该计算，已有部分结果仍可发布/提交。
  180 秒只可作为首次小批试运行的建议，120 秒只可作为初始提交余量建议；Worker 根据实测计算、
  发布及整理耗时调整请求与余量，不能把建议数值变成科学可实施性的条件。
- 超时终止该脚本的进程组，保留非零退出、异常与已写结果；不伪装成成功计算或科学输出拒绝。

重试也受同一剩余预算限制，不能像现场一样只设置独立的 400/420/560 秒进程超时。
Agent 使用已有计算耗时估计本次剩余工作；不足时缩小可独立交付的工作单元或提交现有结果，
不能仅因代码已修好就重启全部计算。程序提供实际耗时与截止事实，不判断科学取舍。

运行记录留在 scratch，纳入 P1 恢复；有科学引用需要时仍通过现有发布工具封存，发布不升级为科学证明。
`run_status` 可读取一个固定位置、有界的技术摘要：当前/最近计算开始与结束时间、退出情况和观测覆盖。
技术摘要不展示脚本内容、命令参数、stdout/stderr 科学内容或主机秘密；查询不写 Run 状态、不延长预算。
记录属于 Local 环境的执行观测，不是防篡改运行证明；不能用其取代控制层终态或独立科学判断。

保持旧的直接原生执行方式可用；未使用启动脚本时明确显示“原生执行未观测”。启动脚本缺失或日志损坏
只降低可观测性，不能阻断有限分析。模型阅读、推理和写代码的时间仍不可精确拆分，应标记为未观测时间，
不得把它们算成数值内核耗时。本轮不做平台遥测集成。
排查旧 Run 时优先利用已经存在的原生命令返回记录；不能把 MCP 错误列表为空解释成所有执行均无错误。
本地会话技术记录可供工程定位，但不把整份平台聊天导入控制层或作为跨 Agent 科学证据。

验收：小脚本成功、退出非零、秒级超时、剩余时间不足、日志截断、进程组清理；
同时证明请求超过剩余可用预算时被截定，以及超过建议小批时间但仍在可用预算内的计算可以完成。
查询纯读；没有日志也能提交合格的部分结果。Agent 不需要手工编造耗时/RSS字段。

## 6. P3：修正说明、诊断与机械交接

### 路径及比较引用

在 `curve_score/analysis_files.py` 统一模型字段说明、GUIDANCE 与实例为
“相对于工作区根，例：scratch/analysis.py、scratch/results.csv”。保持现有已工作的参数形式，
不增加两套路径猜测或改名器。缺前缀时错误指出参数位置和正确基准。

`ObjectiveDiagnosisAssessment.comparison_keys` 的字段说明明确：只能引用评分记录中已有的比较；
原生计算通过已发布文件的 evidence_keys 引用，该字段可留空。不重加评分前提，不要求手工登记虚构比较。
保留不存在证据/比较引用的输出完整性检查；用原生结果无 comparison_keys 的正例验证可提交。

### 输入身份诊断

`tcad_artifact/result_analysis.py:analysis_parentage` 保留原判断真值，在实际失败分支抛出已有
`OperationInvocationError`，注明相关端口与失败关系。
`operations/invoke.py:_run_guards` 透传这种已声明输入错误；其他异常继续归工程故障，旧 bool guard 兼容。
不在另一层复制父链检查，不在提交阶段调用它。preflight 与 invoke 对同一请求给出相同原因。
至少覆盖 plan→review、plan→package、package→manifest 及 diagnostics 执行归属关系。

### 减少重复绑定

- `artifact_catalog` 在既有有序 parent_artifact_names 旁返回同序父对象 schema、kind 和安全生产端口
  元数据，使用当前实例已有名称；不可解析名称保持 null，不回退最新对象，不读取科学载荷。
- `run_status` 增加从已冻结输入导出的 `bound_inputs`（端口及精确 artifact_names），供后续同类任务复用。
  保持原顺序，当前实例缺少别名则明确 null；不在 run_list 批量展开大清单。
- 明确 TCAD experiment_plan/experiment_review 是原执行对应的计划/审查；新回顾性分析方案及审查
  通过 current_progress 输入。同步 catalog 端口描述、Worker 输入描述和调度说明，不改变端口名/必需性。
  Worker 输入描述从同一编译端口复制，避免另维护一份角色说明；旧 assignment 缺少描述仍可读。
- 调度者仍提交完整显式请求，控制层不自动选择目标、参考曲线、最新审查或新的 Operation。
  本轮只减少重复发现与搬运；不增加任意依赖图遍历器或“自动补齐所有输入”功能。

验收：原错误配对在 preflight 被拒绝且解释明确；正确的原执行绑定+新分析进展通过；
无 Run 的 preflight 不制造状态；旧记录可读；缺失别名、同 Schema 多父件不会被静默替换或拼接。

## 7. P4：阶段落盘、计算与绘图分离、局部重试

### 实施位置与职责

修改已有通用/TCAD 分析角色的共同指导，放在曲线插件共同说明的单一来源并由 TCAD 引用。
同时在安装后的真实任务中，由受控分析 Worker 修订本轮绑定的分析脚本，并通过现有发布工具产生
新的不可变脚本与结果版本。只更新提示词、只跑示例测试或安装 matplotlib，均不算 P4 完成。
Root 不直接改写受控科学脚本，不原地覆盖此前封存代码，不新增审查阶段或 scientific Schema。

### 脚本的实际行为

- Worker 先读已封存脚本与局部结果；按科学上可独立保存的工作单元组织计算，例如一材料的一次拟合。
  每个单元结束即保存数值结果，采用任务目录内临时文件写完后原子替换，保留最后一个完整版本。
  未写完整的单元不得因为进程成功、文件存在或部分字段存在而被当成完成。
- 数值计算与绘图使用独立入口或独立调用函数：计算入口生成/更新数值文件；绘图入口只读取保存的
  数值文件，不隐式触发拟合。实际入口由 Worker 在发布脚本中给出，不引入通用流程状态机。
- 绘图前确认本次所用库可用；可先做极小绘图试运行，或选择现有可用实现。此检查只影响该绘图动作，
  不成为设计、author、整体分析或报告提交的前提，不要求安装所有可能使用的库。
- 绘图依赖缺失或渲染失败时，保留并及时发布已有数值文件和具体错误。Agent 可修正绘图后只执行绘图，
  或在预算不足时交付缺图的有限报告。图缺失影响哪些科学判断仍由分析者解释。
- 对解析和数据结构错误，先在小输入/一个工作单元上修复再扩大计算；按照绑定方法处理相关数据范围，
  不因图外节点或一个局部错误擅自修改科学方法，也不重新执行已完成且仍适用的其他工作单元。
- 续算只复用与本次输入、数值方法和参数匹配的完整检查点。绘图代码变更无需让数值缓存失效；
  数值方法或相关输入改变时重新计算受影响部分并保留旧版。这里是任务脚本的计算复用规则，
  不在框架提交时重放计算、追加缓存合同或要求 Agent 填写新的控制身份字段。

### 预算与交付

先做一个有界工作单元，用 P2 的实测耗时安排后续批量与局部重试。预留发布和提交余量；
到达余量边界不启动新计算，使用已有发布工具保存已完成部分，以现有报告说明未完成项、错误与下轮条件。
绘图失败不自动把数值计算标成失败，也不自动让科学结论通过。缺口由 Agent 解释，控制层不生成科学阶段。

分批计算不改变正式方法时不重走计划审查；确实要改方法/目标，走目录现有修订及匹配独立审查。
保留 900 秒 Run 上限和现有重试限制。发生失败后，先读实际诊断与恢复覆盖；没有新增依据不原样再试。

本轮用原 Fig.4 已封存的中央分析及四份派生文件继续，原执行计划/审查保持原身份。
旧失败 Run 因合同升级不再满足 resume 时，不绕过合同；使用已完成分析的直接绑定文件，或通过当前
preflight 允许的 draft_from 交付旧草稿。任何材料不能准入均报告具体边界，不能修改历史资格。

## 10. 安装后验收与完成判据

源码验收后按已有安装流程部署；不改安装参数和 runner。核对改动文件、workspace 资源及在线目录。

先在临时实例做一次非求解器的受控中断：保存脚本和一个局部结果后失败，创建新 Run，派发全新 Agent，
证明其能仅凭 assignment/草稿继续；复用同 Agent 的路径由工程夹具覆盖，不能代替新 Agent 接手验收。
该验收包含“数值已落盘、绘图故障”场景：新 Agent 只修复并重试绘图，命令记录能证明没有重启数值计算。
另检查中断发生在下一个计算单元时，上一个完整单元仍可读；任务脚本中的缓存复用不代表科学资格继承。
保留真实绘图异常日志，并通过规范化副本交付诊断；自动缓存的排除不影响数值文件恢复。
原目录仍有写入或遗漏原始日志时，验收记录必须保留这些限制，不能因新 Agent 接手就宣称全部清理完成。
再在原 Fig.4 实例中选择一个有科学意义、能在预算内完成的剩余分析任务，由分析者自主选择工作单元。
要求至少封存一个此前未完成的结果或有证据的不可判原因，并能作为下一轮设计的绑定输入。
若是受影响方法本身不可实施，允许返回设计调整；不得强迫输出占位数值。

工程验收和科研进展分开记录：

- 工作区故障后脚本/局部结果可恢复，有覆盖证据；旧格式和既有 author 路径没有回归。
- 未确认停写时原目录仍在；已交付子集、未保存文件和待清理状态分别如实呈现。
- 普通 traceback、字节码缓存不拖垮合格数值文件的恢复；原始日志与规范化副本的边界可查。
- 缺绘图库或渲染异常只影响绘图；数值结果已经保存，局部重试不增加已完成数值单元的执行次数。
- 输入或数值方法变更时不会错误复用旧检查点；可选绘图或遥测缺失仍允许封存有依据的部分分析。
- 计算时间、失败位置、日志覆盖可查；无法观测的时间明确 unknown。
- 本次执行受绝对 Run 截止及所选提交余量约束，预算内的合法计算不因统一 180 秒限制被杀掉。
- 正确输入和无评分/无遥测的部分输出继续，错误身份与伪造证据仍拒绝。
- 新 Agent 依靠绑定记录接手并产生新增封存进展，不靠父聊天或上轮 Agent 记忆。
- 本轮新增框架阻断逐项记录。若仍超时，有明确诊断后再决定下一动作，不以自动重试冒充进展。

## 11. 风险、兼容与回退

变更 workspace hook/提示会改变编译合同摘要，新 Run 消费新合同；旧 Run 不被原地更新。

不能承诺旧版本直接续接，也不得降级解包后删除它。原 Artifact 和旧完成记录始终保留。
观测缺失降低诊断能力，不能让程序退出成功升级为科学成功或成为新的提交拒绝理由。
