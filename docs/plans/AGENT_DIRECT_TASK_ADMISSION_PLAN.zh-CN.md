## 历史 D1–D4 方案（已被以上决定部分替代）

## 1. 责任与依据

本计划是[科研进展判断与纠偏主计划](SCIENTIFIC_PROGRESS_AND_CORRECTION_PLAN.zh-CN.md)的局部修订，负责原始目标准入、前置任务选择和对应启动材料。它部分替代 R0 对目标来源仅限三类结构化对象的设计；精确来源绑定、预算、科学判断记录和长 loop 计划继续保留。历史验收不改写，本计划不代表行为已经上线。

当前入口的三个事实：

- 验收启动器通过 `artifact_ingest_text` 冻结完整原题，得到 `source_text / opaque`。
- `science.experiment.v1` 的 `objective_source` 只从 research-objective、foundation、intake 三种 schema 派生；校验还要求 `ResearchObjectiveContract`。
- 公开 `source_requirements` 指示“只有原始材料时选择 source-based task”。本轮 Root 明确据此先派发 intake，没有尝试直接实验。

因此，框架把“科学问题需要澄清”和“对象未包装成指定格式”混为一谈。`676d418` 已解决本地执行入口，不包含此项修复。

最近一场真实试验：40 次运行及审计完成，但在 2,020,374 累计 token 时停止，最终报告未封存；Root 798,072、前置 Worker 469,612、实验 Worker 752,690。前两者合计约 63%，不等于该比例全部可以省掉。缓存输入包含在总量中。原始证据保留在本地隔离试验目录，计划仅维护事实摘要，不收入日志、凭据或模型产物。

## 2. 行为规则

| 情况 | Agent 行为 | 控制层责任 |
|---|---|---|
| 目标与完成条件明确，或疑问可在实验内解决 | Root 可直接派发完整实验；Worker 内部完成理解、设计、执行和交付 | 绑定冻结原文、材料及现有权限预算 |
| 关键问题值得独立研究，且结论会改变后续方向 | Root 可选择前置分析、询问用户或独立审查 | 提供真实可用合同，不预设步骤 |
| 已有足够的 intake、目标或实验历史 | 复用科学内容及限制 | 按精确来源关联，不按最新对象猜测 |
| 缺少内部对象格式，但原文足够 | 直接处理原始任务 | 不要求先生产中间对象 |
| 原文缺少关键科学信息或环境不可用 | Worker 做可行检查，必要时澄清或交付 blocked/inconclusive | 不伪造结构化目标，也不把资料不足算成执行成功 |

保留 intake Operation，按其独立科学价值使用。Root 无需填写“是否前置”的新字段。Worker 的内部设计可以作为阶段交付，但不是开始运行的自动审批门槛。本地 shell 与配置选定的远端能力沿用 `676d418`。

## 3. 最小设计

### 3.1 原始目标与结构化目标并行支持

- 复用现有 `subject` 与控制绑定的 `objective_source`，增加冻结原始文本目标的合法路径，不新增目标数据库或常驻解析模型。
- 原始文本路径按明确的 artifact 类型、文本媒体类型和使用位置识别；不能将任意二进制、任意 opaque 文件或损坏 JSON 当作合格目标。
- Root 选择科学 subject。直接以原始任务为 subject 时绑定同一原文；从派生科学对象开始时按其声明的目标来源关联。只有一个非目标输入，不代表它自动成为目标。
- 结构化目标仍按原 schema 严格校验；损坏结构化对象不能回退成原始文本来绕过校验。多目标来源继续要求精确选择或修复，不能静默换成当前目标。
- 文本的科学充分性由 Agent 判断；控制检查可读性、精确身份、来源用途和材料上限，不以字段数量判定科研任务可执行。
- 原文始终可由 Root 和 Worker 有界回读。Worker 在完整任务内部形成工作理解，不要求先提交一个 intake 或独立目标对象。

### 3.2 下游规则保持诚实

- 准入允许原始目标，不等于原文是已审查的科学证据，也不赋予执行授权。
- 实例/loop 预算身份、远端授权、受限来源与精确审查不因原始目标路径而放宽。
- 自动指标比较、holdout、已核验进展等只在相应判据存在时工作；缺少判据记录为能力缺口/未知，沿用已配置的观察策略，不捏造机器可验证结论，也不为启动任务强制补表。
- 完成报告继续引用采用的实现与执行材料；“目标达成”的科学判断与控制层结构检查分开。未达成原文中的要求须明确保留。
- 普通文本目标在 UI、历史、相关任务查询、预算归属和轮换简报中保持同一来源身份。

### 3.3 有价值内容可读，机械内容自动处理

- 启动材料默认给原始目标、当前任务、相关已有结论、必要限制和材料索引；按精确引用合并重复原文展示，但保留其不同用途绑定。
- 实验输入同一原文兼任 subject/user_context 时，不重复打印内容。结构化补充结论仍可按需读取。
- 默认输出入口展示 Agent 需要填写的表单；核对实际 `read_output_schema.py --full` 内容，区分必要作者字段与机械封装 schema，再决定最小修正。
- 合同在同一运行内可复用。避免用禁止 `text(r)` 或隐藏必要字段解决重复读取；保留原文分页和明确的未读内容提示。

## 5. 验证与成功判定

### 源码和安装边界

1. 清晰原始任务直接派发，无科学中间对象；短真实本地进程完成运行、材料封存、validity 和最终报告。
2. 原始任务信息不足时可以提问/交付限制；控制层不强制它先变成结构化对象。
3. 结构化目标、历史目标、来源冲突和受限证据负例；无关材料不能冒充目标或批准。
4. 目标回读、实例预算、loop 关联、可选远端准备和跨任务续接；重点防止仅修改入口后下游仍按旧 schema 拒绝。
5. 安装后通过实际编译/Worker 入口验证；使用受限串行测试，不用全套和真实模型反复验证同一个源码问题。

### 真实 Agent 行为与成本

- 用同一公开 Covshift 原题检验自主调度，不在题目中添加“禁止前置”或强迫直接实验的提示。
- 记录 Root 选择前置的公开理由。明确任务若仍仅因格式而前置，判行为修复失败；若确有新的科学问题，保留其理由审阅，不能仅按任务数判错。
- 有意含关键歧义的任务先做定向夹具；如需真实行为小样本，单独声明其预算，测试 Agent 是否合理澄清或选择前置，而非是否机械走固定流程。
- 记录总输入、缓存输入、非缓存输入、输出、各角色用量、用量更新次数、工具回包字节、首个实验之前成本和收尾成本。用量更新次数不是精确计费请求数。
- 整场完成要求：原题规定的模型覆盖、至少 25 次不同实验、最后 8 次无最佳审计改进、选择并提交最佳合格模型、无泄漏标志、规定目录产物及平台最终封存；一项不足均不宣称完整通过。
- 初步成本目标：明确题目不再产生仅为对象格式服务的前置任务；Root 与前置消耗相较本轮 1,267,684 tokens 至少下降 40%，且完成质量不降低。记录绝对成本与最终封存状态；40% 是探索目标，不作为源码或自主选择行为修复的通过门槛。单次结果不宣称稳定收益或统计显著。
- 已有 Native 组因较低内存限制异常停止，只作历史参考，不能作为严格同条件对照。若要正式比较，双方须固定相同模型、输入、预算、内存和停止规则重新授权执行。
