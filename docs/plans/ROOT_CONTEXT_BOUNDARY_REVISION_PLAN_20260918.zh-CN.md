## 2. 不变边界

- 控制层负责绑定、配置快照、预算、身份、资格、幂等与权限；Worker 负责科学结果，Root 根据封存结论选择行动。
- 创建时检查输入；提交时检查输出。不得借本次改动把输入准入重新放回成果提交。
- 总体目标及相关进展原件仍可访问；结论、限制、剩余矛盾与行动理由不能裁成单一 verdict。
- 不修改封存科学原件、数值精度、历史审查资格或审批机制。
- 不新增预检票据、摘要 Agent、结果缓存数据库、状态机或全局截断器。不重做已经短化的 execution 默认返回。

## 3. 工作包 A：常规直接 invoke，preflight 可选

### A1. 复用已有准入路径

修改范围：`interfaces/mcp_root_operation_routes.py`、必要的 `mcp_root.py` 合同说明；仅在证明确有缺口时调整底层创建路径。

当前 invoke 已执行 `_configured_operation_call`，Agent 路径随后执行 `_prepare_local_run`；先逐分支确认 agent、transform、effect、approval 各自创建前的检查。检查齐全的分支不重复重构，不从 invoke 内部再调用一次公开 preflight。

正常行为：接收一次请求 → 解析并固定输入、执行配置和预算 → 准入 → 创建/返回已有对象 → 返回短回执。配置解析结果须贯穿指纹、Run 保存及 Worker assignment；不能创建时再次解析默认值，导致模型或预算漂移。

preflight 继续用于“只检查、暂不创建”，保留原接口和 normalized_request。预检不是授权、不保留资源，也不保证稍后的动态条件仍有效；invoke 仍独立检查。显式使用预检时仍可原样复用 normalized_request，兼容旧客户端。

### A2. 重试与错误

- 输入不合格时，不创建任务/成果/审批对象，不启动外部执行；允许保留诊断日志。
- 保留具体 reason_code、字段路径、原因及现有诊断入口，不把异常压成笼统拒绝。
- 不改变现有语义名称和内容指纹规则。配置不变的相同请求幂等；同名不同内容不得悄悄覆盖。
- 默认配置变化后，对旧名称的调用不得静默创建新配置对象或冒充原请求。沿用明确冲突；响应丢失时先查已有 Run 的绑定与配置，必要时重放其冻结配置。
- 并发相同请求不重复创建。审查独立性、恢复链 max_attempts、审批和 effect 权限仍有效。

### A3. 更新调用者

修改 `roles/scheduler.md` 与 research、inputs、dispatch、recovery 指南中强制两步的段落；同步接口描述、平台生成与相关架构中英文对应段落。

普通操作只读取 invoke 合同；需要预检才读取 preflight 合同。Worker 派发配置以创建成功的 Run 快照为准，不能依赖必须存在的预检结果。完整机器响应保存在编排存储，仅输出创建结果、必要配置和精确错误。

## 4. 工作包 B：字段目录与正文分离

修改范围：`mcp_root.py`、`mcp_root_run_routes.py`、`mcp_response_views.py`、results 指南。

在现有 run_status 增加 `output_mode="values"|"index"`，默认 values 保持旧行为。index 模式使用 output_paths 指定一个对象/数组路径，未知结构从 `[""]` 开始；增加 `index_offset`、`index_limit`（默认 16、最大 32）。这些分页参数只用于 index。

目录只返回原件身份、所选路径类型/大小、直接子项精确 JSON Pointer/类型/大小、总数和 next_offset，不返回子项正文。标量返回类型/大小和可读取路径；空对象、null、missing 明确区分。目录受现有 8 KiB 预算约束，无法容纳条目时明确报告，不能返回不前进的游标或伪造截短路径。

保留 `output_paths=[""]` 在默认 values 模式下原有语义，保留显式全文入口。index 即使搭配 view=detail 也不能夹带 sealed_output 正文。选定字段读取继续返回精确值及省略信息；按需逐层导航，不重新加载已保留值。

results 指南改为：已知字段直接选取；未知字段先目录；为决策读取正式结论、限制、剩余矛盾、行动依据及 scheduler_signal；完整设计/代码/数据绑定给对应 Worker，不由 Root 先全文中转。必要科学核查仍允许精确原件读取。

## 5. 工作包 C：父链及编排展示去重

修改范围：`mcp_root_instance_routes.py`、`mcp_root.py`、`mcp_response_views.py`，以及输入恢复指南。

- 给 artifact_catalog 增加显式 `view="parents"`，分页参数 `parent_offset`/`parent_limit`（默认 16、最大 32）。返回单份 parents 条目、parent_count、next_offset；名称只出现一次，保留 schema/kind/producer 用于筛选来源。
- 默认摘要不变；旧 detail 行为暂留作明确兼容入口。正常查父链改用分页，不能把第一页当成全部。
- 复用既有返回层，不由 scid_call 对所有工具进行内容无关截断。保留完整请求、合同和错误的机器表示。
- 生成指南明确：store 后不得顺手 text 整份结果；只打印当前需要字段，structuredContent 与 text 只解析一种。已知合同在同版本且上下文仍保留时复用，部署或上下文丢失后重读。
- 不新增 known_digest 协议或新的合同缓存服务；不把本轮 Root 改动宣称为所有 Worker 领域工具已优化。

## 8. 成本验收与完成标准

先做确定性返回对照，再用独立新进程对同一组冻结产物执行同任务 A/B：发现 Operation、创建无外部副作用任务、等待并读取成果、恢复相关父链、选下一步。模型、初始上下文、权限、材料、任务和预算保持一致；不把历史 81k 起点与新空会话相比。

分别测量 A 的直接调用与两步编排、B 的目录与旧全文路径、最终组合长链。旧两步已在同一编排且无回显时，允许 A 的 token 收益很小；不能预先承诺比例。

验收要求：

1. 功能及权限负例全部通过；无新的输入/输出职责混淆。
2. 常规任务不再要求预检；目录导航不隐式返回正文；父链可完整恢复。
3. 同任务组合对照的上下文净增量及累计输入下降，结论/限制完整、无效重试和人工介入不增加。单次观测只作为本样本证据；若未下降，不宣称优化完成，定位反例后再调整。
4. 等待请求数量及其成本单列，区分平台行为与框架可控行为；Worker 消耗分开报告。
5. 记录精确源码/安装版本、测试结果和逐请求计量。独立审查通过后方可标为计划通过；实施完成后另行审查实现和证据，不能拿计划审查代替实现验收。
