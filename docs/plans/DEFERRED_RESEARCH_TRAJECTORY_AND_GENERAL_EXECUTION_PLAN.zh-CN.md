# 后期计划：科研轨迹、通用项目执行与新领域接入

记录日期：2026-09-12。状态：后期方向，待排期；未作为实施方案完成审查，未实施。

本文记录科研轨迹、三维场景 VLA 探索、通用项目执行和其他仿真任务接入的后期方向。
当前优先工作仍由[分析工作保全、运行观测与跨轮交付修复计划](ANALYSIS_WORK_PRESERVATION_AND_DELIVERY_PLAN.zh-CN.md)负责。
本计划复用其后续实际交付的能力，不扩大该计划的范围，不继承其审查结论，也不改变当前研究调度。
当前架构以[架构说明](../ARCHITECTURE.zh-CN.md)和实际编译目录为准；本文描述预期能力。

## 1. 共同目标与职责

使现有科研框架能够追查研究如何推进，并将同一研究组织机制用于不同项目和求解器。
沿用 OperationSpec、一次编译的目录、不可变 Artifact、Run 和 Execution 生命周期。
具体实施前选择一个真实任务，核实届时已有能力，再确定最小增量。

| 责任方 | 应负责的内容 |
| --- | --- |
| 设计与分析 Agent | 科学目标、方法选择、实验范围、结果解释和下一轮问题 |
| 实施 Agent | 项目代码、依赖说明、运行入口，以及基于实际日志的修订 |
| 控制层 | 精确绑定、版本、已有授权规则、任务状态和机械交接 |
| 执行适配器 | 启动、查询、取消、日志与产物收集，以及能够观测到的运行事实 |
| 轨迹视图 | 展示上述事实及其来源，提供检索和关联阅读 |

机械身份、时间、文件映射和状态由程序生成；不要求 Agent 另填过程表。
输入准入与输出校验保持职责分离。轨迹完整度、计时工具和曲线评分均不成为新的科学提交前提。
需要的领域知识和工具通过现有声明机制提供；不按每个任务名称增加角色、状态机或核心分支。

## 2. 科研过程轨迹

参考 DeepSeek Harness 的追加式事件记录与 Trajectory 展示方式，先实现对当前科研有用的部分。
[官方介绍](https://deepseek.com/harness/)描述了会话日志、工具调用、上下文与子 Agent 事件的关联展示。
是否能够采集某类模型运行事件，取决于实际执行平台提供的接口。

首版范围：

- 按研究实例组织时间线，关联各轮目标、输入、设计、审查、执行、分析和修订。
- 复用现有活动与诊断记录，在实际入口补齐开始、结束、失败和恢复事件。
- 科学选择理由引用封存输出；运行中的过程信息和未封存草稿明确标注，不充当正式科学证据。
- 事件关联当时的代码、日志、产物和恢复快照；轨迹记录发生了什么，快照支持实际续接。
- 默认显示摘要，详细日志与数组按引用分页读取；下一 Agent 仍只获得本轮显式绑定的相关材料。

轨迹作为现有事实的查询和展示投影，不建立第二套任务状态权威。
采集缺项显示覆盖不足，不伪造事件，不因此拒绝科学结果；历史回放默认只读，不重新执行外部动作。
完整模型请求、实际上下文和平台可提供的推理摘要留待运行平台接入，首版不承诺全量模型内部轨迹。

验收：从一条真实研究记录中能够找到任务的输入、工具错误、修订和后续成果；
一轮失败能够定位现存代码与日志，并明确未采集的信息。重启后仍可查阅，展示不改写原记录。

## 3. 通用项目实施与执行

使同一个实施 Agent 能够编写普通项目、准备独立环境、安装依赖、调试、运行推理或提交训练。
环境准备和小样本调试可作为该任务内的动作，不机械拆成独立科研阶段。

最小增量：

1. 通用项目实施入口：交付项目文件、依赖与运行说明，并可明确返回实现缺口。
2. 通用执行适配器：接收项目、命令、工作目录、执行环境、资源预算和待收集产物；
   返回任务句柄、状态、日志、退出原因与实际产物引用。
3. 结果交接：把结果与精确计划和执行关联，供已有分析入口消费；保留原始输出与解析结果的区别。

执行先支持一个实际需要的环境，例如本地进程或 SSH 工作目录；云端队列有真实需求时再接入。
依赖安装限定在任务选择的环境，环境信息随项目保留。运行代码使用 Worker 或声明的执行环境，
不把任意项目脚本移入控制服务进程。

长训练与 Agent Run 分离：提交后由现有 Execution 生命周期管理，后续 Run 能查询、接收结果并续研。
项目检查点用于程序续算，Agent 草稿用于任务交接，两者分别保存，不靠会话记忆代替。
进程退出、任务成功、产物收集和科学结论分别报告。

验收：一个小项目完成环境准备、运行、故障修订和结果分析；另以低资源长任务替身验证
Agent 会话结束后仍可查询、取消或接收任务结果，并在新 Run 中继续。重复查询不重复执行。

## 4. 三维场景 VLA 技术探索

作为通用项目能力的候选首个非 TCAD 案例，先选一个明确任务，完成路线比较、基线运行和小规模离线评测。
复用已有证据阅读、设计、独立审查和结果分析能力；核查开放式技术选型是否能自然表达，
不为进入假设实验入口而虚构科学假设或强制无关审查。

首版只接入该案例实际需要的数据读取、图像或三维可视化与评测方式。
任务划分、数据与模型版本、配置、必要随机性记录和评测结果随项目与产物保存。
具体指标由设计与分析 Agent 根据目标确定，不将 VLA 指标写入通用控制层。

验收：在绑定的数据和环境上完成一次基线评测，分析可查的失败案例，
据此提出并完成一次有界修订；结果进入下一轮设计。首版不以大规模训练、真机部署或完整三维平台为目标。

## 5. 其他仿真任务接入

每个新求解器按三项能力核查：执行接口、领域实施知识、原始结果读取。

| 接口情况 | 接入方式 |
| --- | --- |
| 提供可用命令行入口 | 优先复用通用执行器，增加运行配置和项目格式知识 |
| 提供云端 API 或任务队列 | 插件适配提交、状态查询、取消和结果下载，复用 Execution 生命周期 |
| 依赖图形界面 | 单独评估自动化与故障恢复成本，有明确需求后再实施 |

第一种新求解器接入时，核实执行包和结果清单中的 TCAD 特有部分；
提取实际共享的项目、命令、任务、日志与产物交接，专用格式和求解器知识留在领域插件。
实施角色优先复用，通过声明的知识和工具获得领域能力；需要新增 Operation 时沿用唯一目录与编译机制。
格式转换、绘图和指标工具按真实原生产物补齐，不预先覆盖所有求解器。

适配器报告实际可观测的提交、初始化、求解和收集情况；无法证明的阶段标为未知。
独立审查和分析判断实现与科学目标的符合性，不能用进程退出成功替代物理或数值判断。
来源身份与执行授权继续有效，领域扩展不改变旧 TCAD 记录或原始文件。

验收：选择一个非 TCAD 小案例，完成项目实施、实际求解、结果读取、分析和一次有依据的修订。
制造一个受控执行或收集错误，证明诊断能返回负责环节并继续；新插件接入后旧 TCAD 路径仍可使用。

## 6. 后期推进顺序

1. 优先完成当前 TCAD 的工作保全与真实跨轮验证，再依据交付证据启用本计划的相关部分。
2. 建立科研轨迹首版，复用已经形成的运行观测和恢复记录。
3. 以一个具体项目落实通用实施与执行能力，并优先验证长任务和新 Agent 交接。
4. 在 VLA 小规模评测与新求解器案例中，先选实际需要的一项验证通用性，再按需求接入另一项。

各项只在具体实施前细化文件范围、兼容处理、资源预算与回退方案，不将本文视为已通过的施工合同。
工程验证优先采用串行、低资源定向检查；真实案例使用明确的计算预算。
不以全量测试数量替代真实交接验收，也不为后期能力修改当前进行中的研究目标。
