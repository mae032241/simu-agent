# 四模块实施主计划：颗粒度优先与配置化 TCAD 自主执行

更新日期：2026-09-24。状态：**按用户最新要求修订的实施提案；本轮只整理计划，未修改运行代码或部署配置，未运行测试或求解器。**

## 1. 决策归属与本轮目标

用户明确了两个要求：首先调整四模块的任务颗粒度；其次允许文件存储不超过 2GB、执行时间不超过 1 小时的 TCAD 任务由 Agent 自行决定运行，无需申请人工执行审批，相关阈值必须来自 config。

本文是这轮工作的统一主计划和实施入口。它替换本文件旧版“先优化 Root、再有条件合并作者”的排序，也替换旧策略中“所有外部执行均须逐次人工批准”的本轮设计要求。[原四模块策略](FOUR_MODULE_SIMPLIFICATION_STRATEGY.zh-CN.md)保留背景与不冲突的约束；[独立规划者的颗粒度计划](FOUR_MODULE_TASK_GRANULARITY_IMPLEMENTATION_PLAN.zh-CN.md)作为图证据纵向实现的细节依据，其执行授权描述以本文为准。历史审查和失败记录不追改，不继承旧 PASS。

当前架构、宪章和已安装合同仍描述现行行为。实施时应同步更新受影响规范和生成指南；本文不会使尚未修改的服务自动获得新行为。用户本次指示已明确授权规划新的配置策略，无需再为“是否允许额度内自主执行”重复请示。

事实基线是 `5871a64` 加实施前实际工作树。本轮核对了声明、执行控制、配置示例和本地/远端收集路径；未验证安装态。历史 138 通过、12 失败的定向记录不代表当前全树绿色，也不把修复全部历史测试列为前置任务。

## 2. 四模块按完整工作交付

| 模块 | 一个完整任务内连续完成 | 必须保留的交接 |
| --- | --- | --- |
| 证据 | 定位来源、描述标定与系列、调用确定性提取、自查、整理证据及局限 | 对正式证据的独立审查；改变来源/目标或超出预算 |
| 假设 | 理解证据、提出竞争解释、检查矛盾、形成可证伪预测 | 独立 critic；封存后修订需新对象和匹配审查 |
| 实验 | 科学骨架、作者具体化、源码、开发调试、形成可执行交付；额度内由 Agent 决定受控执行与收集 | 科学与实现的必要独立审查；目标/对照/判据变化；超额执行的人工决定 |
| 分析 | 有效性判断、计算、保存数值、绘图、解释和有限结论 | 需要新证据/实验、改变科学问题或权限；必要的独立复核 |

四模块不是四个巨大 Run、固定 DAG 或四个永久 Agent。工具与 Operation 可以细；同一作者在目标、权限和预算内的专业判断，不应每次都返回 Root 新建任务。不可变记录仍可分别保存，保存一份记录不等于增加一次模型任务。

保留来源与不可变性、精确审查、唯一 current/资格权威、预算和幂等恢复、只读查询、失败如实记录。删除重复实现不等于取消它保护的要求。自主执行授权与科学结论资格分开；额度小不代表科学结论自动通过。

## 3. 实施顺序

### 首批 A：真实合并图证据作者任务

当前“选图作者 → 确定性物化 → Intake 作者 → 独立审查”改为“一个作者连续定位、提取、自查、整理 → 独立审查”。同批闭合选中工具证据的完整封存、来源与修订、audit 及 curve bundle 消费。禁止在模块 wrapper 后面继续运行原来的两个作者。

优先复用现有工具证据、恢复和算法；具体文件、来源族风险和有限支持范围见[颗粒度实施细节](FOUR_MODULE_TASK_GRANULARITY_IMPLEMENTATION_PLAN.zh-CN.md)。不新增模块状态机或统一大报告。

### 首批 B：TCAD 配置额度内自主执行

与 A 可独立交付，不以 A 完成或全局 Root 改造为前置。沿现有实验模块和 Execution 生命周期，实现第 4—6 节的策略授权与资源执行。Agent 在已配置额度内明确发起执行，服务无需创建人工审批请求，也无需等待 UI 或聊天确认。

### 第二批：实验和分析连续工作收口

在已有骨架、作者工作区和分析工具上修复实际断点。普通工程调整留在作者任务内；数值计算先保存，可选绘图失败不重做成功计算。额度内执行沿首批 B 的授权路径，不在每次开发诊断或生产执行前额外插入人工决定。仍不混淆作者、独立审查者和执行 adapter 的职责。

### 随任务边界调整收简 Root

取消已经内收的机械调度与搬运，再改善决策字段投影、绑定候选和指南。默认状态继续短返回；显式决策读取采用结果类型声明的字段组合。绑定候选查询只读，创建派生对象是显式命令。自动 native spawn/attach 不是前置条件。

最后按支持范围与真实消费者退役重复 writer、废弃路由字段和不用的说明。隐藏后一周无调用不证明没有消费者；不以代码净减少或全文归档作为交付硬门。

## 4. TCAD 自主执行策略：明确口径

### 4.1 本轮采用的计量定义

- **大小**：2GB 按十进制解释为 `2_000_000_000` 字节，通过配置明确单位。不是 RAM 上限，也不是所有历史 Artifact 的全库容量。
- **范围**：单个执行任务的逻辑文件总额与执行工作目录占用。输入、运行中间文件、输出、日志均计入，不能只统计最后选中返回的文件。全局 CAS 去重不免除该任务对输入/产物的逻辑预算占用；收集同一文件的镜像不作为第二份科学产物重复计数，但传输/暂存的真实磁盘空间另作容量检查。
- **时间**：单个执行任务从启动到终止的墙钟时间不超过 `3600` 秒；不包括等待审批、队列和 Agent 写作时间，不把 CPU 时间替代墙钟时间。收集与网络传输有单独可配置超时，不能借此延长 solver 执行。
- **比较**：边界包含等号；大小和时间必须同时满足。可注册 capability 的 SProcess/SDevice 执行使用同一规则，不借本计划增加未支持的 solver。
- **多 case**：一个 study 请求的所有成员共享其总存储和墙钟预算，不能逐 case 各获 2GB/1h 后仍将整组称为同一额度内任务。运行器对整组设定共同截止时间及共享存储预算。
- **恢复/重试**：同一执行请求的恢复与重试不重置已消耗额度；新的科学任务可以按策略另行决定，不能自动改名拆单绕过同一任务额度。

以上是本轮计划采用的明确口径。界面和合同直接展示字节、秒、scope 和实际额度，避免“2GB”在不同入口被解释成不同值。

### 4.2 唯一配置来源

在现有 TCAD 执行策略配置中增加自主授权段，不创建另一套权限注册表。建议形状如下（键名在实现合同中统一，数值是本次用户要求的配置值，不是 Python 常量）：

```json
{
  "agent_execution_policy": {
    "enabled": true,
    "max_storage_bytes": 2000000000,
    "max_wall_time_seconds": 3600,
    "outside_limits": "require_human_approval"
  }
}
```

`enabled`、两个额度以及超额处理均可配置。字段缺失/配置损坏不能静默授予自主权限；旧配置迁移显式写出新策略并展示生效值。用户本次要求对应的部署配置应启用上述值，不能交付一个默认关闭且仍要求每次审批的实现。

Agent 选择自己的任务资源限额，不能通过任务参数或普通 Worker 写权限修改管理员策略。服务读取并冻结有效配置及其摘要；本地执行、远端执行、输入合同和能力视图消费同一有效策略。源码、提示词、Schema、测试逻辑和 installer 不得各自再维护一组 `2GB/3600s` 授权判断。配置示例和测试输入中可以出现明确数值；断言应依据传入配置。

请求预算与机器能力上限分开：RAM、CPU、并发、文件数等已有资源规则继续有各自配置和诊断，不能把 2GB 存储误设为 2GB 内存。若某个后端不具备所配置的存储/时间执行能力，在准入时给出确切能力缺口；不能先承诺支持再被隐藏常量阻断。

### 4.3 授权结果

| 条件 | 行为 |
| --- | --- |
| 启用自主策略，精确请求的存储/时间预算都在配置内，现有输入与独立审查有效，后端能执行限额 | Agent 决定执行；控制层登记配置策略授权并提交，不创建待人工决定、不生成审批 URL、不伪造 HumanDecision |
| 时间或存储请求超出配置额度，或自主模式关闭 | 按配置走现有人工执行审批；可由 Agent 主动缩小任务，但不能悄悄改写原计划 |
| 请求预算缺失/无效、输入错配、执行能力无法落实限制 | 返回具体可修正缺口；不凭模型预测“应该很快/很小”放行 |
| 运行时到达时间上限或触发存储限制 | 停止继续消耗，保留可保存的诊断/部分产物并如实记录；不自动扩大额度或继续等待人工后超额运行 |

这次改变的是人工执行审批门。已有独立科学/实现审查仍适用，但不得新增等价的人工“低额度资格批准”让免审批名存实亡。额度外的批准继续绑定精确对象；审批也不能授予后端本身不存在的能力。

## 5. 授权与资源实现边界

### 5.1 复用现有 Execution 状态

现有 `created → authorized → submitted → running → terminal → collected` 生命周期继续使用。`authorized` 的依据区分 `policy` 与 `human`：同一个执行对象、同一幂等提交路径，只是授权来源不同。记录精确请求/包/审查绑定、有效配置摘要、资源预算及授权方式，便于重启后核验。不新增 PolicyRun 或并行执行生命周期，不写假的人工同意。

preflight 与 invoke 使用同一策略判断。预检只报告是否可自主执行；Agent 明确 invoke 后才创建/授权/提交。提交前复核请求、包与当前有效策略；配置收紧或关闭时，未提交旧请求重新准入，不能沿用过宽的旧资格；配置放宽不会自动替旧请求扩预算。已启动任务继续受其冻结上限约束，取消仍走现有显式命令。未知提交状态先权威查回，不重发。

### 5.2 真正执行存储与时间上限

本地 `worker.py` 与 `remote_runner_py36.py` 已使用墙钟截止时间及 `RLIMIT_FSIZE`，但后者只限制单文件，收集时的总输出检查也不能限制运行中的多文件占用。因此必须实现任务工作目录的总量约束，并在 admission 中声明后端可执行的能力。

首版优先在现有 runner 中增加任务目录总量监测、达到阈值后的停止和诊断，复用后端已有配额时可提供更强的限制。监测间隔与停止宽限也由配置提供；采样方案必须记录实际峰值和可能超调，不能宣称无超调的硬磁盘配额。不得把新建目录配额系统、强隔离或多租户沙箱变成额度内免审批的前置工程。开发诊断和生产执行若适用自主策略，都沿同一资源规则执行。

时间控制覆盖 solver 子进程树及多成员 study，共用任务截止时间；退出后仍有存活写文件的子进程不能被记为已完成。重启和恢复不能重置预算。资源超限与科学失败分别表达。

### 5.3 全链路支持 2GB 以内文件

核对输入接收、项目归档、Artifact/CAS、工具产物、打包、runner 工作目录、远端传输、收集和分析读取，避免 64MiB、512MiB 等独立旧上限使配置范围不可达。既有 `max_output_bytes` 仍表示输出子额度，不足以替代总存储；与任务总额度、传输上限的关系在合同中明确。

大二进制保持文件/流式搬运与内容摘要，按需读取；不能为了接受 2GB 而把文件放入 JSON/base64、模型上下文或一次性整块加载。JSON 合同大小与二进制文件额度分开。实际占用预算由字节决定，不能只相信声明的 size。输入已耗尽存储额度时应允许 Agent 调整预算分配或任务范围，不静默截断输出。

## 7. 验收与资源纪律

### A：颗粒度的主验收

一个真实图证据正常任务由一个作者 Run 完成，原双作者交接与重读消失；独立 audit 和下游消费成功；整理/提交失败后复用已保存提取。源错配、旧审查、半族和篡改仍被拒绝。指标记录交接数、上下文重建、完成质量、工具调用、耗时、实际 token 与峰值上下文；不预设 40% token 或 5 次调用，不用字符数冒充 token。

### B：自主执行与配置的验收

1. 默认目标配置下，请求大小/时间等于边界可自主执行；任一项超一字节或一秒走配置的超额路径。正常额度内路径没有人工 approval 请求/等待/弹窗，不要求聊天再确认。
2. 改成两组更小和更大的合法配置，无需修改源码，目录/准入/本地与远端运行/状态展示均随配置变化；关闭开关恢复人工路径。检查边界数值只作为配置数据存在。
3. 输入/审查错配即使很小也拒绝；policy 授权不能被 Agent 参数伪造，human 授权仍验证精确对象。
4. 用小额度快速复现多文件总量超限、单大文件、日志膨胀、子进程超时、多 case 累计、收集/重启/恢复及未知提交。不要为验证一小时上限等待一小时。
5. 受限资源下通过真实存储和传输入口验证大于旧 64MiB/512MiB 的文件可流式接收、收集并核对摘要；2GB 边界验证安排明确磁盘/内存预算，并记录监测停止的实际峰值与超调。稀疏文件或模拟计数只证明对应边界逻辑，不能冒充真实传输完成；不得为测试把整文件加载内存。
6. 在已配置且能执行限额的真实 TCAD 路径完成一个短小任务：Agent 决定 → policy 授权 → solver → 收集 → 分析。用量在额度内时无需人工执行审批；真实模型/solver 未运行则明确保留现场验收未完成。
7. 降低策略或关闭后，未提交请求不能沿旧宽松准入放行；在途任务保留冻结上限，旧执行和旧人工审批记录可读。

每个首批交付共用一份持续追加的实施记录，工程独立复核聚焦精确改动和真实生产者—消费者；需要时把报告作为附件链接，不限制到无法记录证据的半页。正常正例与关键负例共同验收，测试数量或代码净减少不代表通过。

串行执行检查，不叠加重测试和 solver；按 diff 选择回归，不清理全部历史 pending，也不将所有历史文档搬家。未知费用或平台能力只记录具体缺口，不泛化成额外审批。达到冻结成本预算或重复同因无进展时停止并重新判断范围，不设所有问题必须“一次复验”解决。

## 8. 发布、回退与完成标准

- 发布前排空受影响在途任务；当前 `RunService._compiled` 拒绝安装 version/digest 漂移，不能承诺旧 assignment 自动跨版本继续。
- 新配置由部署过程显式安装并核对有效值。开发诊断已有的尝试预算、作者 Run deadline 与 solver 执行额度分别说明，不能用旧的低额度硬编码替代用户配置的自主执行范围。本轮计划编辑不修改现有服务，不声称免审批已经生效。
- 回退切代码/配置与新任务入口，保留新产生的请求、策略授权、原件和失败记录；先验证新授权记录仍可读，不把 policy 记录伪转人工决定。
