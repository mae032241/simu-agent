## 2. 职责和范围

| 主体 | 负责的事实或判断 |
|---|---|
| 用户 | 研究目标、关键约束、已有政策要求的人工授权 |
| 完整任务负责人 | 科学结果、解释、限制和下一步建议；必要时使用原生助手 |
| Root | 根据负责人封存结论判断目标进展，选择继续、调整、验证、等待或结束 |
| 控制层 | 精确关联、版本、事件去重、实际变化与成本统计、调度权及配置执行 |
| UI | 读取同一投影，展示判断、依据、缺口和用户待处理事项 |

边界：

- 程序可以确定记录是否变化，不能仅凭新文件、文字变化或 Run 成功推断科研价值。
- Root 的目标进展判断不能变成实验结果、独立审查回执或科学资格；它引用负责人结论，不能替负责人制造结论。
- 普通阶段不增加审批；精修次数不自动触发独立审查。重大节点沿用声明的资格和执行政策。
- 不按阶段拆 Agent，不要求每轮启动助手或审查者，不增加用于检查进展的常驻模型进程。
- 不新建循环引擎、数据库文件或另一套任务身份；不进行全库合并、安装器重写、多目标并行。
- 经验库、额外模型漂移检测及跨实例建议注入后置；本轮保留证据与适用限制供未来复用。
- 全程串行实现和验证。搜索先定位具体文件，禁止全仓/目录递归 `rg`；输出截断不能当作内存限制。

## 3. 最小科学合同与持久记录

### 3.1 任务意图：只在选择完整任务时表达

在现有 `operation_invoke` 中增加一个可选的科学意图对象；不新增 Root 工具。
后台开启本能力时由合同明确推荐，普通交互任务和现有插件不强制填写。
后台 assist 也不逐任务强制填写；但持续缺少意图或评估会由第 4 节的观测缺口计数触发复判，不能靠不报告一直避开保护。

| 科学字段 | 含义 | 处理规则 |
|---|---|---|
| intent | 换机制、补证据、精修、验证、诊断之一 | 表达研究目的，不规定必须按此顺序运行 |
| target | 本次要解决的目标项或矛盾 | 使用已可见的科学名称/描述；不要求填写数据库键或端口绑定 |
| expected | 哪种观测能够改变当前判断 | 写可被结果支持或否定的预期；不要求预先保证成功 |

控制层将意图与既有冻结任务一起保存，并供负责人只读理解任务目的，不要求负责人再填一遍。
已有指令足够但未结构化时保留原文，标为未分类；不能靠关键词猜测意图。
缺少意图不能使已经合格的科学任务无法封存。

### 3.2 完成后的科学意义

- 先复用现有 summary、limitations、remaining_question、阶段材料和适用的 objective_assessment 等。
- 各 Operation 的字段不同，不能假设所有结果都有 objective_assessment / remaining_contradiction / scheduler_signal。
- 当前 `ExperimentReport` 主要是 summary、outcome、limitations、remaining_question、adopted_stages；首版不为此重写所有插件输出。
- Root 在正常完成结果消费时，通过现有 `progression_report` 的可选评估项记录：对哪个问题作出什么判断、依据哪些当前可见原件、限制是什么。
- 该评估自动形成不可变的目标决策记录，与科学成果分开；更正追加新版本，不覆盖旧判断。
- 不新增“先交进展表才能启动下一任务”的通用 gate。缺少评估时投影为 unknown，同时更新控制层独立维护的观测缺口计数；不能只等待 Root 主动承认无进展。

### 3.3 控制层自动承担的字段

已有科学内容由控制层解析和提供，Root 不重复填写：

| 内容 | 自动来源 |
|---|---|
| 全局目标及完成标准 | 所选任务材料及其精确封存来源中的目标合同 |
| 阶段目标 | 所选假设或任务已有的阶段目标 |
| 当前进度 | 关联 Run / execution 的状态、封存阶段和最终结论 |
| 历史进度 | 同一任务谱系的既有结果与决策记录，按需分页读取 |

目标行为：Root 必须能读取全局目标、完成标准、阶段目标及进度摘要；隐藏的是填写端口与机械绑定，不是科学内容。相关证据任务默认摘要提供目标与完成标准，阶段目标复用假设的科学内容；较大内容提供有界读取和遗漏提示。当前不同生产者的默认摘要及原文回读尚未一致，按 R0 修复，不能把此要求描述为已有完整能力。
Root 选择要推进的科学问题；Worker 对新结果作科学判断。已有内容可读取不代表程序能推断科学价值。
材料缺少目标、存在冲突或多条方向时明确报告缺口，不从最新同类对象或实例简介猜测补齐。
工作树已实现部分主题选择、目标来源派生及封存逻辑；预算归属、UI、旧调试任务和完整执行路径仍需 R0 验证。Root 合同只选科学主题材料；进度判断与纠偏仍按 S2–S3 实施。

目标确切版本、任务/执行身份、前驱关系、输入输出引用、科学意图关联、时间、费用观测、归属、配置版本、去重键、消费位置均自动补齐。
对 Agent 只暴露科学名称、选定材料和完整的科学填写合同，不暴露内部绑定、端口回填或提交事务字段。

存储选择：复用现有 Artifact 保存不可变意图/评估，现有调度数据库保存实例/目标归属及消费索引。
若现有记录不能提供精确索引，只在该数据库增加必要版本化表；checkpoint 只保留有界近期摘要与位置，不无限追加历史或复制成果正文。
源码声明、Agent 表单、最终封装、下游读取和 UI 必须使用同一合同；机械字段只在控制层物化。

## 4. 判断语义与计数规则

分开保留两个维度：**观察事实**和**科学判断**，不压成一个成功布尔值。

| 情况 | 观察事实 | 科学判断与计数 |
|---|---|---|
| 新结果排除候选机制 | 产生确切结果及引用 | 有证据的 advance；负结果可以有进展 |
| 参数不确定范围收窄，主矛盾仍在 | 证据/范围发生变化 | 可判 advance，不能仅比较矛盾文本 |
| 新文件或结论换措辞 | 输出发生变化 | 不自动判 advance |
| Run 失败且没有合格解释 | 工程失败/结果缺失 | unknown；另记失败模式，不直接判科研无进展 |
| 失败产物经有效封存和分析揭示边界 | 失败事实与可用证据都保留 | 可以据证据判 advance；禁止把原始日志自动当作科学结论 |
| 等待求解器、审批或用户材料 | 存在可核实等待条件 | waiting，不增加无进展/精修计数 |
| 有理由认为结果未改变认识 | 最终材料已消费 | no_progress，需保留理由与引用 |
| 无法判断或引用缺失 | 缺测/遗漏显式保留 | unknown，不能当作成功或无进展 |
| 新结果与先前结论冲突 | 同一目标内出现冲突判断 | 触发复判提示，不自动选择正确的一方 |

计数单位为**控制层已向决策回合交付终态信息的完整任务**，不是 tick、日志条目、阶段交付或 Root 工具调用。
控制层保存投递位置；该回合结束或下一任务准入边界到达时结算一次。是否有 Root 评估是被观察的信息，不能成为登记该任务的前提。
完整内容被截断时保留缺口和读取入口，不声称模型看过原件；仍可以记录评估覆盖不足。仅在运行中的任务不进入完成任务计数。
重复通知、重启、同一结果重读不能再次计数；回合结束与下一任务准入竞争时使用同一事务去重。未确认终态的回合由现有恢复流程处理，不推断其已消费。

- `no_progress` 连续计数只在有效评估时更新；waiting/unknown 不增加，也不靠它们清零。
- 有依据的 advance 可以结束该连续段；工程成功或换名字不能清零。
- 精修计数按已接受完整任务的科学意图统计；作为提示，不自动阻止继续精修。
- 目标版本变更保留旧记录，新的判断段关联新目标；既有预算、尝试和未结束外部动作不随之清零。
- 缺少科学判断时既有观测缺口保护，也保留原有时间/任务/token 预算约束，不用强制填表替代止损。

### 4.1 不依赖 Root 自评的兜底信号

控制层自动记录，shadow 只观察，assist 按配置触发复判。实施速查：

| 信号/事件 | 确定性依据 | 控制动作与边界 |
|---|---|---|
| 评估覆盖不足 | 缺意图/评估、unknown 或引用无效 | 单个终态任务计一次；Root 不报告也计数 |
| 连续引用未更新 | 同一目标版本内，已消费任务没有采用新的封存科学结论；按精确引用和已有内容摘要去重 | 独立于 intent/target 文本计数；方向相同只是附加解释 |
| 重复工程失败 | 同类可识别错误及相关输入/恢复变化 | 复用故障政策并提示；不直接判科学无进展 |
| 有依据的等待 | 实际在途作业、待决审批或持久用户问题 | 等待不增加任务计数；不能遮蔽已完成的其他任务 |
| 达阈值 | 原因、关联任务、引用、计数、配置和投递位置 | 原子冻结提示快照，合并同类原因；有预算时复判一次 |
| 迟到评估 | 对原任务/结果版本追加更正 | 更新当前分类和解释；已投递提示及其触发计数保持不可变 |
| 复判回应 | 新说明与确切材料 | 对提示追加 resolved/unresolved 处置；“补交 advance”本身不撤回提示或暂停 |
| 持续缺口 | 复判后仍无法解释或配置条件继续满足 | assist 暂停新派发，保留已接受任务；显式恢复不扩预算 |

前两类使用同一可配置的观测缺口阈值，分别计数，默认候选为 3。任务名称、target 改写、提示 ID 或补交文本不能清除已投递的原因组与复判次数。
未投递前按正常评估结算更新；投递和更正竞争时串行化，已发出的提示保留当时完整快照。实时计数可以反映新分类，触发快照与追加处置分别保存，不篡改历史也不永久冻结整个目标。
缺失评估、unknown、旧引用或无引用的 advance 均不清除原 no_progress 计数。采用新的有依据的分析结论可以结束引用未更新段，无需强制新增物理实验；仅有格式变化或新文件名不够。
信号说明推进依据的覆盖情况，科学价值仍由带证据的判断和独立评分检验。对语义改写、伪造但有引用的论断没有完整机械检测保证，基准明确记录这一限制。

## 5. 纠偏闭环

1. 控制层生成有界的异常迹象：重复失败、反复精修、连续无进展及第 4.1 节的观测缺口。验证下降仅来自同一冻结标准下的已有可比较数值结果，或负责人/Root 带引用的已记录判断；目标偏离仅来自带引用的已记录判断。没有这些来源就不生成该信号，本轮不新增语义漂移检测器。
2. 同一组原因和证据合并成一次提示，在下一安全任务边界交给 Root；不额外派审查 Agent。
3. Root 消费近期意图、实际结果和限制，选择继续、补验证、改变假设/实验、先修工程问题或向用户提问。
4. 调整后的下一任务复用第 3 节意图，控制层自动关联触发本次复判的原因。
5. 后续结果对照调整预期；只有证据支持问题得到推进时，才记录纠偏有效。改计划本身不是成功。

默认先 shadow：记录提示和本应采取的控制动作，不改变调度。
assist 模式下同一原因组最多进行一次有预算的复判；持续无进展或观测缺口达到条件、复判后仍无可用解释时暂停新派发，显示具体问题和可选后续方向。
Root 沉默、重复 unknown 或仅写“有进展”不会消除触发原因；无需等待 Root 自己申请暂停。修复性说明可复用现有意图/评估字段，不要求新表单或新审批。
提示的投递、复判结束和暂停都持久化；新增同类任务不能靠更新提示 ID 不断获得一次新的宽限。仅调整计划不能清除历史计数，后续实际结果仍需核对。
用户恢复不自动增加预算；恢复后沿用未解决的原因和记录，不把暂停当作清零。
停止或暂停保留已接受工作的状态；取消是单独动作，不能由“无进展”暗中取消求解器。

## 6. 实施批次与退出条件

### R0：目标与交付链修复，按基线依赖分批

本批不替代 S1–S3，编号标识修复项而非固定执行顺序。划为两组，仍全程串行：

- **R0-A，基线前必需**：R0.3 后台权限、Worker 复用问题的确定性关闭证据，以及目标来源改造和 R0.1 配套预算归属修复。先通过源码、已有轨迹和协议夹具核对两道合成题的目标输入及可调用路径，不为确认路径另起模型预演。若短目标仍被省略或相关输入无法自动绑定，则将 R0.5/6 对应最小修复前置。
- **R0-B，发布前必需**：R0.2 当前任务/UI、R0.4 TCAD 封装、R0.5/6 未被基线使用的读取及跨插件投影。可在 S0 基线之后完成，不阻塞与其无关的合成场景；在 S5a 冻结候选前完成，正式发布覆盖全部 R0。

**基线合同决定**：已提交的 `science.experiment.v1` 从 `research_objective` 改为 `subject`、由控制层派生 `objective_source` 的改造，明确纳入修复基线，和预算归属一起通过 R0.1 后冻结。Root 可自主选择完整任务，单次轨迹未派发实验不能证明后续样本不会使用该合同；因此不把这项改造留到 R0-B。基线与候选、人工与自主组使用相同的目标输入合同及预算归属规则，均记录代码/catalog 摘要。三类目标到政策授权 start 用受限适配器夹具验证，不以此要求真实场次必须执行 TCAD；原始 `c00706f` 及其失败记录单独保留。

先用定向源码与协议夹具验证，再启动真实研究。复现成功代表发现缺陷，不能记为修复通过。

| 配置项 | 初始策略 |

## 8. 基准与验收标准

复用 `scripts/accept_b6.py`、`scripts/b6_evidence.py`、`scripts/acceptance/scientific_progress.json` 和 `scripts/run_tests.py`。先建样本与标准，再改行为；运行全程串行。

| 场景 | 要证明的判断 | 对照/负例 |
|---|---|---|
| 已知关系 | 正确结论且保留外推限制 | 拟合相同数据不等于因果证明 |
| 数据不足、两机制不可辨识 | 能明确不知道并提出区分观测 | 不能强选胜者或捏造数据 |
| 连续无效精修 | 发现未改变证据并重新判断 | 有效缩小不确定范围不算停滞 |
| 有效负结果 | 排除机制算科研进展 | Run 状态不能独自决定科学价值 |
| 过拟合与验证失败 | 限制结论并改变后续任务 | 换名的同一数据不算 holdout |
| 工程故障及恢复 | 区分工程修复与科学结论 | 未知提交不重放，已有结果可继续采用 |

控制层刹车用确定性夹具及实际消费/调度路径的回放覆盖：投递足量终态任务，跨阈值后复判、暂停，验证未知评估、旧引用、迟到更正、重启和正常等待。复判是一次 Root 决策回合，不强制再派一个完整 Worker 任务。
真实 `stagnation` 题的三点使扰动项为零，实际测量“识别不可辨识、避免无效精修”；正确早停是合格结果，不必出现连续三次失败。历史 case 名保留以便关联证据，不把它当作刹车触发用例。刹车触发与科学质量分开评分；轨迹未达到触发条件时，触发/漏停记未观测，不能算零漏停或已证明实际纠偏有效。
单场 200 万 token / 20 分钟不保证容纳连续三个完整任务及复判；历史单场成本只是估计。首版不扩额来强求触发，若未来专设真实多轮刹车实验，另冻结场景、预算和评价标准。
评分责任：可计算的已知答案由固定评分器判断；科学解释、有效负结果和纠偏合理性由未参与该次任务的人工评分员按冻结 rubric 评阅。
可选独立模型只辅助评分，单独记录其用量与与人工的分歧；不得由运行该研究的 Root/负责人兼任最终评分员。人工未完成的项目保持待评，不以自动字段校验替代。
评分时隐藏组别与版本标签，不能看完结果后改变规则；主观项目保留依据与分歧。
固定材料/目标/模型配置/预算，并保存代码、catalog、设置、题目及评分规则摘要。模型随机性和样本量在报告中明示；单次小样本不能声称普遍收益。

最小采样设计：

- 核心“不可辨识与避免无效精修”（现有 stagnation 题）、“有效负结果”各做 3 次独立重复；基线/候选 × 人工/自主四个实验单元均使用相同重复数。合计最低 24 场，全部串行，S0 先留存其中 12 场基线；这些是质量与成本对照，不能全部宣称为真实刹车有效性样本。
- 其余场景先用确定性控制负例和已有证据筛查，再按变更风险分批真实验收；单次运行仅证明场景可运行，不能外推稳定收益。S4 的验证质量另按冻结样本验收。
- 每场使用相同初始材料和隔离状态，不继承上一场产物/助手上下文。设定单场及整组预算，失败、中止、超预算与缺测全部纳入结果，不只统计成功场。
- 报告逐次结果、成功/误停次数、token 中位数与范围；三次重复仍是探索性样本，不宣称统计显著。
- 若现有额度不足以完成采样，先报告探索性结果与剩余数量；不自动扩预算，也不反复重跑整组。平台条件漂移时补同期配对或明确不可比。

### 8.1 S0 成本预估与整组上限

按评审提供的 B6 历史单场约 100 万累计输入+输出、约 7.6 万非缓存 token 估算，只用于规划；不同场景真实用量以原生 usage 为准，不据此估算货币价格。
该估计来自人工组，不能直接推定自主组成本。R0-A 后先在现有单场及整组额度内运行一场自主组；记录 Root/Worker/helper 用量与完成任务数，更新余下场次的成本预测后再排期，不自动提高预算。若未改冻结条件，该场可纳入相应预定样本；如调整材料、合同、评分或预算，则保留为预演，计入成本但不混入同条件比较。余量不足时明确减少可完成样本并报告探索性结果，不能悄悄降低 24 场资格要求。
预算单位明确为：总 token＝输入+输出（缓存属于输入）；非缓存工作量＝输入−缓存输入+输出。S0 开始前核对历史“非缓存”口径，不能确认时保留估算不确定性。

| S0 的 12 场基线 | 总 token 约 1,200 万；非缓存工作量约 91.2 万 | 总 token 1,600 万，非缓存工作量 120 万，执行墙钟 4 小时 |

### 8.2 shadow → assist 的量化门槛

1. **隔离试验准入**：无模型的确定性夹具/shadow 回放及消费到调度的集成路径全部通过；覆盖达阈值、复判后持续缺口、正常等待、有效负结果、完全不报告、改写 target、补交评估及重启。应提示/暂停的轨迹全部触发，误停、漏记、重复副作用均为 0。满足后仅在隔离候选中试用 assist；只测试计数函数不足以通过。
2. **真实科学质量**：候选自主组的“不可辨识与避免无效精修”3 次中至少 2 次给出符合冻结 rubric 的、有证据的停止或调整；Root 主动正确判断与响应提示均可通过。单纯撞到预算上限不算科学判断成功；此项不作为刹车真实触发有效性的证据。
3. **误停为零**：候选自主组“有效负结果”3 次全部无错误暂停。3 次任务均安排可核实的正常等待窗口，全部不因等待误计数/误停；夹具另覆盖作业、审批、用户问题三类等待。新证据合理继续的对照也不得误停。
4. **证据充分**：24 场均报告结果与缺测，候选上述关键场景完成独立评分；未测/待评不计通过。基线和人工组只作效果对照，缺少新信号的旧代码不能被算成“新机制误停为零”。
5. **启用与结论范围**：以上各项通过后，可显式配置在候选验证范围内默认 assist；没有真实触发样本时仍标注“真实触发效果未观测”，只声明控制机制的确定性证据和真实场景质量/误伤观测。未达标保持 shadow。修改阈值或 rubric 后标新候选，保留失败版本，不能反复调题后宣称独立验证或普遍收益。

第 2/3 项分母按候选自主组固定，不把四个实验单元混成 24 场统计来稀释误判。实际默认切换通过显式配置执行，测试通过不直接修改运行中目标。

指标：

- 结论正确性、证据绑定、限制保留、目标闭合；错误自信与伪造证据单列。
- 进展判断/停滞提示误判和漏判；有效负结果、正常等待误停必须作为阻断回归处理。
- 调整前后实际信息收益、无效任务数、额外复判次数及用户介入次数。
- Root / 负责人 / 助手各自输入、缓存输入、输出和缺测；非缓存输入按有效累计差计算，缓存不重复相加。
- 总体 token、Root token、耗时、写库次数、内存观测范围和停止原因。不能靠转移成本给 Worker 宣称整体节省。

效果通过条件：目标场景给出预期科学判断和下一步依据；控制负例无重复副作用/越权/错停；如果 token 或延迟增加，量化增加与质量收益。无收益则调整或保持 shadow，不预设节省比例或 LoopX 能力百分比。
真实 TCAD 是单独的领域集成资格；合成题和协议夹具不替代它，也不作为本轮每次迭代的必跑门槛。
