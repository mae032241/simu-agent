# 历史兼容修复实施计划 R2

2026-09-09。依据全路径审查 R1，目标是让精确历史记录参与新研究工作，同时不继承旧 Run、旧审查或执行批准。

## 范围与取舍

不新增状态机、迁移引擎、兼容白名单或第二份 Operation 指纹。不改科学载荷，不放宽实例、引用、摘要、当前头、精确审查和执行批准。使用现有输入用途区分读取与授权，避免新增默认字段引起全部 Operation 摘要变化。

- `evidence_inventory`：背景/原始材料阅读，不以当前生产合同决定可读性；原有来源关系和资格校验继续执行。
- `prior_signal`：可在当前输入结构可消费、来源可核验时读历史对象；仍执行当前独立审查要求。
- `revision_base`：允许历史对象作为新 Run 的基底，必须满足当前精确非通过审查；不允许复用历史 Run；跨版本保留有界修订计数。
- `change_request`、`review_signal`：继续要求当前审查及精确主体。
- `claim_evidence`、执行载荷以及其他用途：保持精确生产合同门，不借此直接执行旧计划。

以上按输入用途适用，不按 Agent/Transform 粗分；这不是放开所有 Transform。

## P1：上下文展开和修订闭环

位置：Root 输入准入、修订历史计数及对应测试。

1. prior_signal 与 evidence_inventory 使用一致历史读取语义，覆盖确定性展开/证据拆分/新批准所需输入。
2. revision_base 允许历史版本，但匹配当前声明的审查关系；原非通过 verdict、精确主体、循环上限及无进展检查不变。
3. 修订历史追踪依据同一修订 Operation 与精确基底链，不能只因 digest 更新重置预算。遇到不明确链结构明确拒绝，不猜。
4. 负控：旧审查、错主体、错来源、claim_evidence、执行及跨合同 Run 恢复仍拒绝。

验收：历史假设＋当前审查→新设计→完整 cohort 展开→新计划审查→author 准入；历史计划/项目→当前非通过审查→新修订。探针必须通过真正的 Root preflight/invoke/Worker 提交边界，不能只 mock 审查为 True。

## P2：历史来源与申请新批准

位置：Root 来源族重建、当前资格投影路径及对应测试。

1. Run 来源事实使用其完成记录、精确 output_ref、保存的版本/digest、输入和 Artifact 标签，不能写成当前生产身份。
2. 可消费性与当前独立审查关系仍由当前目录提供；当前端口类型不兼容、生产者不可用、来源标签与完成记录不一致明确拒绝。
3. Transform 仅在现有冻结标签、实例内调用指纹、完整 sibling 集合、相同有序父引用与唯一端口分组均可证明时恢复来源族；保留原生产身份。当前端口无法唯一承接历史结构时报告缺失，不自动迁移或猜测。
4. 新批准仍要求完整族、冻结来源、当前精确审计和 UI 决定；不接受旧批准替代新决定。

验收：历史 Run 提取族在新审计后能够创建新的批准请求；漏 sibling/来源、篡改生产身份均拒绝；Transform 兼容与不兼容分支各有负控。

## P3：结构兼容与读取可解释性

位置：Root 读取与输入校验、Run 交接只读查询、Worker assignment 描述。

1. 结构化历史输入在准入时使用已有输入 JSON Schema 做有界验证；报告输入端口与首个字段位置。inventory 原样阅读不要求当前科学结构；不填默认科学参数、不转换载荷。
2. 完成载荷与 handoff 分开判定；handoff 不可解析不再遮蔽可独立核验的历史载荷，handoff 仍返回 null 并明确状态。
3. inventory 明确历史生产状态，历史 handoff 仅供阅读，当前资格路径仍使用严格查询。
4. Worker 输入描述提供最小历史标记，不能传出控制身份或把历史 verdict 宣称为当前授权。

验收：旧 signal 格式不损失封存载荷；结构不兼容在新 Run 前定位；历史标记在 assignment 中可见；运行中结果仍不可读。

## P4：有界验收与交付

所有测试串行，BLAS 线程 1、虚拟内存上限 3 GiB、每批超时 180 秒。优先小型真实本地 MCP fixtures，保留执行批准与精确引用负控。不跑全量、压力、14 环境安装矩阵或 solver。

保存实施前相关文件、精确增量和日志。每阶段相关测试通过后才进入下一阶段；相关失败先定位，不重复跑无关已通过集合。部署前不改正在服务的 state，也不代替用户批准。最终报告本地完成与实际部署续跑的差别。

## 计划审查（执行前）

执行者自审，未冒充独立审查。

- 目标匹配：P1 对应已发生的展开阻断及修订断点；P2 修复批准准备的二次来源障碍；P3 对应结构与可读性缺口；P4 要求串联证据。
- 工程完整性：显式覆盖通用准入、来源族、当前审查、修订预算、JSON Schema、读取和 assignment，不只改报错所在 if。
- 权限边界：历史读取不改变当前审查/执行身份；新批准仍走 UI。来源族保留原身份，不以新身份覆盖旧记录。
- 最小改动：复用现有用途和 Schema/Run/Artifact 记录，不扩充科学角色、操作目录、存储表或状态机。
- 限制：未知生产者或不能唯一核验的旧 Transform 不保证结构化复用；只能作为历史背景读取并明确缺失。该限制不能被包装成任意版本兼容。

结论：计划通过上述自审，按 P1→P2→P3→P4 执行。若实现发现影响准入/安全语义的新缺口，先修订此计划并重审，不能静默扩大范围。

## 执行中补充审查：历史非合格结论传播

P3 串联检查发现，Transform 的非合格标签传播此前读取的是“当前资格交接”；历史 Run 的 blocked/revise 会因合同更新而返回 null。放开历史输入后必须保留这些负面事实，否则变换输出可能丢失 nonclaiming 标记。

补充要求：仅在计算 derived_from_nonqualifying 时读取历史交接；当前审查/批准路径仍使用严格当前交接。添加历史 blocked intake→新审计→确定性 split 的负控，确认下游标记仍为 nonclaiming。此项是原计划“不恢复旧资格”的必要实现，自审通过，范围限于该传播分支。
