# C 版：研究交付体验实施计划

日期：2026-09-27

状态：待实施；不表示 UI、导出或成本收益已经验证。

参考基线：`dev` / `e27352a`；实际实现基于已验收的 A/B 候选，先核对届时功能与工作树。
分支与提交遵循[总路线第 4.3 节](SCIENTIFIC_CONTINUATION_AND_SIMPLIFICATION_PLAN.zh-CN.md#43-分支与提交约定)。

## 1. 发布目标与边界

本文件拥有[总路线](SCIENTIFIC_CONTINUATION_AND_SIMPLIFICATION_PLAN.zh-CN.md) P5 的增强体验及对应发布验收。
[A 版](STABILITY_AND_SIMPLIFICATION_RELEASE_PLAN.zh-CN.md)负责数据/合同/交付链路正确，
[B 版](AUTONOMOUS_RESEARCH_RELEASE_PLAN.zh-CN.md)负责推进控制、最小状态/成果读取和通知。
C 让用户更容易理解研究、比较版本、检查证据、导出成果和判断成本，不重建这些基础能力。

完成标准：用户在现有 UI 可以回答“研究到哪、依据是什么、哪里变了、还缺什么、消耗多少”，
并取得与下游任务使用的对象一致的图件、表格及结论。

不增加科学 Agent 报表、不新增审批、不引入复杂工作图编辑器或 UI 进度数据库。
不因输入变化自动判定科学结论失效或自动重跑，不增加定时 LLM 总结任务。
必要交付缺陷在 A/B 修复，不能作为 C 的增强功能延期。

## 2. 用户旅程和数据归属

| 用户动作 | 应呈现的内容 | 数据权威 |
|---|---|---|
| 打开研究页 | 目标、当前模式、主要结论、运行/等待/需处理事项、更新时间 | B 推进状态及原 Run/Approval/Execution |
| 展开一个完整任务 | 阶段结论、限制、最终结果、助手贡献的现有记录 | 原阶段交付、封存结果 |
| 查看证据 | 确切版本、图表预览、原件下载、来源及用途限制 | Artifact 和交付清单 |
| 变更目标或材料后检查影响 | 已记录的直接/传递依赖、未知范围、值得重新判断的事项 | 冻结引用与版本关系 |
| 导出阶段或最终结果 | 明确时点的报告、证据清单、附件、限制及未解决项 | 所选确切结果快照 |
| 检查成本 | Root/负责人/助手/失败消耗、覆盖率和可比较范围 | A/B 的同一用量账本 |

UI 只投影，不持有新的科学 verdict。运行中阶段明确标为预览；运行结束、交付完整、科学目标达成分别显示。
相同显示名称不能把不同封存对象合并；缺少数据不以空白或绿色通过掩盖。
展示模型只传用户需要的数据，后台路径、端口、凭据和私有绑定不下发浏览器。

## 3. 实施包

按 C0 → C1 → C2 → C3 → C4 → C5 → C6 串行实施，每包提供可复核 Git 节点。
同一包复用现有视图/组件；删旧入口时保留实例选择、材料管理和必要配置等完整用户能力。

### C0：固定用户旅程、数据来源与验收样例

**依赖：A/B 已发布或有精确合格候选。所有权：现有 UI 路由、读模型与验收范围。**

- [ ] 核对 B 已提供的状态、控制按钮、结果、通知与用量，列出 C 真正新增的体验。
- [ ] 固定复用清单：既有 presentation/read model、管理页 SSE、`approval_ui/attachment_presentation.py` 和
  `artifact_agent/portable_bundle.py`；逐项记已有能力、缺口、实际消费者和保留/替换方式，不重复估算现成能力。
- [ ] 将每个展示字段映射到已有生产来源，识别缺测、分页、草稿、阶段与最终封存的区别。
- [ ] 固定已知正例、科学负结果、缺数据、目标修订、同名异物、长任务历史等小型自包含样例。
- [ ] 定义页面获取量、附件预览和刷新配置边界；不通过提高后端全量扫描上限改善体验。
- [ ] 保存发布前用户旅程与读取成本基线，避免只比较截图美观。

**验收与 Git 节点：**字段来源和用户旅程明确，不能读取的值标明缺失；不新建通用图模型或第二套状态表。

### C1：研究总览与完整任务视图

**依赖：C0。所有权：既有 UI presentation/read model、页面组件。**

- [ ] 总览组织目标、主要结论及限制、正在进行的完整任务、等待条件、下一项需用户处理事项。
- [ ] 任务内部阶段按需展开，区分预览与最终封存；不把一个实验显示成多个独立审批任务。
- [ ] 使用 B 的暂停/恢复/停止/接管处理，不复制状态机；查询页面不隐含取得调度权。
- [ ] 已有助手贡献记录可展开，缺少采用证据时如实显示，不能要求 Agent 补新的“助手采用表”。
- [ ] 复用既有 SSE 与增量/分页读取，避免一次加载全实例历史；显示刷新时间及部分读取，断线不显示为任务失败。
- [ ] 保留实例切换、原材料、审批和设置入口，明确当前作用范围。

**删改：**重复状态卡片、各页面独立推断的运行模式及重复轮询。
**验收：**正常、等待、失败、暂停、负结果和缺数据均可解释；浏览不调用模型、不派发任务。
**Git 节点：**研究总览与完整任务视图，沿用 B 的控制语义。

### C2：图件、表格与原件的一致阅读

**依赖：C1、A 的交付读取接缝。所有权：现有附件呈现、下载及插件展示扩展点。**

- [ ] 复用 `approval_ui/attachment_presentation.py` 的生产读取路径，只补 C0 确认的缺口；
  图件、CSV/表格、结构化结果和诊断附件从同一确切交付清单发现，避免每种 Operation 再维护独立列表。
- [ ] 预览显示对象版本、来源及用途限制；下载原件与下游引用保持一致，不按同名最新文件替换。
- [ ] 表格分页、图件按需加载，大文件流式下载；预览超限仍提供可用下载入口，不缩小合法存储/提交额度。
- [ ] 通用类型由核心展示，领域说明由已声明插件扩展提供；未知类型给元数据与下载，不强行解析。
- [ ] 处理缺失、撤销访问、损坏或不支持预览；预览失败不误报科学封存失败。
- [ ] 对不可信 HTML/SVG/文件名沿用或补足现有安全呈现和路径约束，不让附件执行页面脚本。

**删改：**按 Operation 名拼附件路径、重复图件列表及“只查最近同族结果”的展示规则。
**验收：**阶段/最终图件、CSV、未知类型、同名异物、长表和恶意附件；UI 下载与下游读取校验同一对象。
**Git 节点：**统一证据浏览。若发现基础交付错误，归回 A/B 对应 owner 修复，不在 UI 加补丁掩盖。

### C3：版本对照与变更影响提示

**依赖：C0 的精确来源映射、C2 的对象读取。所有权：已有引用查询与 UI 对照视图。**

- [ ] 对照用户选择的两个确切目标/材料/结果版本，显示已知差异和来源，不按时间猜前后关系。
- [ ] 沿已保存的输入引用、审查 subject 和派生关系标记可能受影响的直接/传递消费者。
- [ ] 缺少依赖关系时显示未知范围，不推导“未受影响”；遍历有配置上限、分页和截断说明。
- [ ] 区分“输入版本变化”“尚未对新版本审查”“科学结论需要重新判断”，不自动合成失效 verdict。
- [ ] 用户要求重新判断时，通过既有研究入口传递准确对象和差异；不静默重跑或复用旧审查批准新版本。
- [ ] 对照页面为只读；执行修订仍服从 B 的调度所有权与现有操作合同。

**删改：**按名称/最新版本比较的旧逻辑、重复关系存储；不建设可编辑科研 DAG。
**验收：**直接、传递、缺失关系、截断和相同内容不同身份；旧成果可读，不会自动触发新外部作业。
**Git 节点：**有依据的版本对照和影响提示，明确不是科学有效性判定器。

### C4：阶段快照、最终报告与成果导出

**依赖：C1–C3。所有权：既有封存结果/附件读取和报告呈现。**

- [ ] 从用户指定或目标结束时的确切结果集合生成阶段快照/最终报告，包含目标、结论、限制、证据和剩余问题。
- [ ] 报告是已有内容的确定性编排；无现成综合结论则标明缺失，只有明确需要新科学综合时才使用普通任务。
- [ ] 快照固定源引用和生成版本；后续数据变化不悄悄改写已导出报告。预览未封存材料不能冒充最终证据。
- [ ] 先核对现有 `artifact_agent/portable_bundle.py` 的格式、身份、包含范围及消费者；可等价复用的清单和打包能力直接使用，
  完整迁移包与用户科学报告不能混用；缺口通过既有 owner 的窄扩展解决，有实际消费者才引入新格式。
- [ ] 导出说明附件包含或省略范围、完整性信息及原始引用；不把签名回执、内部状态、凭据和私有路径打入报告。
- [ ] 按配置选择附件并流式打包，检查存储/时间预算，超额给出明确结果；不整包读入内存或暗中截断。
- [ ] 必要时提供可重试的工程导出任务，重试复用同一快照，不重新触发科学研究。

**删改：**独立拼装的 UI 报告、要求 Worker 重写同一结论的模板、与原件不一致的临时副本。
**验收：**导出后可核对确切引用与文件完整性；缺数据、负结果、阶段预览、部分附件和导出中断有准确说明。
**Git 节点：**确定性报告与成果导出。导出不是新的科学封存或批准流程。

### C5：成本、人工介入与收益对照

**依赖：A/B 用量及状态记录。所有权：现有观测投影、UI 成本视图。**

- [ ] 按目标、完整任务及角色展示实际输入、缓存输入、输出、调用次数、等待/运行时间与失败消耗。
- [ ] Root、负责人、助手可以展开；总数去重，缓存输入按提供方语义呈现，不再额外加一次。
- [ ] 标明观测覆盖范围、未归属调用、缺测和重启影响；不以换线程后的局部数据冒充全目标消耗。
- [ ] 展示有记录的人工介入、恢复和无变化唤醒，不要求 Agent 填写额外绩效字段。
- [ ] 对照只接受模型、任务输入、权限、预算、评分方法等条件明确的记录；不匹配时解释差异，不能直接宣称收益。
- [ ] 默认展示资源计数；若提供金额估算，价格来源、版本/日期与缺测必须明确，价格配置不可硬编码。
- [ ] 展示与导出复用同一观测来源，不新增计费账本，不把回包字节折算成真实 Token。

**删改：**多页面不同口径的 Token/成本求和和重复观测扫描。
**验收：**缓存语义、失败、助手、重复快照、缺测、不同模型以及不公平对照；收益未证明时明确标注。
**Git 节点：**成本与收益对照视图。读页面不产生额外模型评估请求。

### C6：浏览器验收与独立发布

**依赖：C1–C5 定向验证通过。**

- [ ] 以 A/B 的精确封存样例验证所有 UI 路径，再对本候选补一次真实新产物的出现、预览、下载和下游消费。
- [ ] 浏览器覆盖绑定实例、任务展开、图表、待处理事项、版本对照、导出、成本和 B 控制入口；
  同实例多读取会话复用 B 的规则，浏览与切换页面不隐式夺取调度权。
- [ ] 受控注入长历史、分页、失联、缺附件、预览失败和导出中断，不破坏真实活动实例。
- [ ] 安装构建只共享执行一次；小页面修改不重复跑真实求解器，只有领域执行接缝改变才补相应验证。
- [ ] 比较读取请求数、响应体积、峰值内存和定位结论所需步骤；不把视觉变化自动算成 Token 节省。
- [ ] 保存实际安装候选、配置差异、支持的导出格式和已知限制；历史证据与导出文件保持可读。
- [ ] 回滚主要切换表现层，旧版本不支持的新导出仍保留；涉及读模型迁移先验证兼容，不倒退研究事实。

**Git 节点：**C 发布候选与用户旅程验收索引；A/B 回归范围和未覆盖项明确。
