## 1. 目标与职责

在现有服务端口提供绑定 ResearchInstance 的研究工作台，完成三类页面：实例概览与轨迹、人工审批、
实例归档管理。参数和证据是前两类页面共用的视图。用户无需阅读大段 JSON，就能了解研究目标、当前任务、
已经得到什么结论、结论的适用范围、关键参数和来源，以及一次审批实际授权什么。

控制层从已有权威记录自动建立页面和节点关系；科学 Agent 继续负责科学判断，沿用原有输入和封存输出。
不增加轨迹 Agent、审批报告 Agent，不让原角色重复填写参数、引用、进度或摘要。审批辅助首先复用现有
独立审查与结果分析；本版不新增 AI 审批解释功能。

文档职责：本文件定义新功能的拟议范围；本目录 README 标明进度；既有计划、审计、科学成果保持原样。
实施完成后才更新架构和安装文档，不能把本计划提前当作当前系统能力。

## 2. 源码事实与必须保护的边界

| 当前事实 | 实施约束 |
| --- | --- |
| `approval_ui/app.py` 已有同端口实例页、审批页、原件下载和本地管理 capability | 扩展现有 HTTP 服务，不增加独立服务、端口或前端构建平台 |
| `approval_ui/render.py` 对 `json_value/json_tree` 主要用 `<pre>` 展开 | 修改人类阅读层；原始内容仍可按需展开或下载 |
| `schema/approval.py` 的 `review_document`、subject 集合等进入不可变请求身份 | 不改已封存审批请求，不为了排版修改执行 projector、审批 Schema 或编译身份 |
| TCAD 执行 projector 已保存执行资源、项目、独立审查、resolved inputs 等引用 | 从这些精确引用读取上下文，不重新询问 Agent，不按同 Schema 选择最新记录 |
| `runs.py` 有 Run 时间、绑定、诊断事件；`executions.py` 没有保存每次状态迁移时间 | 复用原始事件；缺失的历史不能补造成精确时间线 |
| `scheduler_bindings.observe_state_changes` 只保存上次观测状态 | 不能将它称为完整历史日志，也不能让页面依赖短窗口的 Root 摘要 |
| 现有 HTTP GET 整段持有 maintenance 共享锁 | 增量推送等待不能持有该锁，避免阻塞维护和业务写入 |
| Artifact/引用及审批决定有禁止修改、删除的数据库约束，CAS 跨实例共享 | 归档使用专用维护迁移路径；普通写入约束不变，共享记录保留，永久删除后置 |
| 参数模型已有 selected/reported value、条件、epistemic_status、source catalog、定位与 accessed_at | 直接展示已有事实；缺失来源、默认值依据或不确定度如实显示未知，不新增输出准入 |

### 不得退化的能力

1. Operation catalog 是唯一行动权威；不新增科学 Operation、固定阶段状态机、自动科学路由或浏览器直调 Worker。
2. preflight 管输入准入、提交管输出；本次不新增科学字段必填、机械登记、参数覆盖率或展示完整性拒绝。
3. Run 四态、不可变绑定、原始输出、资格与 current、独立审查和人类授权语义保持。读取历史不恢复其资格。
   显式归档允许停止该实例的调度并移动其存储，但不重写研究事实、不影响未归档实例。
4. 原审批 URL、到期刷新、精确请求/subject 身份、决定单次提交、旧版只读行为保持。新视图不能扩大批准范围。
5. `resume_from`、`draft_from`、Agent 复用、新 Agent 接手、用户原文绑定、紧凑 handoff 与选择性 status 读取保持。
6. 日志同步、求解终态、产物收集与恢复保持分离；浏览器刷新不调用 sync、collect、start 或外部求解器。
7. 工作台不可用时，已有控制与科研调用继续工作；轨迹缓存或领域展示失败不得使 Worker 提交失败。

## 3. 具体实现结构

### 3.1 一个读取服务，三个页面，共用参数与证据组件

```text
现有不可变 Artifact / Run / 审批 / 执行 / 实例绑定
                  ↓ 精确引用、分页只读
        实例读取服务 + 纯函数展示映射
                  ↓
  概览与轨迹        人工审批        整理页面
                  ↑
       可重建的视图缓存与增量更新游标
```

新增的 `approval_ui/read_model.py` 统一读取实例所属记录、精确父链、封存摘要和错误事件；
`view_models.py` 只表达页面数据，不成为科学模型或 Operation 输入。HTTP 路由不各自拼一套来源规则。
需要的分页查询放在原服务所属模块，不让渲染函数直接访问数据库或服务器路径。

领域排版使用一个很窄的可选展示扩展：新增 `scidiscovery.instance_views` entry point，只有通用科研和
TCAD 两个提供者。每个提供者按已知 Schema 版本将已读取的记录映射为正文、参数行、来源定位和图件引用。
接口只接收不可变数据及已授权引用集合，不接收 runtime、执行器、数据库写句柄或 Worker 工具。
扩展在 UI 中惰性加载，独立于 `scidiscovery.plugins` 的 Operation 编译；不增加第二行动目录。

通用提供者放在 `src/scidiscovery/general_science_views.py`，TCAD 提供者放在
`plugins/tcad_artifact/tcad_artifact/instance_views.py`。不把 TCAD 字段判断写进通用 HTTP 渲染器。
未知版本或缺少插件时退回安全字段阅读和原件下载，显示具体展示缺口，不以新版 Pydantic 模型重新准入历史对象。

展示映射不允许返回任意 HTML/JS。所有事实必须保留原记录引用和 JSON Pointer/原件定位；重复引用由控制层
自动解析。来源关系解析失败，只影响对应信息的展示，不能悄悄替换对象或改变科学资格。

### 3.2 数据归属和版本

| 页面内容 | 唯一事实来源 | 不允许的替代 |
| --- | --- | --- |
| 实例名称、管理描述 | ResearchInstance 元数据 | 将最新管理描述当成旧实验原始目标 |
| 总体研究目标、本轮目标、后续目标和条件 | 当前选中节点绑定的原始 objective、正式计划及精确父链 | 依名称、相似文本或最新时间猜一个目标 |
| 当前任务与多个活动分支 | 该实例的实际 queued/running Run、待审批及未结束执行 | 强行选出一个科学优先级最高的任务 |
| 阶段结果与限制 | completed Run 的封存输出，含正式 summary/conclusion、limitations/gaps 和 signal | 子 Agent 聊天、草稿、AI 新摘要 |
| 审查意见与有效性 | 原对象的匹配审查、当前资格记录、历史决定 | 将 completed、pass、qualified、执行成功合并为一个“有效”标记 |
| 参数、实验条件和引用 | 精确计划、参数族、来源目录、封存实现/执行清单中的已有字段 | 从代码全文猜关键参数，或要求 author 为网页再填一次 |
| 错误与日志 | 原 Run 的完整分页诊断、scoped diagnostic、已同步日志和已收集原件 | 从最后一条 reason 推断完整失败过程 |
| 执行状态和可恢复性 | 现有 execution 状态、收集状态和 recovery 两个标记 | 将未观测当作成功、耗时为零或没有错误 |

审批页的“本次审批依据”只沿冻结 subjects 及明确的不可变引用读取。实例最新进展可作为单独导航入口，
不混入审批依据。上下文补读不改变 subject 集合、审批请求哈希或授权对象。
若父链存在歧义或缺失，显示是哪条引用无法取得；不选择另一个同类记录来凑齐页面。

### 3.3 页面与 HTTP 接口

沿用 `/instance/{id}`、`/review/{id}`、`/history/{id}`、`/subject/...`，旧地址继续可用。
新增接口仅服务浏览器，命名在实施时按现有路由规范固定：

| 接口 | 作用与写入范围 |
| --- | --- |
| `GET /api/instances/{id}/overview` | 目标、当前任务、最近节点的紧凑视图，只读 |
| `GET /api/instances/{id}/nodes?cursor=...` | 节点分页，默认 30 条，最大 100 条；不内联全份成果 |
| `GET /api/instances/{id}/nodes/{key}` | 选中节点、依据、阶段结论、精确前后继；原件和诊断按需读取 |
| `GET /api/instances/{id}/events?after=...` | 有界 SSE 更新，内容为变更节点定位和游标，不发送整份成果 |
| `GET /api/instances/{id}/evidence/{key}` | 已授权精确引用的参数来源、原件或安全图件；不接受文件路径 |
| `POST /api/instances/{id}/display-preferences` | 列表显示偏好；只写 UI 数据，不称为归档 |
| `POST /api/instances/{id}/archive-preview`、`archive` | 预览并确认后，执行第 6 节的实例资料迁移 |
| `POST /api/instances/{id}/restore-preview`、`restore` | 核验并恢复精确归档版本；不自动重启任务、绑定会话或重新执行 |
| `POST /api/maintenance/cleanup-preview`、`cleanup` | 只检查或清理 UI 自有缓存/临时文件，返回精确范围和实际释放量 |

节点详情中的错误列表沿用现有诊断分页语义，保留原错误码、字段路径、工具、归属 Run 和日志入口。
列表、错误、源文件分别懒加载，不在首次页面响应展开实例全目录。长文本保留“查看完整原文”。
首屏结构化数据目标不超过 256 KiB（图件另行懒加载），到达上限必须给出分页或继续读取入口。

访问沿用现有 loopback 服务的信任边界和管理入口。新详情/图件/API 使用由本地管理 capability 建立的
实例范围浏览器访问凭据，明确区分读取、界面整理与维护范围；不以知道 instance_id 作为读取凭证。
`mcp_root_instance_routes.py` 的 `instance_current` 在已绑定且 UI 配置完整时同样给出既有管理 URL；
验证补发入口前后控制记录不变、过期入口可换新以及无 UI 配置的旧调用兼容。
实现放在独立 UI access 模块，复用现有加密库和本地密钥，不改变旧 capability 的格式和含义。
审批 token 仍只授权原审批对象及其明确关联上下文，不自动授权整个实例，也不能用于清理。
现有无凭据概览最多维持原元数据可见范围，不因此开放成果、日志或引用原件。

所有 POST 保留 Host/Origin、CSRF、输入大小和明确用户动作要求；整理权限不能提交科学决定。
归档与恢复使用独立维护权限和精确预览版本，不能仅凭读取凭据执行。
不自动请求外网图片或下载引用；外链仅允许安全协议，禁止携带本地 token，设置不发送 Referrer。
图像仅对已登记 PNG/JPEG 等安全格式提供有界预览，限制字节和解码尺寸；HTML/SVG/未知 blob 保持下载。
不新增通用服务器路径读取接口，不将任意 Agent HTML 作为页面执行。

## 4. 审批页的排版和参数证据

页面从上到下按用户作决定的顺序呈现：

1. **顶部任务摘要**：实例、总体目标、本轮目标、正在审批什么，以及同意/拒绝后由现有合同允许什么。
   文案依据实际 ApprovalRequest 的问题、选项与副作用合同；不能暗示“批准即已经执行”。
2. **主要依据**：正式设计理由、匹配的独立审查摘要、未解决缺口和适用边界。保留原话及来源跳转。
3. **关键参数与条件表**：按材料/物理条件/实验变量等已有分类分组；异常、假设和缺省来源信息常显。
4. **图件与结果对照**：显示已封存的参考图、仿真图、残差诊断图，注明案例、坐标/单位和来源；
   第一版不在浏览器重新做科学评分、拟合或图像抽取。没有合适图件时明确未提供，保留原数据下载。
5. **执行范围**：执行器、实际案例范围、入口、资源与时限、预期产物和外部操作。
6. **决定区**：沿用原选项、理由和确认规则，视觉上固定可达；原始 JSON/引用清单折叠放在页末。

桌面采用主内容加窄侧栏，侧栏显示决策对象、版本和操作；小屏改为单列。表格有固定表头、单位列、
可展开来源，避免长 ID 挤占主要内容。错误、假设和审查结论同时使用文字和视觉标识，不只依靠颜色。
键盘可操作；即使 JS 失败，正式审批表单和原件阅读仍能使用。

参数行至少呈现：参数名称、选用值、单位、适用条件、所在案例/变量范围、事实类型、来源定位、
不确定性说明、选择理由。底层原始值和文献报告值分开展示，避免单位转换或选值掩盖来源差异。

来源与不确定性分成独立维度：

- **获得方式**：明确记录为网络快照时标“网络检索”，展示 original/final URL、accessed_at 和保存原件；
  有 DOI 不自动等于本轮从网络检索获得，登记时间也不代替访问时间。
- **科学依据**：论文事实、用户给定、推导、工程假设、已声明的工具默认值等，按现有记录显示。
- **不确定性**：原记录给出范围/候选值就原样显示；只给定性假设则显示原说明；未给出则标“未提供估计”。
  工具默认值必须显示默认来源、版本（有则显示）及适用性未证实的限制，不标成实验测量值。
- **精确出处**：作者/标题/年份/DOI 或网页、页码/图号/表号/locator、封存 Artifact 跳转。
  当前没有定位或默认值声明时标“来源未记录/是否默认未知”，不自行补造，也不阻断原有任务。

同一参数在不同条件、案例或版本下不合并成一个“权威值”。展示使用精确计划/包中的实际选用值；
若实现未登记该参数或无法与计划建立明确对应，分别列出并说明无法确认实际采用情况。
本版覆盖现有通用实验变量和 TCAD 参数结构；未来 AI 研究已登记的超参数可使用相同表格，
不在本版实现新的 AI 实验后端或通用代码参数抽取器。

## 5. 控制层自动生成轨迹

### 节点与阶段

节点包括已有 Run、确定性成果转换、审批和执行；引用边来自实际 bindings、Artifact 父链和执行审批关系。
不能因为一个转换没有 Run 就漏掉其产物。只有存在明确父链时才按计划/修订归组，否则列为未归组节点。
科学阶段取正式计划中已有的阶段表述；没有时用操作类型展示，不从目录顺序推导必经科研流程。

每个节点显示：任务目标、输入来源、操作状态、正式结果摘要与限制、独立审查状态、执行/收集状态和
后续实际节点。主轨迹默认显示阶段成果和关键事件；工具调用、拒绝、超时、错误及恢复记录在节点内展开。
同一 Agent 跨 Run 复用时仍按原 Run 归属展示，保留 recovery/draft/resume 链，不按 Agent ID 合并错误。

“completed”“审查 pass”“当前可作为依据”“已执行/已收集”分别表达，不生成综合可信分数。
历史资格变化不禁止浏览；同时展示当时匹配审查和当前资格，不能让旧页面暗示仍可授权执行。
草稿只能进入明确标注的工程恢复信息，不作为已完成科学结论。

### 增量更新与存储

由 UI 服务内**一个**有界读取任务维护 `state_root/ui/workbench.sqlite3`，保存展示设置、缓存版本、
节点来源定位和更新游标。科学内容仍在原始记录中，缓存不成为新事实或调度状态权威。
没有浏览器订阅时不持续解析成果；有订阅时只轮询元数据，初始建议间隔 2 秒，按实例去重、分批处理。
终态摘要只在节点首次打开或已变化时按精确版本读取。禁止每个页面各起一个全库扫描器。

有原事件时间使用 source_time；读取任务发现变化时另记 observed_at。历史执行缺少中间事件时，
只能显示持久记录中的现状和首次观测时间。服务离线期间漏过的瞬态不补造；界面注明观测范围。
本版提供节点成果与状态变化轨迹，不承诺完整命令重放、每次执行迁移的原始时间或未接入的 token 计数。
缓存重建可恢复权威节点和已有诊断；仅 UI 观测得到的旧时间不能凭空恢复，需说明该段观测历史缺失。

SSE 只发节点变更通知与有界游标；支持断线续接、去重和游标过期后的局部重载。每服务最多 8 条长连接，
单连接按 25 秒有界退出后重连；慢客户端丢通知后重载，不积累无限内存队列。
读取短事务结束即释放 maintenance 共享锁和数据库连接，等待及网络写入在锁外。UI 缓存异常只在页面/服务
日志报告；不向 Run 写一个伪失败。SSE 不可用时回退有界轮询/手动刷新。

## 6. 先做实际归档，再做永久删除

### 6.1 固定目录与完整范围

归档的含义是**迁移实例资料**，不是只隐藏、关闭实例或另存一份备份后保留所有活动副本。
固定根目录为当前运行时 `project_root/.scidiscovery-archive/instances/`，每个实例使用不可变 instance_id
作为子目录名，不接受浏览器传入任意路径。project_root 使用已有工作区配置，不新增环境变量。

```text
<project_root>/.scidiscovery-archive/instances/<instance_id>/
  manifest.json         归档版本、原身份、完整清单、大小与摘要
  records/              实例所属的控制数据库记录及原 Schema 信息
  objects/              原始输入、输出、引用文献、参数、图件和其他 CAS 内容
  workspaces/           各 Run 源码、草稿、检查点、尝试修改和失败现场
  executions/           本地执行交换资料、收集结果、过程日志与恢复资料
  diagnostics/          实例关联的详细诊断及错误记录
  views/                实例轨迹展示资料、偏好与已有缓存
```

所有历史版本、失败 Run、审批请求/决定/尝试记录、用户原文、current/资格与语义绑定都属于归档内容。
不能只搬最新成功成果。按清单流式搬运，不让 Agent 汇总、挑选或重写资料。

与其他实例共同使用的内容，归档包保存完整可恢复副本，活动侧保留其他实例仍需要的原件；只移除被归档
实例的活动关联。共享与独占字节分别计数，不能将共享原件误称为已经释放。引用判断使用所有未归档实例
的绑定、父链、Run/执行及恢复根，不只检查 CAS 是否有 registry 行。

范围是框架实际管理的实例资料，包括从 VM 收集到本地的输出和日志；不移动用户工作区的 Git 源码、
外部手工文档、服务程序、密钥或其他实例的数据。尚有求解、收集或后台写入时不能归档；缺少应收集产物时，
先通过现有收集/恢复路径处理或明确标记历史缺失，不能宣称迁移补齐了本来就缺少的证据。
本版不更改远端 VM 文件；远端未纳管临时文件单列说明，不暗示其已经移到本地归档目录。

### 6.2 归档操作与中断恢复

新增 `service/instance_archive.py` 统一负责清单、迁移和恢复，UI 只发起用户确认的操作与显示进度。
维护记录存于 `state_root/maintenance/`，**不属于可随意清理的 UI 缓存**。不新增科研 Operation 或 Run 状态。

P0 的归属清单必须逐项落实下列存储，不以“扫描实例目录”代替：

- 五个控制库中实例/全版本语义绑定/current、Run/input/output/receipt/tool evidence/activity/recovery、
  审批请求/决定/attempts/nonces、执行 request/decision/result、Artifact/envelope/links/idempotency；
  兼容已有旧表时保留其原始记录，不按新版模型重写。
- local workspace 的 `.bindings` 映射、`workspaces/workspace_<uuid>`、`recovery/<digest>`、quarantine
  和原失败目录；共享 recovery 按所有 Run 引用保留，不能从路径名字猜对应关系。
- hardened 的独立 workspace 根、dispatch 记录、传输占用资料；execution-exchange 内的收集/观测/日志；
  TCAD 插件在运行配置中明确管理的 `executor-results`、`local-tcad-debug` 等本地资料。
- `engineering-diagnostics` 中按 instance/execution scope 精确归属的文件；`worker:unbound` 和其他
  无法证明属于目标实例的系统级记录保留并单列，不声称已迁移，也不要求 Agent 重新登记归属。

归档 manifest 摘要还保存在维护索引中；恢复只接受本服务登记且摘要匹配的归档，不接受浏览器上传任意
数据库或修改任意归档路径。需迁移的已登记对象原件缺失时保留缺失清单，不能用空文件替代或伪造原始摘要。

1. **预览**：列出具体实例、历史对象/文件数、数据范围、共享保留量、预计迁移量、临时磁盘需求、
   缺失资料和活动写入者。未归属文件不按目录相似性猜归属，不静默丢弃。
2. **用户确认**：确认精确预览版本和归档路径；有 queued/running Run、未终止执行、收集或调试写入者时
   返回具体 busy 原因，不自动杀进程。旧待审批请求随归档保存，不能继续在活动入口做决定。
3. **固定范围**：短暂取得现有 maintenance 排他锁，重新核对快照及所有写入者，先保存原实例开关/会话的
   精确历史快照，再关闭并解绑目标实例。对该实例设置持久维护门，门的检查位置见下表。
   已确认终止、无人写入的失败 Run 和 recovery_pending 草稿必须归档，不能因“失败/待恢复”被漏掉。
4. **准备归档**：在固定根目录的临时目录写入完整数据库记录包和文件清单，复制/迁移按文件系统边界处理。
   跨文件系统必须先复制、同步落盘并校验，不能把 rename 失败当作成功。逐文件校验大小/摘要、关键身份和
   引用闭合；磁盘不足或校验失败时保持活动原件。准备阶段可解除全局长锁，目标实例保持关闭且有维护租约。
5. **切换归属**：再次短暂排他并复核，原子发布已验证归档目录和归档定位；按记录所属关系移走活动数据库中
   目标实例独占的完整历史，仅保留实例归档索引及其他实例依赖的共享记录。移除活动副本只能发生在归档已
   验证持久化之后。文件系统与多数据库无法一笔提交，必须有持久维护日志和可重复完成的切换步骤。
6. **收尾**：精确清理已完成迁移的活动副本，显示实际结果。中断后根据维护日志继续或回退，不重做科学任务。
   数据库切换完成而活动文件尚未移除时标“收尾中”，不能误报资料丢失或彻底完成。

控制库当前有 append-only 触发器。迁移采用**仅维护连接内、精确对象集合的事务路径**：在排他锁下检查
数据库版本与 DELETE journal 前提，通过 ATTACH 将相关数据库纳入同一事务；保存必要的禁止删除触发器定义，
仅在该事务内临时处理迁移所需删除，提交前恢复原触发器并核验保留集、外键与原定义。普通更新限制不变。
任何失败必须回滚记录和触发器；不得全局永久关闭约束，不换数据库文件导致存量连接访问旧 inode。
若现有某条写入路径绕过维护锁，须先补上该存储维护边界或将该后端归档明确标为未支持，不能冒险在线搬运。

**B1 的确定修改范围：** 新增 `service/instance_maintenance.py` 作为唯一实例存储维护门，所有调用者复用
同一份租约读取和锁实现。它只判断用户已发起的归档/恢复占用，不判断科学输入或输出是否合理。
普通未维护实例走原流程；维护忙碌是管理操作诊断，不能写成科学 Run 失败。

| 实际写入入口 | 必须实施的接入与行为 |
| --- | --- |
| `mcp_daemon.py` / Root 的现有请求边界 | 保留既有全局共享锁；归档准备完成后闭合实例会话入口，不能从旧缓存绕过 closed/维护门重新调度 |
| `approval_ui/app.py` 的 decision 和 refresh-access | 在写入前按 approval 精确 owner 检查维护门，锁覆盖决定/刷新整个写入；旧表单在归档期间只能得到明确归档提示，不能修改目标记录 |
| `mcp_local_worker.py` 与 `mcp_hardened_worker.py` | 将维护保护放在最外层，覆盖调用前后 timing、错误记录、实际工具动作及 hardened transport 收尾。打开新 assignment 按新选中 Run 判断，不能误用旧 Agent 的 `_run_id`；后续调用按原 Run 所属实例判断 |
| `runs.py` 的选中 assignment 到工作区创建 | 在精确 Run 已选定、尚未写入前检查同一维护门；不改变 Operation 工具 Schema，不给科学输出新增字段或登记要求 |
| `execution_collection.py` 的子进程和监督线程 | 从实际获取 active/collection 锁到最终日志落盘、释放占用的整个生命周期持有目标实例写入保护；不能在 execution 变 collected 时提前解除。新 collect/debug 也必须经同一维护门 |
| UI 轨迹读取任务及视图缓存 | 归档准备时停止目标实例活动缓存写入，切换后读归档；其他实例更新继续。维护进度写在独立维护目录 |

固定锁顺序为：全局 maintenance 共享锁 → 目标实例共享锁 → 后端 transport/collection 锁 → 单服务局部锁
与数据库事务。归档先以非阻塞全局排他做活动核对和标记，准备期间只冻结目标；最终切换同样短暂排他。
已有后台收尾持有保护时返回 busy，不长时间持全局排他等待。避免 hardened 外层已持 transport 后再在
父类倒序申请维护锁；所有相关异常处理和 finally 中的持久写入必须仍在保护内。

维护门拒绝的迟到 Worker 调用直接返回管理诊断，原实例不再追加 timing/error；需要记录该拒绝时写
维护日志而不是已迁移的 Run。正常工具错误仍按原机制完整记录。未知对象归属不能猜配给另一实例。

Run 终态和 execution.collected 只作信息，不作“已无人写入”的充分证据：归档还要试取原 active/collection/
transport 锁、核对已有受控计算进程及收尾状态。`local_process_observation.py` 无法证明 native writer 停止
时返回具体 unknown/busy 并保留原目录；不把无遥测当作无进程。首版覆盖现有 local/hardened 的已知本地
存储，预览遇到未列明的后端/配置/写入者时明确不支持，不能给部分迁移标完成。

服务重启后维护门不能仅因 PID 或时间过期自动消失；按持久迁移日志重新核对，提供继续/回退管理动作。
未确认切换结果时不开放目标实例。旧审批 GET 与科学历史仍可读取稳定原件/已完成归档，不能触发恢复。

归档管理信息是存储定位权威，仅限资料位置和维护进度；不记录或计算新的科学状态。归档后通过原实例页
进入只读资料视图，原审批链接仅可查看历史、不允许新决定；活动选择列表不允许直接续跑。
其他实例的原审批、读取、提交和执行保持正常。

### 6.3 恢复是归档的首版验收项

恢复前核验完整归档清单、软件/记录版本、引用和空间；同名同身份幂等，身份冲突明确列出，绝不覆盖另一
实例或偷偷生成新 Artifact 身份。按原字节与原身份恢复控制记录、原件、工作目录、绑定、草稿及诊断。
恢复过程同样使用维护日志，失败不破坏归档原件；活动副本全部验证成功之前保留可用归档。

| 记录类别 | 固定恢复规则 |
| --- | --- |
| 实例 active/closed | 使用归档冻结前保存的原状态；原 active 实例在全部核验后恢复为可选择且未绑定，原 closed 仍 closed。通过归档服务的定向事务恢复，不新增普通 reopen 科研命令 |
| 语义绑定、current/资格、旧 Run 与审批 | 原字节/原身份恢复，不重审、不提升资格、不延长截止时间；共享对象存在时验证完全一致，否则停止恢复并保留归档 |
| scheduler_sessions 与浏览器凭据 | 保存在归档中作历史，但不重新激活旧 session 或浏览器读取/维护凭据；用户选择仍走现有入口，不影响后来绑定到其他实例的会话 |
| 工作区与恢复目录 | 保存并恢复原 state_root、backend、local workspace root、Run→workspace 映射、原文件权限和共享引用。首版仅支持同一 runtime 原根目录恢复；根/后端变化或路径冲突给出明确不支持，不改写成果中的路径 |
| Hardened 运输租约、PID、锁与收集请求 | 保存历史记录但不重新激活 owner/lease/PID/FD，不回放后台请求；锁由新进程重新取得。过期 transport 内容可在历史中查看，不能被导入成活动占用 |

B3 实施涉及 `scheduler_bindings.py` 的归档恢复定向事务、`local_workspace.py` 的精确文件清单/映射、
`hardened_workspace.py` 的占用识别；不修改现有原始成果、不自动把一个旧 Run 变成新 Run。

恢复后实例仍由用户通过现有管理入口选择；不自动恢复已过期审批、不继承新的科学资格、不把失败 Run
改为 completed，不自动重启旧 Agent 或求解器。依原 resume/draft 规则继续，输入或合同变化仍走原机制。
完成“归档—浏览—恢复—接续”验证，才可交付归档能力。

### 6.4 清理和永久删除的顺序

首版可以清理 UI 自有可重建缓存，但归档目录、维护清单和归档资料绝不能被缓存清理包含。
缓存清理按预览、明确确认、重查占用、精确类别删除、结果明细执行，不接受任意路径，不跟随符号链接。

**永久删除下一版开发，本版不提供入口或隐含自动清除。** 后续删除针对已核验的归档实例，清除该实例
独占的全部历史、文件和缓存及其活动残留；共享原件保留其他实例所需部分。先用归档及恢复证明资料归属和
迁移清单正确，再复用该清单设计永久删除，不能以“不可变记录”作为永久无法删除用户实例的理由。

## 8. 验收：证明有用，也证明主干未退化

### 功能与反例

| 验收面 | 正例 | 必须保留的反例/边界 |
| --- | --- | --- |
| 审批身份 | 升级前创建的 pending/decided 请求仍按原对象显示与决定 | 换 subject、换版本、决定重放仍由原授权逻辑拒绝；显示元数据变化不重建请求 |
| 事实与版本 | 每个目标、参数和结论可定位原记录；旧审批固定旧依据 | 当前新计划不能替换旧审批依据；缺失引用显示缺口，不恢复历史资格 |
| 参数与图件 | 原值/选值、条件、来源类型、网页时间、locator、假设常显 | DOI 不自动标网络检索；空值不自动标默认；坏图件/未知版本不阻断其他内容 |
| 轨迹 | Run/转换/审批/执行均有节点，封存摘要仅引用一次 | completed 不等于科学成功；无遥测不等于无错误；观察时间不冒充发生时间 |
| 错误追溯 | 多于一个诊断页的错误可完整翻查，精确到字段/工具/原 Run | 不从截断 summary 冒充全部历史；旧错误详情缺失保留原缺失事实 |
| 接续与紧凑输入 | 原 user_context、resume/draft、新/复用 Agent 路径按原合同可用 | 页面/缓存/轨迹内容不自动进入 Worker 输入；原文不被 UI 摘要替代 |
| 执行与收集 | 浏览期间原执行同步/收集/恢复正常 | GET 不触发 start/sync/collect；超时、收集失败不成为第二次求解 |
| 权限与安全 | 同实例读取、合法决定、既有过期刷新正常 | 跨实例凭据、审批 token 越权、CSRF、脚本/路径注入和清理越界被拒绝 |
| 故障隔离 | 关闭工作台读取任务或清空缓存后原科研链正常；可重建页面 | 扩展抛错、缓存满/不可写、浏览器离线不改 Run 状态、不阻断提交 |
| 归档与恢复 | 全部实例资料迁入固定目录，浏览与恢复后的原身份/摘要/绑定一致 | 失败 Run、旧审批、用户原文、日志、recovery_pending 不遗漏；不移动其他实例或 Git 文件 |
| 迁移故障 | 文件搬运、记录切换、清理活动副本各阶段中断后能恢复；原触发器一致 | 未校验就删源文件、半套数据库提交、运行中搬运、恢复覆盖冲突必须被阻止 |
| 清理 | 明确确认后释放 UI 缓存；共享内容逐项说明 | 不清理归档、维护日志、原始科学资料；本版不存在永久删除入口 |
| 性能 | 有界首屏、节点分页、懒加载图件、断线重连 | 多浏览器不重复全库/全成果扫描；慢连接不持维护锁或堆积通知 |

调用、collected 后仍持锁写日志、native 停止观测失败、服务重启遗留维护任务；同时证明另一实例的读/提交/
执行正常。恢复覆盖原 active/closed、旧 session 已转属另一实例、跨实例共享 recovery、自定义 workspace root、
保留原目录的失败恢复源及 hardened 过期 transport。恢复后实际核对原 `resume_from`/`draft_from` 行为。

### Fig4 真实资料与用户可用性

使用当前封存的 Fig4 目标、计划、参数、实测图/仿真图、诊断和历史审批，至少验证一份执行审批和一份
证据/参数审批。任何对齐或机制结论均引用原科学输出；不为演示页面补写一个新的科学结论。

浏览器验收必须能直接回答：总体和本轮目标是什么；重要参数是什么、凭什么取值；哪些是默认/假设或未知；
批准将允许哪项动作；上一阶段结论及限制是什么；一次失败发生在哪里、是否已恢复。保存页面截图和
相关原记录定位供复验。排版验收使用实际长表、长来源、失败记录和窄窗口，不只用短占位数据。

回归在隔离状态目录走完整控制请求/审批/执行模拟/封存/接续，验证升级前请求和升级后请求两条路径。
现场先只读核对真实实例和历史轨迹；涉及新外部执行时仍由用户在原审批链决定，不因验收界面擅自启动
TCAD。真实科学接续是否开展单列为现场项，离线 UI 通过不称为 Fig4 科学目标完成。
归档的故障注入和恢复接续先用隔离测试实例，不能为验收擅自移动当前 Fig4 实例；真实实例的归档只能由
用户在管理页面明确发起。

### 资源与证据记录

所有测试、构建与浏览器进程串行，一次一棵进程树；不运行全量套件或 xdist。关闭无关 pytest 插件，
BLAS/OMP 线程设为 1；沿用 512 MiB 受控预算，测试分批并记录峰值和耗时。浏览器若在该预算下无法启动，
先明确记录资源阻碍并调整低资源验收方式，不擅自提高预算或并发硬跑。
每项记录源码版本、输入样例、预期、实际、错误细节和适用范围；不以总 passed 数替代权限、身份和真实页面验收。

## 9. 部署、回滚与停止范围

沿用现有安装流程和 HTTP 服务，打包新增 Python 模块与静态文件，使用原 state_root 下的 UI 私有子目录。
不新增 TCAD_STATE_ROOT、服务账户、VM runner 协议或远端组件；按本计划实施不需要同步 VM runner。
隔离 wheel 必须证明两个展示提供者、静态资源和旧审批接口均可用，不能只验证源码 import。

**B2 的部署改动：** `deploy/install.sh` 安全创建 `<project_root>/.scidiscovery-archive/instances`，按现有
服务账户赋予所需目录权限，拒绝符号链接或不安全路径；`deploy/systemd/scidiscovery-approval-ui.service.in`
仅为实际承载归档的 UI 服务增加该固定根的 `ReadWritePaths`。保留 `ProtectSystem=strict`、`ProtectHome=read-only`，
不开整个工作区写权限，不新增环境变量。安装/卸载/回滚不删除已有归档。源仓库忽略此运行资料目录。
在等效 systemd 沙箱下用隔离实例验证迁移与恢复及源码目录仍不可写；无 systemd 能力时如实单列未验收的
安装限制，不能用源码单测冒充部署通过。

未使用归档时，回滚至基线代码可忽略 UI 缓存目录；原科学库保持原格式。已经归档的实例不能让旧版代码
自动理解新归档索引：回滚前须用当前版本完成恢复并验证，或保留归档为离线资料并明确旧版不可续跑该实例。
禁止删除维护记录来假装恢复完成。未归档实例继续使用原库；展示缓存带版本号，升级时按需失效，
禁止对原科学记录执行“格式升级”。

本版明确不做：实例永久删除、任意工作区清理、可编辑工作流图、拖动节点改变绑定、浏览器自行
选择下一科学 Operation、AI 生成新审批意见、全量命令/推理/token 遥测、浏览器重新计算科学评分。
这些不作为本版的隐含依赖。

计划当前尚未通过独立审查；实施前审查两项：功能设计完善度，以及是否损坏原框架和自动科研流程。
具体重点是审批不可变身份、历史引用边界、插件展示与行动编译隔离、页面访问范围、推送锁行为，
以及归档全历史覆盖、事务触发器恢复、中断恢复和共享资料隔离。修订后须再次独立审查，通过后严格实施。
实施后对上述边界独立复核，不能只看前端截图宣布框架无退化。
