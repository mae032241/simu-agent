### N1：长时间运行基础

优先从现有意图、原生结果和封存记录推导状态：未启动、运行中、已结束待封存、已封存、结果未知。
避免持久化第二份可互相矛盾的状态。

恢复规则：

- 已封存节点直接继续；模型成功但封存失败只重试封存。
- 原进程仍在运行则重新连接或等待，不重复启动。
- 结果未知先核对原执行，无法核实时停止自动重放。
- 恢复不重置预算；预算修订需要明确的人类授权，通过控制入口留痕，角色不能自行续额。

分别记录推进启用时长、暂停时长和总经过时间；明确长作业等待如何计入时间预算。
N1 实施前冻结以下口径：实际原生执行和控制推进计入启用时长；暂停请求生效前已接受的工作仍计时；
无活动执行且已进入暂停时不计推进额度。控制器退出而原执行仍在运行时继续计时；无法核实终态时保守计时，
恢复不能把这段时间当成免费暂停。另报总经过时间，既有实例时间口径不静默重写。
推进额度以秒计；控制推进与原执行重叠区间按并集计一次。每场启动前冻结推进时长上限；
若设置总经过时间的绝对截止，也一并冻结并分别展示。暂停和停机不重置已计时量。
预算修订仅由外部操作者通过 CLI 显式发起，在无活动/未知执行且持有实例写锁时追加审计；
科学目标、模型配置和已有节点保持冻结。真实三场不依赖修订额度完成。
修订审计记录原上限、新上限、操作者授权说明与时间。
及时获取运行中用量并标明计量延迟，不能把滞后观测宣传为精确账单硬上限。
等待由控制层承担，结果到达再启动角色；首版验证本地任务事件，远端执行接线仍属于 C3。
原执行身份、结果和用量须由可持续记录的执行宿主持有，控制器重启按同一执行身份核对，不能只凭 PID 判断。
本地完成事件绑定确切原执行与返回角色并去重；原科学 `wait` 当前只表示停止并等待，不宣称已支持自动事件续接。
N1 的本地事件等待限定为已启动原生 runner 的完成通知，科学角色 `wait` 的自动恢复协议后置。
N1 真实 cov 仅验收已有科学链路与恢复；事件等待的异常覆盖使用无模型夹具，不新建通用长作业引擎。
N1a 退出证据见 [源码与安装验收](evidence/ROOTLESS_N1A_SOURCE_20261011.zh-CN.md)，N1b 见[计时与预算验收](evidence/ROOTLESS_N1B_ACCEPTANCE_20261011.zh-CN.md)。
实现拆为 N1a（持久原生 runner、同一执行核对与等待）、N1b（推进时钟和人工预算修订），分别审查和提交；
N1a、N1b 与 N2 全部通过独立审查并提交后，冻结同一候选，再执行下述剩余两场验收。N1b 完成不单独触发真实测试。

故障注入：启动前退出、执行中断连、模型结束后崩溃、封存失败、重复恢复、暂停期间重启。
退出条件：无重复执行、未知不算成功、恢复不增加额度。

能定位旧记录且保留适用条件。源记录保留，投影可重建。

### N3：W 内有界搜索

动作策略：

1. 执行失败时，在有限修复次数内修复。
2. 关键机制尚未筛选时，优先完成已批准的最小判别实验。
3. 有可改进候选时，在 H 范围内改进。
4. 连续无效、触及 H 边界或评估有盲区时，结束预算片并交给 A。

H 声明关键机制与探索承诺；A 可以调整优先级，延期应附理由和证据。
控制层执行已声明额度与边界，不从名称猜测机制等价性或科学价值。
首版不强制每个候选新开 Agent；在预算片边界用新上下文续接，测量是否值得增加派发成本。
最佳候选持续保留；最终提交替换由 A 给出依据，不由最新文件覆盖。

夹具覆盖：领先分支不无限挤占未处置承诺；重命名不构成新的机制记录；失败修复不清零科学计数；
代理无法观测目标条件时，不把无提升自动作为淘汰理由。

### N4：A 主导纠偏与强制刹车

A 每轮简短回答：新增认识、对全局目标的贡献、评估盲区和未处置机制、下一步动作及依据。

| 层级 | 触发与处理 |
| --- | --- |
| W 内局部搜索 | 连续无效或触及假设边界，交 A 判断 |
| HWA 科学循环 | 多次 A 判断无有效进展，要求 H 修订；未解决则暂停新增研究工作 |

有效负结果可算进展；等待、重启和查询不计无进展。
新文件、自报 advance、改写措辞不能自动解除纠偏；控制层只核对可机械验证的身份与记录，科学判断由 A 负责。
未知单独记录；持续未知可要求复核，不冒称已识别停滞。
暂停仍允许已接受工作的收集、取消和封存；人工继续不抹掉历史，不增加预算。
首版采用 A 独立判断加机械信号，不新增常驻哨兵模型。
触发阈值和解除条件在节点设计评审时冻结，真实场启动后不为通过验收调整。

夹具覆盖：每轮新文件但持续精修、有效负结果、合理等待、换名绕过、暂停时仍有活动执行。

### N5：先 cov 行为验证，再小时级恢复

以下是 N2–N4 完成后的验收设计，不属于当前 N1 三场之外已安排的真实运行。
先利用 N1 证据校准；新能力无法由旧场验证时，再单独确定最小场次和预算，不默认启动额外测试组。

第一场沿用 cov，整场 token 上限为 600 万；启动前根据前序实测成本冻结墙钟上限。
应观察完整 HWA、一次使用历史/候选状态的后续决策、最佳候选与失败记录可回读、无模型承担机械封装。
自然发生的无效重复按规定纠偏；未发生的刹车场景标为未观测，由夹具验证，不诱导科学角色制造停滞。

第二场在节点边界主动暂停并重启，验证不重复派发、预算连续、候选/失败边界/方向可恢复且不依赖旧聊天。
优先安排在同一已授权场次内完成恢复验证；若另开独立场次，启动前冻结并获得其预算授权。
本计划不自动累加第二个 600 万额度，不直接放大到一周或多组大规模评测。

判读规则：

- 更省且行为正确：继续扩大验证。
- 得分未提高但搜索/恢复改善：记为工程收益。
- 机械开销回升或重复工作增加：先删减设计，再决定是否扩预算。
- 单场涨分不证明稳定性；重复试验另行冻结条件和预算。

## 4. 执行纪律与后置范围

每个实现节点：独立执行 → 最小可信定向测试 → 独立审查 → Git 提交。
执行和审查默认使用 gpt-6.1-sol / high，非 fast；正式角色配置冻结并计入验收条件。
连续两轮修复仍暴露同类结构问题时，重新审查设计，避免继续叠加状态。
实现前先审查本计划，节点状态仅在退出证据满足后更新。

本轮交付能搜索、能记住、能纠偏、能恢复的最小闭环。
UI、完整功能插件/TCAD 执行迁移、旧链退役继续由 C3–C5 管理；跨项目经验库、常驻语义哨兵、
多 W 并行和大规模统计验证后置。不能将 cov 通过升级为这些能力的资格。
