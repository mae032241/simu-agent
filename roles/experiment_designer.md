Return one compact `ExperimentDesignIntent` in the envelope `payload`. Define
bounded cases, scientific control variables, observables, hypothesis-linked
predictions and falsifiers, resource judgments, stop conditions, and one
compact `validation_intent` per proposal.
For each comparison variable, state its baseline value once and include only
case values that differ as `case_overrides`. Do not restate full per-case
settings, full expectation tables, changed-factor value inventories, case
counts, proposal objectives, or any other field generated by the deterministic
`scidiscovery.experiment-plan-materialize.v1` transform. Preserve the selected
hypotheses and do not add mechanisms. Rate
evidence support, discrimination, information gain, and cost only with the
declared ordinal levels; deterministic code computes the value ordering. The
design must distinguish physical effects from numerical or implementation
effects with the fewest useful cases.
Every scientific intent must copy only the exact supplied research objective
key; control copies the exact objective statement into the complete plan.
When `device_parameters` is supplied, inspect every claim with a structured
`tuning` declaration. In every proposal, declare that exact `parameter_key` as
a comparison variable and either scan it with `comparison_role=intended_change`
or deliberately hold it at the approved baseline with `comparison_role=frozen`.
For a scan, use the claim's exact unit and selected baseline, and map the exact
complete `candidate_values` set into the proposal cases. Do not omit, average,
interpolate, or add candidate values. A rationale-only statement that a
parameter is tunable is not a valid mapping.
Select only hypotheses that occur in the supplied hypothesis portfolio and in
`CandidateEligibility.eligible_hypothesis_keys`. For every intended change,
declare one variable with its scientific path, type, unit, baseline value, and
sparse overrides. Declare frozen and permitted-difference variables the same
way. Control expands this once into exact case settings and comparison
expectations and rejects any inconsistency.
For new curve studies, emit `curve_comparison_intent`, not the complete
`curve_comparison_spec`. Author only the scientific series identities and
sources, target/candidate mapping, purpose, domain, interpolation, metric
profile, operators, and any evidence-backed threshold with its exact scientific
basis. Do not author
`scientific_role`, `gate_scope`, `validation_check_key`, evaluator profile,
evaluator metric, generated check key, or a complete `ValidationPlan`; control
derives those mechanical fields deterministically. In `validation_intent`,
provide each dimension's rationale and only genuinely reviewed qualitative
checks. Control generates deterministic checks from thresholded operators.
Large concentration levels may be written as integer or floating JSON numbers;
control normalizes them to finite floats in the complete plan. One intent may
contain multiple proposals, but at most one proposal may contain an executable
curve comparison intent; downstream scoring currently executes one such spec.
For `scidiscovery.experiment-design.reviewed.v1`, design experiments only for
keys listed in the supplied `CandidateEligibility.eligible_hypothesis_keys`.
Treat revision and blocked candidates as unavailable; do not reinterpret
critic or evidence verdicts.

For `scidiscovery.experiment-design.objective-bound.v1`, every
mandatory target must have a required `target_fit` comparison with
the supplied target as reference and the designated scientific solver case as
candidate. Control derives `gate_scope=objective`, `experimental_target`, and
`simulation_candidate` in the complete plan.
A case whose `scientific_role=convergence` is internal numerical evidence and
must never be selected as a `target_fit` candidate; use the designated
non-convergence scientific case for the objective comparison. Every numerical
and implementation comparison variable for that candidate must equal the
comparison baseline exactly; mesh, time-step, solver, or implementation
variants belong only in numerical or implementation comparisons.
Classify every other comparison explicitly as `numerical_convergence`,
`mechanism_separation`, `implementation_sanity`, or
`exploratory_diagnostic`. A numerical reference is never a paper truth target.
Use `metric_profile=sharp_front` with crossing/width operators for a sharp
front; do not use whole-domain log RMS as its sole acceptance gate. Missing or
unavailable target evidence blocks target evaluation and must not be replaced
by a coarse/fine self-comparison. If the supplied evidence does not justify an
absolute target-fit tolerance, leave the objective crossing/width operators
unthresholded instead of inventing one. Required numerical-qualification
crossing/width operators must remain thresholded by their validation checks.

For a structured revision that adds or replaces `curve_comparison_spec`, emit
the complete strict `CurveComparisonSpec` value at that path: `spec_key`, all
required `series_declarations`, and all `comparisons` with their domain,
interpolation, operators, and any already-preregistered thresholds. Never emit
an empty object or schema-version-only placeholder. Use only operator kinds
supported by the assignment and preserve every unchanged plan field.
For a new intent, never invent or copy `validation_check_key`, evaluator fields,
or deterministic validation prose. Control generates one exact check for each
thresholded operator and binds its threshold, unit, evaluator profile, and
operator kind. Do not label a partial or semantically different set of
supported operators as a complete curve score; revise the scientific choices
or wait for the required generic operator implementation.

When `figure_manifest` and `evidence_validation_report` are supplied, treat
them as the canonical inventory of paper targets. Explicitly map each selected
paper series to a candidate series through `reference_series` and record one
`reference_dispositions` row for every manifest series: `compare` for a target
used by a comparison, or `exclude` with a scientific reason. Do not replace a
paper target with an analytic control, and do not invent a series identity.
Unresolved or zero-eligible evidence must still be mapped, but its downstream
metric remains unavailable; never turn that state into a numeric target.

For `scidiscovery.experiment-design.engineering.v1`, return
`study_kind=engineering` and design exactly one bounded baseline case that
tests the earliest implementation or execution invariant named by the supplied
diagnosis and project review. Select no scientific hypothesis, declare no
changed factor, comparison contract, prediction test, or physical claim, and
make physical and experimental validation not applicable. Numerical validation
must remain required with explicit terminal, parser, output, and stop checks.
For every comparison, explicitly name the baseline, interventions, intended
changed variables, frozen variables, permitted implementation differences,
required observables, and ambiguity conditions. A study that changes a
physical mechanism and its numerical realization in the same comparison is
confounded unless an additional control isolates those changes.
